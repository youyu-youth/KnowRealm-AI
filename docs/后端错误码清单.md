# 后端错误码清单

**用途**：前端（工单 04 翻译层）按本清单把后端错误响应翻译为界面语言。契约形状与选型见 [ADR-0017](adr/0017-error-response-additive-code-fields.md)。

**契约**：全部错误响应形如 `{"detail": 中文原文, "code": 稳定码, "params"?: 插值参数}`；`code` 必有，`params` 仅带动态值时出现。翻译未命中码时回显 `detail` 原文。

**命名规范**：`资源_问题` 大写下划线（如 `COURSE_NOT_FOUND`）；跨模块同一用户可感条件**复用同一码**（如 `RECORD_NOT_FOUND` 全模块共用）。码名一经消费即冻结，只增不改。

**防线**：生产代码禁止 raise 裸 `HTTPException`（`backend/tests/test_error_code_guard.py`），新增错误必须经 `CodedHTTPException` 配码。

## 通用码（main.py 统一处理器）

| code | HTTP | 语义 |
|------|------|------|
| `REQUEST_VALIDATION_FAILED` | 422 | 请求参数校验失败（不逐字段翻译，通用文案） |
| `INTERNAL_ERROR` | 500 | 未捕获异常；`params.request_id` 供报障 |
| `HTTP_ERROR` | — | 框架级 HTTP 错误回退（路由 404/405 等无业务码） |
| `LAUNCH_TOKEN_INVALID` | 403 | 启动令牌缺失/不匹配（`shared/deps.py`） |

## SSE 对话错误事件（对话流式 error 事件 code 值集）

事件形状 `{code, detail}` 不变，detail 同样保留中文原文：

| code | detail |
|------|--------|
| `CHAT_CONTEXT_TOO_LARGE` | 摘要与知识点仍超过上下文预算，请精简材料后重试 |
| `CHAT_STREAM_FAILED` | 回答生成失败，请稍后重试 |
| `EMPTY_REPLY` | 回答为空，请重试 |

对话相关 HTTP 409/404（`LLM_PROVIDER_UNCONFIGURED`、`CHAT_STREAM_IN_PROGRESS`、`CHAT_RECORD_UNAVAILABLE`、`TRANSCRIPT_NOT_READY`、`CHAT_SESSION_NOT_FOUND`）走上表，不重复列出。

- **处理任务错误码**：`ProcessingJobErrorCode`（jobs/schemas.py）是 job 轮询域的既有枚举，语义与 HTTP 错误不同层，维持原状。`LIBRARY_BACKFILL_FAILED`（回填任务失败码，经列表响应 `backfill.error_code` 透出，前端横幅用固定文案）与 `LIBRARY_BACKFILL_ENQUEUE_FAILED`（main.py 启动日志码）同属此范围，不入上表。网页抓取任务侧的 `WEB_FETCH_CONTENT_TOO_LARGE` / `WEB_FETCH_UNSUPPORTED_CONTENT_TYPE` / `WEB_FETCH_UNREACHABLE` / `WEB_FETCH_EXTRACT_FAILED`（异步任务失败码，经条目任务 `error_code` 透出，`WEB_FETCH_EXTRACT_FAILED` 提示降级手动粘贴）与 `LIBRARY_INGEST_SUMMARY_ENQUEUE_FAILED`（总结入队日志码）、`TEXT_RECORD_ADD_SUMMARY_ENQUEUE_FAILED`（文本记录操作提案的总结提交结果码，经提案 `result_json.summary_error_code` 透出、回执卡翻译，通用 Agent 工单 03）同属此范围。
- **结构化冲突响应**：`QuizConflictResponse` / `TodoConflictResponse`（409 采纳批次冲突）自带 `blocked_reason` 结构化体，前端按 `blocked_reason` 分支处理，不走码表翻译。
