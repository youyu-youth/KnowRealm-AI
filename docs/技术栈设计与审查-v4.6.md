### 为什么是 FastAPI sidecar（而不是 Rust 命令 / 自造 IPC）（v4.1，决策 #56）

"数据在本地"不改变选型问题本身——真正的问题是**Python AI 栈（LangGraph/LangChain/PyMuPDF/腾讯 SDK/sqlite-vec）以什么方式被 UI 调用**：

| | A. FastAPI sidecar（定稿） | B. Rust 命令 + Python 自定义 RPC（否决） | C. 全 Rust 重写（否决） |
|---|---|---|---|
| 协议层 | 一套（HTTP+JSON+SSE，TS 原生 fetch） | 两套手写（TS↔Rust、Rust↔Python） | 一套，全手写 |
| 类型契约 | **OpenAPI → TS 类型自动生成**（§9.2 约 40 端点单一事实源） | 双语言手工同步 | 手工维护 |
| 流式 | sse-starlette（原生） | Tauri 事件桥接自造 | 自造 |
| Pydantic | **API 请求响应与 LLM 结构化输出共用同一套 Schema** | 需桥接转换 | 丢失 |
| UniApp 契约复用（PRD §1.3） | 白送 | 无 | 无 |
| 致命伤 | — | 双协议胶水层长期维护税 | **LangGraph interrupt/checkpoint（HITL 暂停恢复、四个独立 Graph）无 Rust 等价物——产品核心差异化不可迁移**；文档解析/LLM 生态全部重来 |

**性能判定**：本机回环 HTTP 单次调用开销 ~0.1–1ms，而本应用全部耗时大头在 LLM（秒级）、ffmpeg 转码（分钟级）、腾讯 ASR（供应商配额）——传输层开销是噪声，性能不构成三案的区分度；唯一真实性能项是 sidecar 冷启动（R2/Q14，与选哪案无关）。**维护判定**：单人项目维护成本大头是契约同步，A 案将其归零（codegen），B 案翻倍（两处手工同步），C 案连重写权利都没有。

**A 案加固（首个 localhost API 同步落地的硬性项，#56）**：仅绑 `127.0.0.1`；端口由壳随机分配、经启动参数注入 sidecar；壳 spawn 时同步下发一次性启动令牌，sidecar 中间件校验请求头——挡住同机其他进程的误触/恶意调用（localhost 并非天然只属于本应用）。
| TanStack persistQueryClient + cached_* 表 | TanStack Query 内存缓存 | localhost 毫秒级，无需持久缓存 |

## 三、分层技术栈明细

### 3.1 AI 编排层（sidecar Python 进程内）

| 技术 | 版本基线 | 用途 |
|------|---------|------|
| LangGraph | ≥1.0 | StateGraph 编排、`interrupt()`/`Command(resume=...)` HITL 暂停恢复（Summary/Tutor/TeachBack/Autopilot 四个独立 Graph） |
| langgraph-checkpoint-sqlite | 最新 | 图状态持久化到 langgraph.db（HITL 跨重启、隔天恢复） |
| deepagents | >=0.7.x,<0.8（钉 0.7.13） | Chat agent 主骨架（ADR-0018）：`create_deep_agent` 严格空骨架 + `AgentConfig` 轻工厂，tools/subagents/skills/backend/middleware 五扩展点；内置工具默认全部对模型不可见 |
| langchain-core / langchain-openai | 1.x | 模型抽象；`ChatOpenAI` 指向**供应商卡配置的任意 OpenAI 兼容端点**（默认 DashScope `compatible-mode/v1` + qwen-plus） |
| PyMuPDF / python-docx / Python 标准库 | 最新 | TXT/MD/PDF/DOCX 单文件正文提取；DOC、PPT/PPTX 与 OCR 不在范围。确定性解析直接写普通 Service，不为此引入 Loader 抽象 |
| `with_structured_output` + Pydantic v2 | — | 习题/知识点/Concept/Diff 等结构化输出 |
| DashScope text-embedding-v3 | — | 条件能力：仅在资料库真实黄金集证明向量召回有净增益后启用；Embedding（1024 维）→ sqlite-vec `float[1024]`，换模型=全量重嵌入 |

> LangChain 1.x 按能力拆包（core/openai/community），不用旧 monolithic 用法。LLM 供应商抽象：`agents/llm.py` 工厂读 config/providers.json——任意 OpenAI 兼容端点均可；**评测基线（黄金样本）只对默认预设 qwen-plus 负责**，文档明示。

来源片段与最小 Learner Context 发往外部 LLM 前使用供应商绑定同意；长期记忆外发可单独关闭，供应商地址或密钥变化后重新确认。关闭外发只影响外部推理，本地浏览、FTS 与记忆治理不降级。

**资料库 / RAG 的编排边界（ADR-0024/0025）**：

| 能力 | 承接层 | 禁止 |
|---|---|---|
| 抓取、落盘、解析、转写、分片、索引、回填、归档、删除、重试 | 领域 Service + JobRunner | 为线性确定性 Pipeline 新建 LangGraph |
| 作用域过滤、FTS / Concept / 条件向量召回、去重、排序、锚点组装 | LibraryRetrievalService | Agent 自拼 SQL、索引结果直接当引用 |
| 查询改写、多轮检索、证据比较、回答 | DeepAgents `create_deep_agent` + 一个模型可见 `search_library` | 按来源类型拆多个模型工具；V1 启用 SubAgents / Skills |
| 整理、研究入库、记忆写入 | `agent_proposals` + 前端确认 + 领域 Service | Agent 直接写业务表；用长期暂停 Graph 代替业务提案队列 |
| 当前运行暂停 / 恢复 | LangGraph Checkpoint / interrupt | 保存 LibraryItem、Learner Memory 或提案事实 |

SubAgents、Skills 和 DeepAgents Store 只在出现独立上下文窗口、可评测的并行收益或非领域工作记忆需求后启用；不为来源类型或未来可能性预建框架。

### 3.2 后端服务层（sidecar 内）

| 技术 | 版本基线 | 用途 |
|------|---------|------|
| Python | 3.12+ | 运行时（PyInstaller 打包） |
| FastAPI + Uvicorn | ≥0.115 | REST、依赖注入、OpenAPI schema（供前端生成类型） |
| sse-starlette | 最新 | Chat SSE 流式 + Record 失效通知 |
| SQLAlchemy 2.0（async）+ **aiosqlite** | ≥2.0 | ORM，直连 knowrealm.db |
| httpx | ≥0.28（锁 0.28 线） | 异步 HTTP（LLM/剪藏抓取）；剪藏请求执行 SSRF / 重定向 / 大小 / Content-Type / 超时护栏；**`trust_env=False`** 防本机代理劫持 localhost（Windows 实测陷阱） |
| trafilatura | `>=2.2,<3`（实施时锁定补丁版） | 网页剪藏正文与元数据提取；输入 httpx 获取的原始 bytes / HTML，不执行 JS；提取为空或质量门禁失败时降级手动粘贴 |

| Pydantic v2 + pydantic-settings | ≥2.x | 请求/响应模型、结构化输出 Schema、配置 |
| loguru | 最新 | 日志（不落转写/对话全文/密钥） |
| ffmpeg | 实施时锁定稳定版本 | **随包分发、关闭 GPL/nonfree 组件的 LGPL-compatible 构建**；全部音频统一 → ogg-opus@16kHz 并切片。锁定来源、版本、配置、SHA-256 与许可证；生产禁止依赖 PATH，ffprobe 仅测试使用 |
| **PyInstaller** | 最新 | sidecar 打包单文件（API+worker 一体）；首次可分发里程碑冒烟验证体积/杀毒误报/冷启动 |
| pytest | — | 单测（aiosqlite 临时库 + 迁移链 user_version 逐版本验证） |

### 3.3 数据层（SQLite + 数据目录）

| 技术 | 用途 |
|------|------|
| SQLite（WAL，aiosqlite） | 唯一业务事实源（设计 44 表、已实施 27 表，见数据模型 v3.0）；`PRAGMA foreign_keys=ON`；同一数据目录由 sidecar 持有进程生命周期操作系统排他锁，保证单写者 |
| FTS5 + jieba | 资产导航搜索与 Segment RAG 基线召回；索引只定位，最终引用回业务 Segment / Source Anchor |
| sqlite-vec（vec0 虚拟表） | **条件能力，默认未实施**：仅在真实黄金集出现词汇错配失败且相对 FTS+Concept 有可测净增益时加入 LibraryRetrievalService 内部；仍强制作用域与 `deleted_at IS NULL` 过滤 |
| 迁移：`backend/migrations/*.sql` + `PRAGMA user_version` | 唯一权威；首次应用新 Schema 前 `VACUUM INTO` 独立升级前快照。Schema 脚本只改结构 / 小数据，不扫描哈希历史文件；资料存量回填由可恢复幂等 Job 执行，失败不阻塞旧功能 |
| 数据目录体系 | `.knowrealm.lock`（OS 排他锁对象）+ files/（原件）cache/（可重建）exports/（导出 zip）backups/（启动滚动备份 每日×7）config/（settings.json + providers.json 明文密钥） |
| 备份原语 | `VACUUM INTO`（一致性快照，用于 backups 与全量导出） |

## 五、合理性审查结论

### 5.1 判定为合理

1. **本地优先范式（#55/#58）与"开源+个人使用"完全自洽**——零容器零账号；原始导入文件与录音 WebM 不外发，用户独立同意后仅转码音频片段发送腾讯 ASR；捕获/浏览/转码离线可用，云端处理可恢复等待；安装即用。
2. **SQLite 单事实源在单用户场景无短板**——WAL + 数据目录排他锁保证一个 sidecar 写者；44 张设计表中只有 27 张已实施，资料库新增表按纵向工单落地；`VACUUM INTO` 提供一致性快照原语。
3. **sidecar 保住全部 Python AI 资产**——LangGraph/LangChain/ffmpeg/文档解析栈原样保留，HITL interrupt 语义不变（checkpoint 从 PG 换 SQLite Saver）；代价仅安装包体积。
4. **sqlite-vec 只作条件增强**——个人量级若需要向量，sqlite-vec 仍优于外部向量库；但 FTS+Concept 已能覆盖基线，未通过真实黄金集净增益门禁前不承担依赖、成本与隐私税。
5. **自研 processing_jobs 队列**——procrastinate 的价值在多 worker/分布式，单人单进程内是负资产；jobs 表复用既有"业务态/技术态分离"设计（#7）。
6. **LLM 供应商抽象**——OpenAI 兼容端点是事实标准（DashScope/DeepSeek/月之暗面/OpenAI 均支持）；供应商卡交互对齐 cc-switch/Cherry Studio 用户心智。

### 5.2 风险与缓解

| # | 风险 | 等级 | 缓解 |
|---|------|------|------|
| R1 | 录音→ASR 格式断层（webm 不被 ASR 支持） | 高 | S0 POC：webm 分片 → 本地 ffmpeg ogg-opus@16kHz → ASR 全链路实测；isTypeSupported 运行时探测 |
| R2 | **PyInstaller sidecar**（体积 +150~250MB / 杀毒误报 / 冷启动） | 高 | S0 冒烟（§11-Q14）；关 UPX 换误报率；壳先起 UI 后台预热 sidecar |
| R3 | SQLite 单文件损坏（断电/磁盘错误） | 中 | WAL；启动滚动备份 ×7；导出习惯引导 |
| R4 | 数据目录被同步盘接管（OneDrive 锁冲突/上传风暴） | 中 | 首启检测已知同步路径并提示改选 |
| R5 | 长录音稳定性（休眠/节流/磁盘占满） | 高 | 分片落盘、防休眠、磁盘防呆（≥2× 预估体积） |
| R6 | LangChain/LangGraph 1.x 包结构变动 | 中 | 锁版本；仅用四包 |
| R7 | 腾讯 ASR SDK 同步阻塞 | 中 | 仅在 worker 任务内用；不进 API 协程 |
| R8 | sqlite-vec 净增益不足或 Embedding 外发成本过高 | 中 | 默认不上；真实黄金集比较 FTS+Concept 与混合召回，只有可测净增益才引入 |
| R9 | 自选 LLM 输出质量参差 | 中 | 评测基线只对 qwen-plus 负责（文档声明）；结构化输出 Pydantic 强校验兜底 |
| R10 | 网页剪藏正文解析 | 中 | httpx 受限抓取 + trafilatura 2.2.x + 两级失败检测；失败降级手动粘贴 |
| R11 | 多应用实例同时打开同一数据目录 | 高 | sidecar 在迁移与 worker 启动前获取 OS 非阻塞排他锁；失败实例明确退出；进程退出/崩溃自动释放 |

### 5.3 明确不做 / 后置项

- ❌ Supabase 全家桶（Auth/Storage/Realtime/RLS/pgvector/托管）、docker 部署形态、云主机
- ❌ MySQL / Redis / Celery / RabbitMQ / procrastinate（自研队列覆盖）
- ❌ 登录/账号/邮件（SMTP/OTP/Resend）
- ❌ 双向同步（永不，红线 #1）；Neo4j / Qdrant（独立向量库）
- ❌ Sentry / OTel / Langfuse 自托管（llm_call_logs 覆盖）；Stronghold
- ❌ 静态加密 V1（SQLCipher P3+ 评估）；TTS；视频导入
- ⏭ Playwright 仅冒烟（可选）；gte-rerank 一期不做；Ollama 本地模型 P2 评估；Tauri updater 后置

## 六、关键设计约束（为后续开发立规）

1. **Mastery 唯一写入口**：业务功能只写 learning_events（幂等键唯一），Evidence Builder → Mastery Engine 异步消费，任何 Service 禁止直写 mastery。
2. AI 判断必须带 confidence/evidence_count；证据不足显示"数据不足"而非编造。
3. Misconception 状态机 SUSPECTED → 验证 → CONFIRMED/DISMISSED → 纠错 → RESOLVED，一次答错不得定性。
4. Autopilot 只推荐不执行（HITL）。
5. AI 自述不是 Evidence（AI_SYNTHESIS 不参与掌握度计算）。
6. Todo / Plan Item / Agent Action 三表分立。
7. LangGraph 按 Graph 拆分（Summary/Tutor/TeachBack/Autopilot），禁止超级 Graph。
8. 数值计算与 LLM 分工：确定性规则算数值，LLM 只做语义理解/评分/对齐/解释。
9. Chat 以 deepagents `create_deep_agent` 为主骨架（ADR-0018，严格空骨架、检索为第一工具 #53 预留）；Summary/Tutor/TeachBack 禁止联网工具。
10. **单写者规则**：UI 不直连数据库、不直写数据目录；一切读写经 sidecar API（红线 #35）。同一数据目录同一时刻最多一个 sidecar：sidecar 解析目录后立即获取进程生命周期 OS 排他锁，拿锁失败必须在迁移、备份与 worker 启动前退出；不能仅依赖可能残留的 sentinel 文件。worker 与 API 同进程共享一个写入口。**localhost 通道加固（#56）**：仅绑 127.0.0.1 + 随机端口（壳分配注入）+ 启动令牌中间件校验——无令牌的同机请求一律 403。
11. **数据外呼白名单**（红线 #12）：LLM/条件 Embedding/ASR、受限网页抓取、用户开启的联网搜索、可选快照备份——此外禁止任何出网；供应商密钥不出本机。范围问答外发相关片段与最小必要学习者记忆前取得供应商绑定同意，长期记忆外发可单独关闭；配置腾讯 key 不等于同意发送音频。
