> **文档定位**：KnowRealm-AI **技术选型唯一权威**（v3.4 定稿）。功能范围与需求边界以《KnowRealm-AI-功能需求基线 v1.10》为准。

> **项目定位**：**开源、面向个人使用**——一切选型先过这道筛子：能否被现有 Postgres/Supabase 吸收？自部署用户要多跑几个容器？
> **编写日期**：2026-08-14
> **变更记录**：v3.4（2026-08-15）需求评审联动对齐（功能基线 v1.7 裁决 #25~#50）——Realtime 状态机"10 态"→**9 态**（含 NOTE，#34）；§3.3/R10 向量检索过滤对齐裁决 #28（user_id + deleted_at 恒定强制，course_id 条件附加——records/semantic_embeddings 的 course_id 均可空，裁决 #21/#24）；ffmpeg 定稿**统一转码**（全部音频 → ogg-opus@16kHz，含 MP3/M4A 导入，#31）；认证对齐 #37（V1 邮箱+密码、禁用邮箱确认/OTP，零 SMTP）；arq 残留表述与 docker-compose redis 注释清理；Tauri 自动更新后置（#47，V1 手动分发）；速记快捷键/开机自启/托盘插件随设置域定稿（#51）补入依赖清单；Chat 形态约束（agent 循环 + 检索为第一工具，#53）入 §六；热词定义对齐 #54（课程手动列表）。

```

│  │ 课程/记录/   │ Supabase    │ Agents:      │ pgvector +   │ │
│  │ 习题/Todo/  │ JWKS 验签    │ Summary/Tutor│ rerank       │ │
│  │ 统计/Passport│ → user_id   │ TeachBack/   │              │ │
│  │             │             │ Autopilot    │              │ │
│  └─────────────┴─────────────┴──────┬───────┴──────────────┘ │
│  sse-starlette(SSE流式)  httpx  tencentcloud-sdk(仅worker内)  │
├──────────────────────────────────────────────────────────────┤
│  procrastinate Worker（异步任务，队列=Postgres，零额外中间件）  │

│  → Concept抽取 → Mastery重算 → Misconception检测              │

        │ SQLAlchemy 2.0 async         │ LangGraph checkpointer
┌───────▼──────────────────────────────▼───────────────────────┐
│                       Supabase                                │
│  Postgres(业务主库~30张表 + RLS数据隔离) + pgvector(向量检索)   │

│  Realtime(状态机变更推送)                                      │
├──────────────────────────────────────────────────────────────┤
│  外部服务: DashScope(qwen-plus LLM + text-embedding-v3)        │
│           腾讯云 ASR(录音文件识别)                             │
└──────────────────────────────────────────────────────────────┘
```

**与旧架构（Spring Boot 版）的组件替换对照：**

| 旧组件 | 新组件 | 说明 |
|--------|--------|------|
| Spring AI Alibaba StateGraph | **LangGraph** | HITL 用原生 `interrupt()`，状态持久化用 checkpointer |
| Spring AI（模型抽象/RAG/ChatMemory） | **LangChain 1.x** | 模型、Loader、Splitter、pgvector 集成 |
| Sa-Token + 微信登录 | **Supabase Auth** | JWT 验签，RLS 兜底 |
| MySQL 8 | **Supabase Postgres** | 同源还获得 pgvector / Realtime |
| MinIO | **Supabase Storage** | 私有桶 + signed URL，桌面端可直传 |
| 扩展文档建议的 Qdrant | **pgvector** | 不引入新中间件，个人学习数据量完全够 |
| 扩展文档建议的 RabbitMQ | **procrastinate（Postgres 队列）** | 队列即 PG 表，重试/定时/锁原生支持，零额外中间件 |
| 小程序内轮询状态 | **Supabase Realtime** | 记录状态机变更实时推送 |
| 微信小程序（TDesign） | **Tauri 2 + React** | 3 小时长录音、本地大文件由桌面端天然承载 |
| Druid / Redisson / Hutool 等 | 不再需要 | 职责被上述组件吸收 |

## 三、分层技术栈明细

### 3.1 AI 编排层（后端 Python 进程内）

| 技术 | 版本基线 | 用途 | 对应需求 |
|------|---------|------|---------|
| LangGraph | ≥1.0 | StateGraph 编排、`interrupt()`/`Command(resume=...)` 实现 HITL 暂停与恢复 | PRD §5.4 以总结为中心的管线；扩展 §29 四个独立 Graph（Summary/Tutor/TeachBack/Autopilot） |
| langgraph-checkpoint-postgres | 最新 | 图状态持久化到 Supabase Postgres（HITL 暂停跨进程、跨天恢复） | HITL 节点"等待用户确认"可持久化 |
| langchain-core / langchain-openai | 1.x | 模型抽象；`ChatOpenAI` 指向 DashScope OpenAI 兼容端点接 qwen-plus | LLM 统一调用 |
| langchain-community + PyMuPDF / python-docx / python-pptx | 1.x / 最新 | 文档 Loader：**PyMuPDF** 解析 PDF（解析质量好且可取页码，供 `document_segment.page_no` 溯源），python-docx / python-pptx 处理 Office 文档；文本切分 | 文档导入（PRD §5.3.3）、Document Segment（扩展 F1） |
| ~~langchain-postgres~~ | — | **v3.3 移除**：向量检索走自建 `semantic_embeddings` 表（数据模型 §4.6 统一向量生命周期）+ SQLAlchemy 原生 SQL；其 PGVector collection 自建表与该设计冲突 | Course Brain 语义记忆（扩展 §10.4） |
| `with_structured_output` + Pydantic v2 | — | 习题/知识点/Concept/Diff 等结构化输出 | 保证 AI 产物可入库、可校验 |
| DashScope text-embedding-v3 | — | Embedding（1024 维）→ pgvector `vector(1024)` | Segment/知识点/Concept 向量化 |
| DashScope gte-rerank（可选，一期不做） | — | 检索结果重排；个人课程 segment 量级下向量 + 元数据过滤已够准，暂不引入 | 课程级问答引用质量 |

> **注意**：LangChain 1.x 后按能力拆包（`langchain-core` / `langchain-community` / `langchain-openai`），不依赖旧 monolithic `langchain` 的用法。DashScope 走 OpenAI 兼容模式（`base_url=https://dashscope.aliyuncs.com/compatible-mode/v1`），不使用维护较弱的 `ChatTongyi` 专有集成。

|------|---------|------|

| loguru | 最新 | 日志库（2026-08 定案，二选一悬置收敛为 loguru：零配置、拦截标准 logging 即用；遵循 PRD：日志不落转写全文/敏感内容） |
| ffmpeg（worker 容器内） | **8.x**（2026-08 拉齐；当前稳定 9.0/8.1，8.x 为兼容稳妥线） | **全部音频统一 → ogg-opus@16kHz 转码**（含 MP3/M4A 导入，#31；见 §5 风险 R1；无损 remux 为 POC 待验证优化项） |
| pytest | — | 单测：纯业务逻辑用 SQLite(aiosqlite)；涉及 pgvector/RLS 的用固定 Postgres 容器（testcontainers 可选，不作硬依赖） |

### 3.3 数据层（Supabase + SQLite）

| 技术 | 用途 | 对应需求 |
|------|------|---------|
| Supabase Postgres | 业务主库（v2.1 的 12 张表 + 扩展新增 ~18 张：segment/anchor/marker/event/evidence/concept/relation/mastery/misconception/review_schedule/goal/plan/agent_action/passport 等） | 全部业务事实存储 |
| pgvector（HNSW 索引） | Transcript Segment / Document Segment / Knowledge Point / Concept 四类向量，查询**恒定强制 `user_id + deleted_at IS NULL` 前置过滤，course_id 仅课程/记录范围检索附加**（records/semantic_embeddings 的 course_id 均可空——Inbox 与 @全部资料全局 RAG，功能基线裁决 #21/#24/#28） | Course-level RAG（扩展 §10.5） |
| Row Level Security | 所有业务表 `auth.uid() = user_id` 策略；后端 service role 绕过 RLS 但代码层显式过滤 user_id（双保险） | 数据隔离（PRD §6.3） |
| Supabase Auth | 邮箱+密码（V1 **禁用邮箱确认/OTP**，零 SMTP，#37）；签发 JWT；FastAPI 经 JWKS 验签注入 user_id | M1 认证 |
| Supabase Storage | `recordings`（原始 webm + 转码 ogg）/ `documents` 私有桶；桌面端直传（大文件不过后端），signed URL 读取 | 音频/文档存储（替代 MinIO） |
| Supabase Realtime | 订阅 `record.status` 变更推送桌面端（状态机 **9 态**流转即时刷新，#34） | 替代小程序轮询（PRD §5.6.1） |
| SQLite（桌面端，tauri-plugin-sql） | TanStack Query 持久化缓存 + 离线只读副本（记录列表/转写文本/AI 产出）+ 录音分片暂存索引；**写操作仅录音暂存队列，业务写一律在线走 API** | D1 决策 |
| SQLite（后端开发） | aiosqlite 跑纯逻辑单测；LangGraph 本地开发可用 SqliteSaver | D1 决策 |

## 四、需求 → 技术映射（功能覆盖验证）

| 功能（PRD/扩展） | 技术承接 |
|------------------|---------|
| 录音最长 3h、中断保护（PRD §5.3.1） | MediaRecorder 分片 + Tauri 本地暂存 + 防休眠（桌面端优于小程序，无后台杀死问题） |
| 多文件关联、100MB 限制（PRD §5.3.2/§5.3.7） | Storage 直传；**上限不再受 wx.uploadFile 100MB 约束**，按转码后 3h 音频实际体积重新定限（建议 ≤300MB） |
| ASR 批量识别 + 热词 + 时间戳（PRD §5.3.4） | 腾讯云录音文件识别（procrastinate worker 提交/轮询），热词 = 课程手动热词列表（courses.hot_words，功能基线 #54；知识点自动同步 P2） |
| 句子级 Segment 持久化、证据可溯源（扩展 F1） | `t_transcript_segment` + `t_source_anchor`；AI 输出携带 segment 引用 → 前端点击跳转播放 |
| 总结自动生成 + HITL 确认/调整（PRD §5.4） | LangGraph Summary Graph：`generate_summary → interrupt(review) → (调整则循环) → 解锁`，checkpointer 持久化等待状态 |
| 知识点/习题/Todo/复习按需生成 + 各自 HITL | 同一 Graph 的按需分支，结构化输出（Pydantic 校验题型字段完整性） |
| AI 问答 SSE + 多轮记忆（PRD §5.5） | sse-starlette 流式 + LangGraph checkpointer 管理对话 thread + `chat_message` 落库 |
| 课程级 RAG（扩展 F4） | pgvector 四类向量 + 检索强制 user/course 过滤 + Source Anchor 回链 |
| 掌握度/遗忘/误区（扩展 F7–F9） | 事件表 `t_learning_event`（幂等键）→ Evidence Builder → 确定性规则引擎计算（LLM 只做语义评分/对齐/诊断解释，不算数值） |
| 复习调度（扩展 F9） | V1 规则公式（importance × forgetting_risk × (1-mastery) × exam_weight）；V2 再引入 FSRS |

## 五、合理性审查结论

### 5.1 判定为合理（可直接采用）

1. **LangGraph 替代 Spring AI Alibaba StateGraph —— 契合度最高的一项。** PRD 的核心交互模式（自动生成总结 → HITL 暂停等用户 → 确认解锁后续按钮）就是 LangGraph `interrupt()`/`Command(resume=...)` 的教科书场景；checkpointer 落 Postgres 后，"用户隔天再来确认总结"天然可恢复。扩展文档 §29 要求的"多个独立 Graph 通过 Learning Event/Profile 共享状态而非互相嵌套"与 LangGraph 多 app 组织方式一致。
2. **Supabase 一站式替代 MySQL + MinIO + Sa-Token (+Qdrant +轮询)。** 一个组件吸收五个职责，对个人/小团队项目显著降低运维面；RLS + 后端双重数据隔离满足 PRD §6.3。
3. **pgvector 替代 Qdrant。** 扩展文档本就声明"Qdrant 不当主数据库、只做语义召回"。个人学习场景单课程 segment 量为百~千级，pgvector HNSW 绰绰有余，省掉一个中间件。
4. **Postgres 队列（procrastinate）替代 RabbitMQ。** 任务量级（每日数十~数百个 ASR/生成任务）用不上 MQ；队列即 PG 表，重试/定时/锁原生支持、零额外中间件（v3.2 由 arq+Redis 改定，见 R11）。
5. **Tauri 2 做桌面端。** PRD 最苛刻的非功能需求（3 小时连续录音、100MB+ 文件、断点保护）恰恰是桌面端强项、小程序痛点；安装包小、内存占用低。
6. **React + TS + Tailwind4 + shadcn/ui + TanStack Query + Zustand。** 全部为当前主流、社区活跃的组合；TanStack Query 的持久化缓存与 D1 的"桌面缓存"定位天然咬合。
7. **FastAPI + sse-starlette。** SSE 流式（首字 ≤3s）与 OpenAPI 自动文档（供前端生成 TS 类型）均为成熟路径。
8. **SQLite 在 D1 定位下合理。** 做桌面缓存与开发库无并发与功能冲突；同时明确**不做云端主库**（无 pgvector/RLS/Realtime，与 Supabase 能力直接冲突）。

### 5.2 有条件合理（需按下述条件执行）

| # | 项 | 风险 | 执行条件/缓解 |
|---|----|------|--------------|
| R1 | **录音→ASR 格式断层（最高风险）** | WebView2 MediaRecorder 可靠输出仅 `audio/webm;codecs=opus`；腾讯云 ASR 支持 wav/mp3/m4a/flv/mp4/aac/**ogg-opus**，**不支持 webm** | 链路定为：录制 webm/opus 分片 → 本地暂存 → 直传 Storage → **worker 用 ffmpeg 统一转码为 ogg-opus@16kHz（对齐功能基线裁决 #5/#31——导入的 MP3/M4A 等同样统一转码；无损 remux `-c:a copy` 为 POC 待验证优化项，实测识别质量无差异再降级采用）** → 提交 ASR。M-1 前必须完成全链路 POC（含 `MediaRecorder.isTypeSupported` 运行时探测兜底） |
| R2 | **Supabase 云国内访问** | 延迟与稳定性未实测（Auth/Storage/Realtime 均直连） | S0 阶段实测（选东京/新加坡机房）；不达标则评估自托管或加中转。此项影响 D3/D4，需最先验证 |
| R3 | **Supabase 免费额度不足** | Free 档 500MB 库 / 1GB 存储 / 上传单文件 ≤50MB；3 小时录音单文件即超 | 规划即按 **Pro 档（$25/月）** 预算；或自托管。成本决策须在 M-1 前明确 |
| R4 | LangChain 1.x 包结构 | 旧教程/示例大量基于 0.x monolithic 用法，混装易踩坑 | 锁定 1.x；仅用 `langchain-core/-openai/-community/-postgres` 四包 + LangGraph；依赖以 uv 锁定 |
| R5 | 腾讯云 ASR SDK 为同步阻塞 | 误用于 API 主进程会阻塞事件循环 | 规约：ASR/ffmpeg 仅存在于 procrastinate worker |
| R6 | 邮箱认证送达 | Supabase 内置 SMTP 限额严格（约 3 封/小时），验证码邮件可能送不出 | **V1 禁用邮箱确认与 OTP，注册即用、零 SMTP（功能基线 #37）**；对外发布里程碑再配自定义 SMTP（Resend / 阿里云邮件推送）并启用确认/OTP |
| R7 | SSE 认证 | 原生 `EventSource` 不支持自定义 header | 统一用 `@microsoft/fetch-event-source`（POST + Bearer） |
| R8 | React 桌面端 ↔ UniApp App 端复用度低 | Vue 语法体系不同，UI 层未来需重写 | 接受（D2 已确认）。最大化复用手段：API 契约经 OpenAPI 生成 TS 类型 + 领域逻辑与提示词全部下沉后端 |
| R9 | 长录音运行时稳定性 | WebView 后台节流可能干扰录音定时器；系统休眠中断录音 | Tauri 侧设置 power 防休眠；分片 5–10 分钟落盘，崩溃最多损失当前分片；分片索引存 SQLite |
| R10 | pgvector 维度/检索正确性 | embedding 维度与表定义不一致、检索未过滤越权 | text-embedding-v3 固定 1024 维（`vector(1024)`）；检索封装层恒定注入 `user_id + deleted_at IS NULL`（course_id 按检索范围附加），禁止裸相似度查询（功能基线裁决 #28） |
| R11 | 任务队列选型 | Redis/Celery 对"开源 + 个人使用"定位是纯部署开销（v3.2 决策） | **定为 procrastinate（Postgres 队列）**：零额外中间件，支持重试/定时/锁；复习调度扫描、Passport 快照用其 periodic 任务；原 Redis 缓存职责由进程内 LRU / Postgres 覆盖。约束：worker 连接串用 session 池化或 direct 端口（`LISTEN/NOTIFY` 不被事务池化支持） |

## 六、关键设计约束（为后续开发立规）

1. **Mastery 唯一写入口**：业务功能只写 `t_learning_event`（带 `idempotency_key` 唯一索引），Evidence Builder → Mastery Engine 异步消费更新，任何 Service 禁止直写 mastery（扩展 §3.4）。
2. **AI 判断必须带 confidence/evidence_count**；Digital Twin 证据不足时显示"数据不足"而非编造分数（扩展 §3.5）。
3. **Misconception 状态机** SUSPECTED → 验证 → CONFIRMED/DISMISSED → 纠错 → RESOLVED，禁止一次答错即定性（扩展 §3.6）。
4. **Autopilot 只推荐不执行**，任何动作经用户 `[接受/跳过/稍后]` 后才运行（扩展 §3.7）。
5. **AI 自述不是 Evidence**：`AI_SYNTHESIS` 类型不参与掌握度计算（扩展 §3.8）。
6. **Todo（Record 级）/ Learning Plan Item（Goal 级）/ Autopilot Action（State 级）三表分立**，可引用不合并（扩展 §3.9）。
7. **LangGraph 按 Graph 拆分**（Summary / Tutor / TeachBack / Autopilot），通过 Learning Event 与 Learner Profile 共享状态，禁止合并成超级 Graph（扩展 §29）。
8. **数值计算与 LLM 分工**：掌握度、遗忘风险、复习优先级、下一题选择由确定性规则计算；LLM 只负责内容理解、语义评分、Concept 对齐、诊断解释（扩展 §13.3/§19.4）。
9. **Chat 用 LangGraph agent 循环实现**（功能基线 #53）：检索作为第一个工具（单工具时行为等同纯 RAG 管线），为 P2 联网搜索（Tavily，预留国产替代）等工具扩展保留形态；Summary/Tutor/TeachBack Graph 禁止联网工具。
