# Agent 写操作授权采用用户可选三档模式，默认档维持提案确认绝对门禁

---
Status: accepted（2026-09-21，通用 Agent 设计采纳〔扩展文档 §44、`docs/KnowRealm-AI-通用Agent设计-4.md` 采纳版第 6 节〕）
---

ADR-0024 与扩展文档 §42.11 确立「Agent 写入业务事实必须先提案、经用户确认」的绝对门禁，提案框架（`agent_proposals` + 判别 payload + HITL）已在研究入库、记忆、AI 整理三个场景验证。通用 Agent 操作化（§44）要求自然语言直接创建课程、记录、任务并批量整理，若每步都停确认卡，批量任务的摩擦会抵消「操作入口」的价值；但静默放开免确认写入会侵蚀本地单用户产品「用户可见可治理」的信任根基。

**决定**：

- **授权是用户显式选择的三档模式，不是全局固定档，也不由模型自行判断风险**：**请求批准**（默认，所有写操作先提案、确认后执行——与 ADR-0024 现行规则零行为变更）；**帮我批准**（L1 单对象创建 / 可逆修改与不超阈值的批量自动执行并给回执，L3 删除 / 覆盖仍逐项确认，批量阈值规格期定、量级约 10 项）；**完全访问**（除禁止项外全部自动执行并给回执）。
- **默认档即绝对门禁**：§42.11 演进为「默认档维持『未经确认写入事实 = 零』＋ 用户显式切换档位后按模式规则执行」。免确认是用户显式授权的结果，不是 Agent 的默认能力；切换不通过代码静默生效。
- **任何档位不变的能力边界**：物理删除、任意 SQL、任意路径写、宿主 Shell 不向 Agent 暴露（能力边界而非确认策略）；长期 Memory 写入（ADR-0025）、AI 总结与学习资产采纳审核、外发同意机制在任何档位保持确认——模式管业务操作，不管长期事实与内容审核。
- **授权依据可审计**：自动执行的操作回执记录当前模式、触发指令原文与时间；模式切换本身记入操作历史；审计链在任何档位不断。
- **确认与批次授权语义不变**：确认绑定对象集合、动作参数与对象版本；批准处理五篇论文不等于批准第六篇（完全访问档亦然，计划对象集合外新增目标升回确认）。
- **权限校验位于执行端**：Prompt、页面上下文、网页正文、Skills、MCP 返回内容均不构成授权；三档共用同一套工具与执行入口，模式只决定「落提案等确认」还是「校验通过即执行」。

## 当前阶段关联

[ADR-0030：有界专业 Agent 与持久委派](0030-bounded-professional-agents-and-durable-delegation.md)已批准两个专业入口及受控一级知识协作，阶段性演进后果段中暂不做运行时 Multi-Agent 的范围；实施规格最终确认待答，尚未实现。本 ADR 的三档、受控写入、确认与权限校验决定保持有效，knowledge 不拥有写权限。

## Considered Options

| 方案 | 结论 |
|------|------|
| **A. 用户可选三档（默认 = 现行提案规则）** | **采纳**——默认档零行为变更，免确认成为显式选择；摩擦与信任由用户自定 |
| B. 维持全局确认门禁 + 仅批次授权降摩擦 | 否决——单条创建仍每步停卡，「操作入口」体验上限受限；批次授权保留但不足以独扛 |
| C. 明确指令下低风险自动执行（全局默认直写） | 否决——错建静默落库侵蚀本地数据信任；与 §42.11 字面冲突且须全局翻案，风险与收益不对称 |
| D. Agent 自行风险评估决定是否确认 | 否决——LLM 风险判断不可审计、不可回归测试；确认级别必须是确定性规则 |

## Consequences

- ADR-0024 / §42.11 的字面由本 ADR 修订承载（默认绝对 + 显式豁免）；扩展文档 §41.1 第 5 条「不上通用自主 Agent」口径同步修订（受控通用操作 Agent 见 §44，运行时 Multi-Agent 自治协作仍不做）。
- 实施顺序：第一阶段（G1）仅交付默认档，零新机制；「帮我批准」「完全访问」随 G2（修改 / 归档 / 批量整理与操作回执 UI）上线。
- 自动执行路径复用提案框架的判别 payload 与执行入口校验，不新建并行写通道；回执字段、批量阈值数值、模式切换粒度（全局默认 + 会话记忆）随规格定稿。
- 评测门禁须覆盖三档：越权尝试拒绝、模式切换后行为变化、自动执行回执完整性、重规划不偷加对象。
