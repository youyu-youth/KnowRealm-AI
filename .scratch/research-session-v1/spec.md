# 问题驱动的证据型研究会话 V1 规格说明

Status: ready-for-agent
定稿依据：2026-09-20 用户拍板顺序变更（研究会话插队升为下一站，扩展文档 §41.1 第 3/5 条已回写）+ 当日 grill 六问全按推荐定稿；能力口径冻结自扩展文档 §41.1 第 5 条、§42.2 映射表、§42.6 RAG Agent 工作方式与 V1.1 受控写动作。本 spec 只做整合与冻结，不重新讨论已定边界；与权威文档冲突时以 ADR 与权威文档为准。

## Problem Statement

- 用户想"研究一个问题"（调研对比、论证、技术选型、论文准备）时，现有 Chat 只能"问答"：B2 的 COURSE/ALL 会话能在资料范围内找原文回答单点问题，但不会主动比较多来源、标出冲突与证据缺口，也不会建议把研究中有价值的外部来源沉淀下来。
- 资料库 / RAG V1 波次（七票）刚收口：五档检索、web_search、RESEARCH_INGEST 提案闭环、citations、Learner Memory 注入全部就绪，但缺少一个把这些能力组合成"研究任务"的产品入口——底座投资没有第一个组合型消费场景。
- 现有 web 来源保存是纯手动：用户自己发现值得存的引用、自己点"建议保存"。研究中"哪些来源值得入库"本身就是 AI 应当给出的判断之一。

## Solution

新增**研究会话（Research Session）**模式，纵向闭环：

```text
新建研究会话（研究问题 + 资料范围 + 是否联网）
→ AI 在范围内检索本地资料（可叠加联网补充）
→ 按固定五节结构输出证据综合（已有证据 / 来源差异 / 冲突与缺口 / 暂定结论 / 建议保存的来源），结论挂引用
→ AI 经 propose_ingest 工具主动生成"建议保存"入库提案
→ 用户逐条确认 → 复用现有网页入库链路（抓取 → 分片 → 锚点 → 可被检索）
→ 多轮追问深化（研究问题不变）
```

不新建 ResearchSession 表、不建独立 Research Graph、不上 Skills/SubAgents/MCP/sqlite-vec；与既有普通会话、B2 问答并存。

## User Stories

1. 作为学习者，我想新建一个"研究会话"并写下研究问题（如"transformer 各注意机制变体的取舍"），这样 AI 的回答围绕这个问题组织而不是零散问答。
2. 作为学习者，我想在创建时选择资料范围（全部资料 / 某课程 / 纯联网），这样证据来源有明确边界，AI 不会拿范围外的内容充数。
3. 作为学习者，我想在创建时选择是否联网（默认开），这样 AI 可以补充本地资料没有的外部证据。
4. 作为学习者，我想让 AI 的回答按固定结构组织——已有证据、来源差异、冲突与缺口、暂定结论——这样我能直接看到多来源的分歧与证据不足处，而不是自己翻引用拼凑。
5. 作为学习者，我想让结论句句挂引用角标，这样每个论断都能跳回原文核对。
6. 作为学习者，当范围内没有可引用证据时，我想让 AI 明确说"当前资料中未找到"，而不是用模型常识冒充资料事实。
7. 作为学习者，我想让 AI 主动建议"这几个外部来源值得入库"，这样研究过程发现的好资料能直接沉淀进资料库，不用我手动逐个保存。
8. 作为学习者，我想逐条确认或拒绝每个入库提案，这样进入资料库的来源都经过我的把关（搜索摘要永远不会冒充资料事实）。
9. 作为学习者，我想在研究过程中多轮追问（缩小范围、追问冲突点），这样研究可以迭代深化，且研究问题（会话标题）保持稳定。
10. 作为学习者，我想把研究结论中值得记住的部分保存为知识点（复用现有"保存为知识点"），这样研究成果进入学习资产。
11. 作为学习者，我想让研究回答自动考虑我的学习记忆（已注入的偏好与课程掌握状态），这样解释深度与表达方式适合我。
12. 作为无 Tavily key 的用户，我想在创建联网研究会话时得到明确提示（联网不可用、本次仅本地），这样我不会误以为 AI 查过网。
13. 作为用户，我想在会话列表与标题栏看到"研究"标识，这样研究会话与普通问答会话可区分。
14. 作为用户，我想在会话内看到范围胶囊但不可切换（点击=新建会话），这样与既有范围语义一致、不产生"改范围导致前后证据边界混乱"的问题。
15. 作为维护者，我想让研究 prompt 与评测黄金集一起版本化，这样换模型或改 prompt 时能回归验证引用正确率与拒答纪律没有劣化。

## Implementation Decisions

### 会话建模（grill Q1 定稿）

- `ChatMode` 新增 `RESEARCH` 枚举值；会话创建请求放开 mode 字面量为 `ASK | RESEARCH`（SOCRATIC_TUTOR / TEACH_BACK 继续不放开）。
- RESEARCH 会话的 scope 校验矩阵：只允许 **ALL / COURSE / FREE**；与 RECORD / LIBRARY_ITEM 组合拒绝（422，错误码进实施票登记）。FREE = 纯联网研究（不挂检索工具，证据只来自 web_search）。
- 研究问题 = 会话标题，复用现有 title 字段（可改名），零新列、零迁移。scope 会话内不可变语义沿用（B2 定稿）。
- mode 与 scope 两轴正交语义不变（GLOSSARY.md 已固化）；「会话范围」词条中"mode 恒 ASK"的表述随本票修订，并新增「研究会话」词条。

### 工具挂载（复用 AgentConfig 组装）

- RESEARCH + 非 FREE：挂 `search_library`（作用域由会话运行时经 ContextVar 绑定，先例不变）。
- `web_search`：沿用每请求 `web_search` 标志 + 前端按会话记忆的机制，零后端改动；无 key 时后端强制忽略（现状）。
- `propose_memory`：恒挂载沿用（用户研究中说"记住…"同样有效）。
- **新工具 `propose_ingest`**：仅 RESEARCH 会话挂载；实现照 propose_memory 先例——ContextVar 绑定运行期上下文（session 工厂 + 会话 id）、`@tool` 注册、超限拒绝而非截断；提案走通用创建端点落库，类型复用 **RESEARCH_INGEST**（载荷 {url, title, course_id}：scope=COURSE 自动带该课程 id，ALL/FREE 落 None 由用户后续整理）；单轮提案条数与字串限长在实施票定值（对齐 propose_memory 的 5 条上限量级）；提案溯源口径与现有手动提案一致（带 session_id）。
- 手动"建议保存"入口（web 引用卡）保留不变，与 Agent 主动提案并存。

### 固定结构输出（grill Q2 定稿：零结构化生成）

- RESEARCH 会话使用独立研究 prompt 版本（在现值 `chat-library-scope-v8` 基础上 bump，研究语义进版本串）。
- 五节固定 Markdown 结构作为 prompt 文本协议：**已有证据 / 来源差异 / 冲突与缺口 / 暂定结论 / 建议保存的来源**；前端 Streamdown 原样渲染（V1 零卡片化、零结构化载荷）。
- 拒答与引用纪律进 prompt：无可引用命中时明确说明、不得用模型常识补成资料事实；web 来源与资料库来源保持不同 citation 类型、不得互相冒充（沿用 §42.6 既有承诺）；FREE 范围明示"无本地资料范围"。
- 选型理由（记录备查）：复习资料票有 json_mode 静默降级教训（校验器规则模型看不见、纠偏重试烧 token），V1 用纯 prompt 指引规避；卡片化等真实需求出现再升 V1.1。

### done 载荷与确认卡（grill Q3 定稿）

- 全链路照 memory_proposals 先例：工具成功 → 流内提案事件 → done 载荷新增 `research_proposals`（前端防御性收窄解析，形状不符静默跳过）→ 消息流就地确认卡（确认/拒绝）→ 确认后复用现有 RESEARCH_INGEST 应用器（真实抓取、摘要不冒充事实、未抓取前不进 RAG）。
- 本轮提案展示为临时态（不落库的 UI 状态，先例=turnMemory），提案本体已在 agent_proposals 表跨重启持久。

### 前端入口与 UI（grill Q6 定稿）

- 新建菜单（现四入口旁）加"研究会话"：弹窗三件——研究问题（必填，即标题）、资料范围（默认 ALL）、联网开关（默认 ON）。
- 联网默认值逻辑扩展：selectWebSearchEnabled 的"自由 ON / 挂载 OFF"扩展为 RESEARCH 会话默认 ON；无 Tavily key 时创建弹窗明示降级。
- 会话列表行与标题栏"研究"徽章；范围胶囊只读（点击=新建，沿用）；空会话建议卡换研究特化示例问题。
- i18n zh/en 同步新增（一致性防线覆盖）。

### 零改动确认项（沿用，不设新逻辑）

- Learner Memory 注入：沿用现有 scope 逻辑（COURSE 注入课程掌握状态、ALL 仅全局、外发开关 AND consent 指纹 fail-closed）。
- 沉淀出口：入库提案（新）+ 保存为知识点（B6 已有，全 scope）；不新建聊天导出、不建报告表。
- citations 校验、多回答引用聚合、工具状态卡：全部沿用。

### 评测资产（grill Q5 定稿：随票前置）

- `docs/evaluation/` 新增研究会话黄金集（约 10 条研究问题，覆盖四类：跨来源比较 / 冲突识别 / 无证据拒答 / 范围隔离）。
- 四指标设门禁：引用正确率、无证据拒答、范围隔离（不越 scope）、固定结构完整率；观测项不设门禁：工具调用次数、来源提案接受率。
- 回归触发 = prompt 版本 bump / 模型变更（沿用项目评测纪律）。

## Testing Decisions

- 好测试只断言外部行为：路由级请求/响应契约、prompt 组装产物的文本协议、工具返回的 ok/error 形状、前端可见交互；不测内部实现细节。
- 后端沿现有 seam（零新 seam）：
  - 会话创建路由测试：mode × scope 校验矩阵（含 RESEARCH+RECORD 拒绝）、Fake chat model 先例（learner memory / chat 既有测试模式）。
  - prompt 断言：RESEARCH 会话的 system prompt 含五节协议标题与拒答纪律文本（先例：prompt 组装测试）。
  - propose_ingest 单测：ContextVar 未绑定、超限拒绝、成功建案（payload 判别清洗、course_id 按 scope 注入）；先例 = propose_memory 测试。
  - done 载荷端到端：research_proposals 字段形状与防御收窄。
- 前端：MSW mock + 组件测试——创建弹窗三件与校验、联网默认态、研究徽章、提案确认卡、建议卡文案；先例 = chat 与 ChatMemoryPanel 测试。
- 评测：黄金集门禁脚本可复跑（先例 = 资料库 01 契约与评测地基）。
- 门禁：后端 pytest（独立 basetemp）+ ruff + pyright；前端 vitest + lint + build（内嵌 tsc）；OpenAPI `--check`（mode 字面量变更影响契约，api-types 须 regenerate）；zh/en 一致性防线。

## Out of Scope

- 结构化生成与卡片化渲染（V1.1 按真实需求再评估）。
- 研究结论报告表 / 研究计划持久化 / 聊天导出（沉淀走 B6 + 入库提案）。
- 独立 Research Graph、长时间运行任务状态与中断恢复（deepagents 工具循环足够；跨重启审核由 agent_proposals 承担）。
- Skills / SubAgents / MCP client / sqlite-vec（按既有触发条件，本波次全部不启用）。
- "收集来源建立知识空间"出口（后续波次；V1 出口统一为进资料库派生 Record）。
- 书籍 / 大 PDF / 视频等新来源（书籍拆章为下一波次）。
- 对象驱动模板系统 / "研究一个问题"式通用入口抽象（等 ≥3 场景证据，§41.3 定稿）。

## Further Notes

- **与 B2 的差异化锚点**（防换皮，验收时对照）：固定五节结构输出、无证据拒答纪律、Agent 主动入库提案、前置评测门禁。四者缺任一则本功能退化为 B2 换皮。
- 顺序变更依据（2026-09-20）：ai-summary/03 deferred 使长内容波次失去超长章兜底前置；资料库七票收口后 RAG 底座缺第一个组合型消费场景。见扩展文档 §41.1 第 3 条变更注记。
- prompt 版本现值为 `chat-library-scope-v8`（语义化字符串，非纯数字）；本波次 bump 进版本串并触发评测回归。
- 外部分析（GPT）的代码事实主张已逐项核验属实，两处偏差（书籍拆章不等 03 复活、真机验收非硬前置）已在顺序决策中消化；核验记录见记忆 knowrealm-knowledge-scope-expansion-grill。
