# 学习资产 Markdown 导出

Status: ready-for-agent

## Problem Statement

KnowRealm 已能在一个 Record 中形成 Summary、知识点、习题和 Todo 等学习资产，但这些内容只能留在应用内查看。用户无法把当前已经落定的学习成果保存为普通 Markdown 文件，因而难以在本地编辑器中继续整理、提交作业附件或直接发给同学。Desktop V1 又明确不建设公开链接、账号体系或分享卡片，所以本地 Markdown 是 MVP 唯一需要交付的轻量分享形态。

“导出”在项目中还有另一层含义：全量导出负责打包数据目录以迁移和换机；本功能只处理一个 Record 的学习资产。两者如果继续共用模糊名称，会让用户误以为单个 `.md` 文件能够备份数据库和来源文件，也会让实现错误侵入全量导出边界。因此本功能的规范术语是“学习资产 Markdown 导出”。

当前资产接口还包含不同生命周期的数据：未确认 Summary、DRAFT 候选、SUPERSEDED 历史批次、未作答习题的隐藏答案，以及 Todo 的 AI 项、手工项和被接管项。如果直接把接口数组或页面缓存写入文件，可能导出尚未采纳的候选、泄露题目答案、漏掉用户接管内容，或把读取失败伪装成“没有生成”。本功能必须明确“当前可导出资产”的统一口径，并保证文件与用户此刻有权看到的正式内容一致。

## Solution

在 Record 详情顶部提供统一的“导出”菜单。用户可以选择“导出全部学习资产”，把当前 Record 已生成且符合条件的资产聚合为一个 `.md` 文件；也可以选择“导出当前 Tab”，只保存当前支持的资产。导出动作先通过现有 localhost sidecar API 重新读取最新事实，再形成不可变的前端快照并打开系统保存对话框。保存对话框停留期间发生的后续编辑不改变本次文件。

MVP 的显式资产白名单为 Summary、知识点、习题、Todo；Wave B 的复习资料由其自身功能计划接入同一通道。Transcript 是来源事实，Ask AI 是对话，均不属于本功能。未来新增学习资产时，必须由对应功能显式提供序列化规则与测试，不能因为出现了新 Tab 就自动进入导出。

导出只包含正式、当前可见的数据：CONFIRMED Summary、未删除的 ACTIVE 知识点、未删除的 ACTIVE 习题，以及 Todo 正式清单中的 ACTIVE AI 项、手工项和被接管项。DRAFT 与 SUPERSEDED 内容不导出。习题继续遵守现有防剧透合同：未作答题不包含正确答案和解析；作答后才按页面已经公开的状态输出用户答案、结果、正确答案和解析。

Markdown 在前端由小型纯序列化函数生成，不新增后端导出端点、数据库表、OpenAPI schema 或 learning_events。文件通过已经安装的 Tauri 对话框、文件与打开能力保存到用户显式选择的位置。成功后显示页内状态和“打开文件”操作，但不自动启动外部程序。

## User Stories

1. As an 学习者, I want to 在 Record 详情里找到统一的导出入口, so that 我不用逐个页面寻找不同的保存方式。
2. As an 学习者, I want to 一次导出当前 Record 的全部学习资产, so that 我能得到一份完整的本地学习材料。
3. As an 学习者, I want to 只导出当前 Tab 的内容, so that 我可以按需分享单项资产。
4. As an 学习者, I want to 没有生成的资产不产生空章节, so that 文件里没有误导性的空壳内容。
5. As an 学习者, I want to 当前 Tab 不支持导出时看到禁用原因, so that 我不会把无反应误认为故障。
6. As an 学习者, I want to 当前 Tab 没有正式内容时不能触发单项导出, so that 我不会保存一份空文件。
7. As an 学习者, I want to 一个资产都不可导出时不进入保存流程, so that 我不会被要求给空文件选路径。
8. As an 学习者, I want to 每次导出都读取最新内容, so that 文件不会依赖我是否访问过某个 Tab 或旧的前端缓存。
9. As an 学习者, I want to 保存对话框打开后本次内容保持稳定, so that 保存期间的编辑不会生成内部不一致的半截文件。
10. As an 学习者, I want to 只导出已确认 Summary, so that 未落定的 AI 草稿不会被当成正式学习材料。
11. As an 学习者, I want to Summary 文件包含主题、摘要和结构化分点, so that 导出后仍保留页面的信息结构。
12. As an 学习者, I want to 只导出当前 ACTIVE 知识点, so that 候选和过时批次不会混入正式结果。
13. As an 学习者, I want to 知识点包含名称、详情、重要度和标签, so that 导出后没有丢失我维护的字段。
14. As an 学习者, I want to 知识点沿用页面顺序, so that 文件与我看到的列表一致。
15. As an 学习者, I want to 只导出当前 ACTIVE 习题, so that 未采纳候选和历史批次不会混在一起。
16. As an 学习者, I want to 未作答习题只显示题型、题干、难度和选项, so that 导出不会提前泄露答案。
17. As an 学习者, I want to 已作答客观题包含我的答案、判定、正确答案和解析, so that 文件可以用于订正。
18. As an 学习者, I want to 已提交但未自评的简答题标记为“待自评”, so that 它不会被误写成未作答或已完成。
19. As an 学习者, I want to 已提交简答题包含我的答案、参考答案和解析, so that 我能在文件中继续完成自评。
20. As an 学习者, I want to 已自评简答题显示最终正确或错误结果, so that 导出状态与页面一致。
21. As an 学习者, I want to 习题沿用页面顺序, so that 题目不会因为导出而重新排列。
22. As an 学习者, I want to Todo 导出我当前实际使用的正式清单, so that 手工项和被接管项不会丢失。
23. As an 学习者, I want to Todo 同时保留未完成和已完成项, so that 文件反映完整的行动记录。
24. As an 学习者, I want to Todo 使用 Markdown 任务列表, so that 常见编辑器可以直接识别勾选状态。
25. As an 学习者, I want to Todo 沿用现有追加顺序, so that 导出不会按来源或完成状态擅自重排。
26. As an 学习者, I want to Todo 候选和过时 AI 批次不进入文件, so that 正式清单不被污染。
27. As an 学习者, I want to Wave B 复习资料保留 Markdown 与代码块语义, so that 大纲和程序代码不会在接入导出后损坏。
28. As an 学习者, I want to 聚合文件按稳定的资产顺序排列, so that 每次导出都容易定位内容。
29. As an 学习者, I want to 文件以 Record 标题作为一级标题, so that 脱离应用后仍知道材料属于哪条学习记录。
30. As an 学习者, I want to 导出文件不包含内部 ID、批次 ID 或模型版本, so that 分享内容只有面向人的学习材料。
31. As an 学习者, I want to 文本中的 Markdown 符号保持字面含义, so that 题干或知识点不会意外破坏文件层级。
32. As an 学习者, I want to 文件使用 UTF-8 和稳定换行, so that 中文内容在常见 Markdown 编辑器中正常显示。
33. As an 使用 Windows 的学习者, I want to 默认文件名自动处理非法字符和保留名, so that Record 标题不会导致保存失败。
34. As an 使用 Windows 的学习者, I want to 中文文件名和中文路径正常工作, so that 我可以按自己的目录习惯保存材料。
35. As an 学习者, I want to 自己通过系统对话框选择保存位置, so that 应用不会把分享文件偷偷写入固定目录。
36. As an 学习者, I want to 取消保存时不产生文件、错误或成功提示, so that 取消就是无副作用操作。
37. As an 学习者, I want to 同名覆盖由系统保存对话框确认, so that 覆盖行为符合 Windows 习惯。
38. As an 学习者, I want to 读取任一已有资产失败时整次聚合导出失败, so that 缺失内容不会被伪装成“尚未生成”。
39. As an 学习者, I want to 权限不足或磁盘满时看到写入失败, so that 应用不会宣称一个不存在的文件已经保存。
40. As an 学习者, I want to 保存成功后看到明确的页内反馈, so that 我知道文件已经真实写入。
41. As an 学习者, I want to 保存后自行选择是否打开文件, so that 应用不会突然启动外部编辑器。
42. As an 学习者, I want to 打开文件失败时仍保留“文件已保存”的事实, so that 两个动作的结果不会混为一谈。
43. As an 离线用户, I want to 无网络时仍能导出已经存在的学习资产, so that 本地内容不依赖 AI Provider 可用性。
44. As an 本地用户, I want to 导出不产生 learning_events 或导出历史, so that 文件保存不会伪装成学习行为或新增业务事实。
45. As an 键盘用户, I want to 操作导出菜单、保存状态和打开动作, so that 该功能符合桌面端基本可访问性。
46. As an 维护者, I want to 新学习资产必须显式接入导出白名单, so that 新 Tab 不会在没有内容合同和测试时意外进入分享文件。

## Implementation Decisions

### 领域边界与资产白名单

- 使用“学习资产 Markdown 导出”指代本功能；“全量导出”继续专指数据目录迁移包。UI 在上下文明确时可简称“导出 Markdown”或“导出”。
- MVP 白名单固定为 Summary、知识点、习题和 Todo。复习资料由 Wave B 功能接入；Transcript 与 Ask AI 明确不支持。
- 新学习资产不得根据 Tab 名称或组件存在性自动发现。对应功能必须显式加入资产标识、序列化函数、可用性判断、聚合顺序和测试。
- 不为未来资产建立插件系统、工厂层或运行时注册机制。当前只需要一个固定有序白名单和每种资产一个小型纯序列化函数。

### 导出模式与最新事实

- Record 详情标题区提供一个统一“导出”菜单，包含“导出全部学习资产”和“导出当前 Tab”。不在每个资产面板重复放置按钮。
- “导出当前 Tab”只对当前受支持且存在合格内容的资产可用；Transcript、Ask AI、尚未接入的复习资料以及无合格内容的资产显示禁用原因。
- 单项导出触发时显式调用该资产既有读 API；聚合导出并行调用全部 MVP 资产的既有读 API。不能把 TanStack Query cache 当作最新事实，因为未挂载 Tab 可能从未加载或缓存已失效。
- API 明确返回“尚未生成”时省略资产；请求失败、响应不可解释或序列化失败不是“尚未生成”。聚合导出的任一必要读取失败都终止整个操作，不打开保存对话框。
- 多端点结果是各接口在点击后的最新事实，不承诺属于同一个 SQLite 事务快照。该 MVP 不增加后端聚合接口或数据库读事务来制造跨资产原子快照。
- 完成读取后形成不可变前端快照，再打开保存对话框。之后发生的采纳、作答、编辑或勾选留给下一次导出。
- 导出进行中禁用重复触发，避免同时打开多个保存对话框；完成、取消或失败后恢复。

### 各资产的资格与内容

- Summary 只有响应中的当前版本状态为 CONFIRMED 时可导出；GENERATED 等未确认版本不可导出，也不回退查找更早的确认版本。内容包含 topic、abstract 与 sections。
- 知识点只保留未删除的 ACTIVE 行，排除 DRAFT 和 SUPERSEDED；沿用 API/UI 顺序。每项包含名称、详情、`importance/5` 和标签；无标签时不制造空标签值。
- 习题只保留未删除的 ACTIVE 行，排除 DRAFT 和 SUPERSEDED；沿用 API/UI 顺序，不新增排序字段。
- 未作答 ACTIVE 习题只输出题型、题干、难度和按页面顺序排列的选项；正确答案与解析必须保持缺失。序列化器不得通过其他接口、历史数据或前端常量重建隐藏答案。
- 已作答客观题增加用户答案、CORRECT/WRONG 的本地化结果、正确答案和解析。答案以面向人的选项文字输出，不暴露内部 JSON 或选项下标。
- 简答题 `answered_at` 已存在而 `answer_result` 为空时，输出用户答案、参考答案、解析与“待自评”；自评后再输出本地化的正确/错误结果。
- Todo 正式清单包括未删除的 ACTIVE AI 项、手工项和被接管 AI 项；排除 DRAFT 与 SUPERSEDED。TODO 输出为未勾选任务，DONE 输出为已勾选任务，并严格沿用 `sort_order`。
- 聚合顺序固定为 Summary → 知识点 → 习题 → 复习资料 → Todo；缺失资产不产生标题或占位说明。各资产内部顺序完全沿用其 API/UI 现行顺序。
- 复习资料接入时必须提供可嵌入聚合文件的 Markdown 片段，保留标题层级、列表与 fenced code block 的语义；其具体数据合同随 Wave B 规格确定，不在本功能提前建模。

### Markdown 文档合同

- 文件一级标题为经过纯文本转义的 Record 展示标题。聚合文件和单项文件都使用同一一级标题；资产使用固定的本地化二级标题。
- Summary 在资产标题下输出主题、摘要和各结构化 section；section 标题和 point 列表保持原顺序。
- 知识点以名称作为分节标题，详情为正文，重要度与标签为面向人的字段列表。
- 习题按序号分节，题型、难度、选项、用户答案、结果、正确答案和解析依据可见性规则出现；同一字段不重复输出。
- Todo 使用标准 Markdown task list：TODO 为 `- [ ]`，DONE 为 `- [x]`。
- 不输出导出时间、course_id、record_id、batch_id、generated_from_summary_id、模型、prompt 版本或其他界面未展示的内部元数据。
- Summary、知识点、习题和 Todo 的业务字段按当前 UI 的纯文本语义处理：转义会改变 Markdown 结构的字符，保留用户可见文本和段落换行，不允许原始 HTML 注入文档结构。
- 文档使用 LF 换行、UTF-8 无 BOM，区块之间保留一个空行，文件末尾保留一个换行。相同输入必须得到相同文本，便于测试和比较。
- 系统生成的资产标题、题型和状态文字使用当前界面语言；不在导出交互中硬编码另一套不可翻译文案。

### 文件名与 Tauri 写入

- 聚合默认文件名为 `{Record展示标题}-学习资产.md`；单项默认文件名为 `{Record展示标题}-{资产类型}.md`。空标题复用 UI 的“未命名学习记录”。
- 文件名清理 Windows 非法字符、控制字符、尾部点和空格，并避开大小写不敏感的设备保留名；清理后为空时使用“未命名学习记录”。保存结果必须保持 `.md` 扩展名。
- 使用系统保存对话框让用户显式选择路径并处理同名覆盖。用户取消返回正常取消结果：不写文件、不显示错误、不显示成功。
- 使用已安装的 Tauri dialog 与 fs 能力；Rust 端注册对应插件，主窗口只授予保存对话框和文本写入所需的最小 capability。不得新增依赖，也不得通过 shell 命令拼接路径写文件。
- 已安装的 shell 打开能力用于成功后的“打开文件”。主窗口只增加所需的打开 capability，传递用户选择的路径而非拼接命令。
- Markdown 组装错误、资产读取错误与文件写入错误分别映射为用户可理解的页内错误。权限不足、磁盘满或路径无效时不得进入成功状态。
- 保存成功后显示页内 `status` 反馈与“打开文件”动作，不自动打开。打开失败显示独立错误，但继续保留文件已保存的成功事实。
- 导出只读取现有业务事实并写用户选择的外部文件；不建导出表、不记录导出历史、不写 learning_events，也不把文件强制写入数据目录的 `exports/`。

### 桌面交互与可访问性

- 导出菜单与既有 Record 标题区动作共同布局，沿用当前 Continuous Work Surface、Base UI/shadcn 原语、lucide 图标和 i18n；不引入新视觉系统或通知框架。
- 菜单、禁用原因、进行中状态、错误、成功和打开动作均可用键盘操作；纯图标动作必须有可访问名称。
- 进行中状态防止重复触发但不冻结 Record 的其他阅读操作。用户可以继续浏览，当前导出仍保存已经形成的快照。
- “导出全部学习资产”在已知没有任何合格资产时禁用；若最新读取后才确认全部为空，则不打开保存对话框并显示“暂无可导出内容”的页内说明。
- 离线只指外部网络不可用；只要 localhost sidecar 正常且资产已经存在，导出不得检查 Provider、外部处理同意或网络连接。

### 数据、API 与事件边界

- 复用现有 Record、Summary、知识点、习题和 Todo 读接口与生成的 OpenAPI 类型，不新增或修改后端端点。
- 不修改数据库 schema、迁移、worker、LLM 管线或状态机。
- 不直读 SQLite、数据目录或业务文件；所有业务数据仍经 localhost sidecar API 获取。
- 不产生 learning_events。保存 Markdown 是文件操作，不是学习行为、批次采纳或全量导出。

## Testing Decisions

- 好测试只断言外部行为：给定资产快照生成的 Markdown、用户从 Record 详情触发后的可见状态、调用现有 HTTP 接口与 Tauri 边界的结果，以及真实 Windows 文件内容。不断言纯函数内部步骤、React state 形状或调用辅助函数的顺序。
- 第一条接缝是纯序列化模块。使用一个紧凑的表驱动测试文件覆盖 Summary、知识点、习题、Todo、聚合顺序、空资产省略、纯文本转义、LF、末尾换行和稳定输出；不为每个小函数建立独立测试套件。
- 习题序列化必测四种外部状态：未作答不出现答案/解析、客观题已作答、简答已提交待自评、简答已自评。测试使用公开 API 响应形状，不读取数据库内部字段。
- Todo 序列化必测 ACTIVE AI、手工、被接管、TODO、DONE 的混排顺序，并证明 DRAFT/SUPERSEDED 被排除。
- 第二条且最高的自动化接缝是现有 Record 详情组件测试：继续使用 MSW 模拟 localhost HTTP，在 Tauri 边界 mock 保存、写入与打开能力，渲染真实 Record 详情交互。
- Record 详情必测：菜单可访问性；当前 Tab/全部两种方式；不支持与无内容禁用态；每次触发重新读取；全部资产并行读取；真正缺失时省略；任一读取失败时不打开保存框；取消无副作用；写入失败无假成功；保存成功；打开失败不推翻保存成功；重复触发被阻止。
- 不新增后端业务测试，因为本功能不改变 API、数据库或状态机。现有 OpenAPI 类型检查继续作为“未发生契约漂移”的门禁，而不是本功能成功的主要证据。
- Tauri 配置至少通过 Rust 格式、静态检查和桌面构建，证明 dialog/fs/shell 插件注册与 capability 配置可编译；这仍不证明真实路径已写入。
- 第三条接缝是真实 Tauri Windows 验收：使用含中文目录和中文 Record 标题的真实保存对话框，验证 `.md` 实际落盘、UTF-8 无 BOM、LF、同名覆盖、取消、页内成功和“打开文件”。该验收应读取落盘字节核对，不只观察 UI 文案。
- jsdom、MSW、Vite build 或 Rust 编译均不能替代真实 Tauri 文件系统验收；最终报告必须分别陈述序列化、组件交互、构建和真实 Windows 落盘四层证据。

## Out of Scope

- 链接分享、公开访问、`shares` 表、账号登录、GitHub Gist/Pages 发布渠道或单文件 HTML 分享。
- PDF、图片、图形化思维导图导出，以及用户自定义 Markdown 模板。
- 全量导出、换机导入、快照备份、`exports/` 数据目录管理或供应商密钥打包。
- 导出 Transcript、Ask AI 对话、DRAFT 候选、SUPERSEDED 历史批次或未确认 Summary。
- 绕过习题防剧透规则生成完整答案册，或为了导出查询隐藏的正确答案。
- 跨资产严格原子 SQLite 快照、后端聚合导出端点、导出任务队列、进度 Job 或导出历史。
- 数据库迁移、OpenAPI 变更、新依赖、learning_events 或日志正文记录。
- Wave B 复习资料的生成、确认、存储与具体内部 Markdown schema；本功能只保留显式接入口。
- 自动扫描 Tab、运行时插件注册、通用模板引擎或为未知未来资产搭建抽象框架。
- 自动打开文件、Windows 系统通知、打开所在文件夹或新增全局 toast 基础设施。

## Further Notes

- 本规格综合了计划 10 的 grilling 共识，并同步遵循项目术语：学习资产 Markdown 导出与全量导出是两个不同动作。
- 现有桌面依赖已经包含 Tauri dialog、fs 与 shell；实现工作是注册、最小授权和前端调用，不需要安装新包。
- 当前 Summary、知识点、习题和 Todo API 会返回不同生命周期的行；实现必须按本规格过滤，不能直接序列化整个 `items` 数组。
- 复习资料接入会使计划 16 消费本导出通道，但不能反向把 Wave B 的数据模型提前塞入本功能。
- 本选择易于调整且已由计划、PRD、数据模型与本规格直接说明，没有新增 ADR。
