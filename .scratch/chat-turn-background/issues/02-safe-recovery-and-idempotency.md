# 02：安全恢复与幂等

**What to build:** 应用中断后，用户重启能看到保存的内容，安全轮次自动续跑，已提交业务不重复；恢复条件失效时，在原会话处理明确等待原因后继续。模型重生成的片段有版本标识，原问题、原模型和授权边界保持明确。

**Blocked by:** [01：切换会话与持久控制](01-session-switch-and-control.md)

**Status:** ready-for-agent

## 规格与交付边界

- 依据父规格的 checkpoint、调用身份、恢复上下文、权限、模型、时间与来源决策；覆盖用户故事 9～11、16～17、27～40。
- 本票同时完成业务恢复、控制 API 和前端等待／正文替换。不能只交付 resume 参数或 checkpoint 续跑，而遗漏有副作用的工具路径。
- 普通提案仍允许回答完成。WAITING_USER 只用于继续执行必要的用户决定、恢复授权或故障处理；等待释放槽位但占用原会话，可继续或显式停止。
- 业务写入复用受控 Tool／领域 Service 和既有重试／补偿入口。Operation 和领域表是业务事实源，工具调用记录只服务执行对账与结果恢复。
- 02 前置安全能力全部通过后才开放自动／手动续跑；后台等待唤醒、专属子 Run 控制与清理压缩闭环继续由 03 收口。

## 验收标准

- [ ] 建立工具调用恢复记录及稳定逻辑身份，调用计划持久化后才允许副作用执行；调用键由稳定执行归属、namespace、逻辑调用身份构成，attempt 不进入来源键。
- [ ] 每项副作用使用稳定 effect_index；同身份参数指纹变化拒绝执行。新轮次中的同样意图属于新逻辑调用，不误去重。
- [ ] 明确核查全部有副作用的工具：Operation 写入、记忆提案、研究入库提案、计划／Run 创建、草案生成及再生成、Job 投递、重试和补偿；不以 Operation 工具名单代替完整覆盖。
- [ ] 每项来源键、业务结果和可恢复结果／回执同事务提交；已成功项恢复返回原结构化结果及对象 ID，不再写入业务。唯一键、CHECK 与公开 schema 在全量迁移库验证。
- [ ] 多结果工具先固定逐项计划；五项中前三项成功后崩溃，只补后两项并返回包含原五项身份的结果，不重新创建全部对象。
- [ ] 可重试失败沿既有受控入口原子领取，重验授权、取消和版本；不更换来源键，也不把失败记录当作成功跳过或永久不可恢复。
- [ ] 使用每轮独立 checkpoint 和框架公开状态 API，在持久安全边界推进；不清 checkpoint 续跑、不重复注入用户输入、不手工操作框架内部表结构。
- [ ] 分开处理首次执行、未完成图续跑和图已结束仅补写结果；业务库与 checkpoint 库先后落盘都能对账，不能假设双库原子提交。
- [ ] 业务已提交而调用结果／checkpoint 未保存时复用业务回执；图已完成而最终消息未保存时仅补写消息和终态，模型调用次数不增加。
- [ ] checkpoint 缺失、图版本不兼容或外部结果不明时先核对持久事实；无法确定安全边界则保留内容并等待处理，不一律从头调用模型或盲目重试。
- [ ] 保存范围、页面提示、已注入材料及来源版本、原系统提示／prompt／图／工具版本、原模型与供应商身份、授权来源、同意依据、时区与提交时间；不持久化凭据。
- [ ] 消耗预算、工具次数、联网熔断及用量跨恢复累计，沿既有错误分类和重试上限处理；预算耗尽明确失败，不无限重投。
- [ ] 重启对账在执行槽启动前完成；同进程故障只处理对应领取身份。QUEUED 正常领取，取消优先落实，终态不复活；运行中断进入安全继续、等待或失败。
- [ ] 重复 resume、并发对账和旧 worker 迟到只有一个有效触发和执行；旧身份不能落事件、终态、预算或新副作用。
- [ ] 类型化 resume 校验当前轮次、等待原因、对象版本及决定，不接受改写原问题／模型／范围／参数；继续按钮不等于批准业务提案或重新授权。
- [ ] 同进程降档约束新写入；重启后会话临时高权限失效，需该权限的步骤等待显式重新授权；全局依据按当前配置及原上限检查，升档不自动扩大范围。
- [ ] 已明确批准的独立 Run 保持既有契约，不顺带改写全部 Run 的授权规则；重新授权 ChatTurn 不批准新增目标、未确认内容或记忆。
- [ ] 绑定原供应商身份及模型，凭据从当前配置读取；原配置不可用、同意失效或已注入记忆不再允许外发时保留输出并等待，不静默换服务、改上下文或继续出网。
- [ ] 用户可以恢复原配置及同意后继续，或停止旧轮次并明确以新模型创建新轮次；新执行与旧恢复身份分开。
- [ ] 原问题的相对时间绑定提交时刻和原时区；已进入上下文的材料保持原快照。新的检索遵守原范围和当前访问边界，新写入检查当前版本／期限；日期过期或冲突不静默重规划。
- [ ] 模型节点重放增加 output_revision，只替换未完成 segment，不拼接两份半段正文；完成段落和回执身份保持，旧片段可查看并标识重新生成部分。
- [ ] 原消息位置展示中断／WAITING_USER 原因、授权处理、继续及停止入口；等待时禁止该会话新提交，停止后新问不覆盖旧用户消息。新增文案同步中英文及可访问性。
- [ ] 取消覆盖重放、工具和 WAITING_USER，持久取消先于恢复；副作用提交处仍校验取消与有效执行身份，已提交回执保留。
- [ ] 公开 API、真实 JobRunner、迁移库和既有领域写入的故障验证全部通过，01 行为保持；OpenAPI、生成类型、相关测试、类型与规范门禁通过。

## 验收证据

- 对照规格 T07～T15、T22；补齐 T05 的真正等待、T11 的等待／恢复取消、T12 的并发执行身份和 T21 的调用来源键迁移证据。
- 必须在“业务提交后、结果／checkpoint 保存前”“多结果第三项提交后”“图完成后、assistant 提交前”注入故障，并证明对象数量、原 ID、回执和模型调用次数正确。仅测 validator 或模拟状态变化不足以验收。
- [ ] 真实桌面在模型中途和业务提交窗口中断后重启，验证原内容保留、正文版本替换及业务不重复；记录真实模型、环境、提交与任务身份。
- [ ] 记录降档、重新授权、配置变化、外发同意失效和隔天恢复证据；自动化和真机分别标记，未做项不代勾；临时数据全部清理。

## 执行注意

开始前复核 01 实际闭环，不把已有 checkpoint、测试数量或工单勾选当作安全重放证明。实施完整调用覆盖后再开启续跑；任何覆盖缺口都保留安全等待，不降低验收要求。不要另建恢复平台或通用远端事务抽象。
