# 03：后台等待与完整验收

**What to build:** 回答必须等待后台处理结果时，原轮次释放执行槽，后台结果完成或重启对账后自动接续；停止能准确传播到专属子 Run。清理和事件压缩不会破坏未结束任务，真实桌面故障与交付证据完整收口。

**Blocked by:** [02：安全恢复与幂等](02-safe-recovery-and-idempotency.md)

**Status:** ready-for-agent

## 规格与交付边界

- 依据父规格的 WAITING_JOB、关联控制、压缩清理及最终验收决策；覆盖用户故事 18～20、25～26、41、45，并完成前两票保留的等待／关联控制验收。
- 复用已有领域 Job、RunControlService、Run 结果绑定与等待对账，不新建调度器、全局任务平台或无会话 Background Agent 入口。
- 仅在继续生成必须消费后台结果时令 ChatTurn 等待；仅返回创建回执的回答可以完成，Run 自己等待不机械等同于 ChatTurn 等待。
- ChatTurn、Run、Job 的独立生命周期不改变。已经明确批准的独立 Run 保持现有授权契约；取消不撤销已提交事实。
- 完全退出期间本地执行停止，重启安全恢复；不改宿主生命周期，不引入系统服务。

## 验收标准

- [ ] 在必须消费后台结果的真实 Agent 路径中持久保存原 Job／Run 引用、等待原因、所需结果与后续推进边界；再次恢复不会重新投递同一逻辑来源任务。
- [ ] 进入 WAITING_JOB 释放 ChatTurn 执行槽，同时保持同会话未结束约束；另一个会话可以领取推进，网络等待不占业务写事务。
- [ ] 完成通知只是提示，周期对账和启动恢复能发现原 Job 已成功、失败、未结束或被取消；成功消费真实结构化结果，失败明确分流，未结束继续等待。
- [ ] 同一结果被重复通知、重复对账或重启发现时只触发一次有效接续；结合执行身份、逐项来源键和持久关系，不重复正文、Operation、提案或 Job。
- [ ] 来源 Job 在领取执行中被强杀时，走其真实既有恢复和写回链路再接续轮次，保留来源对象身份；先手工标 SUCCEEDED 不算中断恢复证据。
- [ ] 创建专属子 Run 时持久保存所属 ChatTurn 和控制范围；共享、独立和专属关系可对账，不凭同一会话或内存集合猜测。
- [ ] 当前轮次停止通过现有 RunControlService 传播到专属子 Run；控制请求持久化后，即使崩溃重启也能补齐落实，取消与完成竞态终态唯一。
- [ ] 共享 Job、已提交且沿原契约继续处理的 Job 不误取消，成果和回执保留；轮次取消后不得消费其结果触发新步骤。
- [ ] 已完成 ChatTurn 关联的独立 Run 继续走现有 Run 控制入口；其状态展示和回执真实，不用 ChatTurn 完成或取消覆盖业务任务状态。
- [ ] 原会话展示后台等待原因、真实处理状态和停止入口，返回后可恢复等待或最终回答；关联任务和草案确认仍复用现有组件，文案同步中英文及可访问性。
- [ ] 停止覆盖所有非终态，补齐 WAITING_JOB、专属子 Run 和共享任务场景；前两票的取消、授权、旧 worker 迟到保护不被唤醒路径绕过。
- [ ] 活动会话删除保持冲突行为；既有清理入口保护非终态轮次依赖的 checkpoint、回执、调用结果、来源键和等待关系，清理不能使未完成副作用失去去重依据。
- [ ] 终态事件压缩先保存可独立同步的快照、压缩游标、必要正文版本与业务引用；旧游标重连明确重置到权威快照，不静默跳过正文或引用。
- [ ] 消息与业务事实按既有保留策略管理，事件压缩不等于删除最终消息；恢复依赖解除前不得删除相关元数据，不新增保留策略设置页。
- [ ] WAITING_JOB、关系记录及压缩游标的迁移／唯一索引／CHECK／schema／公开 API 一致；所有迁移使用真实库验证，编号依据实施时现状顺延。
- [ ] 完整复核 Q1～Q5：普通提案不阻塞；真正等待可以处理／停止；临时高权限重启后重新确认；原模型不静默替换；原时间语义与已注入材料保留；当前访问、版本及期限仍重验。
- [ ] T01～T23 的证据逐项可定位到实际测试或真实环境记录；保留 01／02 通过证据，只有新增行为、失败或未解决风险才扩大／重复验证，不补历史测试体系。
- [ ] 相关测试、后端／前端类型与规范、OpenAPI、生成类型及触及文件格式门禁通过；实际有变更的模块完成必要检查，未变更的门禁证据注明来源和提交。
- [ ] 汇总权威文档增补提案：实际表及迁移、切换／停止／恢复契约、ChatTurn 术语、必要 ADR 及真实项目进度；与既有数据模型升版提案协调。未经批准不直接修改权威文档，批准后同步版本及交叉引用，项目进度保持 200 行以内。
- [ ] 交接记录明确区分代码完成、自动化通过、真实桌面通过及文档待批，未完成事项保留真实状态；前两票通过不冒充完整需求交付。

## 验收证据

- 本票重点完成 T16～T20，补齐 T11 的所有等待／关联取消和 T21 的本票持久化；依据 T23 汇总整条链的真机证据。
- 后端以公开 API＋真实 JobRunner＋迁移后的临时 SQLite 验证通知丢失、来源 Job 中途退出、重复唤醒、控制传播和清理保护；模型／网络替身不得替代来源 worker 的恢复写回。
- [ ] 在真实 Tauri＋sidecar＋WebView2 中验证 A／B 切换、离开期间完成、刷新、断线、隐藏、完全退出重启和强杀恢复；真实模型和模型桩证据分别记录。
- [ ] 在后台 Job 执行中退出，在等待确认、WAITING_JOB 和停止过程中重启；对照同一 turn_id、Run／Job 及 Operation 检查没有重复对象或取消复活。
- [ ] 真机查看专属子 Run 取消、共享 Job 继续、已完成回答的独立 Run 控制、恢复版本展示及压缩旧游标同步。
- [ ] 记录实现提交、环境、模型、轮次及业务任务身份、预期与实测结果；临时测试数据和 basetemp 完成后清理，未执行的用户真机项不代勾。

## 执行注意
