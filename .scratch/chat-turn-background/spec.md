# 切换会话不中断任务与安全恢复

Status: ready-for-human（01～03 代码已实现；完整真机验收及权威文档审批未闭环）
确认日期：2026-10-06
当前实施核查基线：5da4076；票 03 实施和验收见 [交接记录](implementation-03.md)
决策依据：设计方案及本次 grill Q1～Q5，用户已确认“全部按建议”。

## Problem Statement

用户让 Agent 回答问题或执行任务时，切换聊天会话、进入其他页面或刷新 WebView，会断开正在消费生成器的流式连接。本规格解决离开视图与停止回答混用取消路径、导致原任务中断的问题；当前实施已将订阅关闭和显式停止分开。

正文仅在生成完成后保存、过程摘要不能还原回答、会话级 checkpoint 提前清理，是本规格处理的原始缺口。01～03 已建立持久受理、结果补发、安全续跑和后台等待；相关自动化与未验收项见各工单记录。单纯保留前端请求无法解决应用退出、服务崩溃、重复提交和工具副作用重放。

用户需要在同一个本地工作台同时处理不同会话：离开后任务继续，返回后看到真实状态和完整输出；完全退出期间停止本地执行，重启后保留内容并安全恢复；只有明确的停止指令才取消任务。

## Solution

新增 ChatTurn，表示一条用户输入对应的一次回答生成。提交、观察和控制相互分离：后端原子受理输入，通过现有 JobRunner 独立执行；前端读取持久快照并按游标订阅已提交事件。切换会话只解除订阅。

复用 Deep Agents／LangGraph 编排和 checkpoint，复用现有 Tool、领域 Service、Proposal、Run、Operation 及 ProcessingJob。checkpoint 承载运行状态，Operation 和领域表承载业务事实；恢复需要同时核对两者，不能凭 checkpoint 重放业务写入。

普通提案仍允许回答正常完成，用户稍后独立确认。只有继续生成确实需要用户决定或后台结果时，ChatTurn 才进入等待。重启时重新检查权限和外发同意，按原模型、原任务语义恢复；条件失效时保留成果并明确等待处理。

本次交付包含三个阶段的完整能力。第一阶段可单独验收会话切换，但安全续跑、等待关联和完整故障验收全部完成前，不宣称整个需求交付。

## User Stories

1. 作为用户，我希望会话 A 生成时能切换到会话 B，以便处理其他问题而不中断 A。
2. 作为用户，我希望不同会话能够并发生成，以便较慢的回答不阻塞其他会话。
3. 作为用户，我希望进入资料、课程或设置页面时原任务继续，以便自由使用工作台。
4. 作为用户，我希望返回原会话看到已经保存的输出，以便接着阅读正在生成的回答。
5. 作为用户，我希望原任务在离开期间完成后能直接看到最终消息，以便不必重新提问。
6. 作为用户，我希望刷新 WebView 后重新同步原任务，以便刷新不产生第二次执行。
7. 作为用户，我希望网络连接断开后能够补发输出，以便不丢失或重复拼接正文。
8. 作为用户，我希望隐藏窗口且后端存活时任务继续，以便暂时离开桌面。
9. 作为用户，我希望完全退出后任务和输出仍保留，以便重启后继续处理。
10. 作为用户，我希望重启后安全任务自动恢复，以便不必手动重新提交同一问题。
11. 作为用户，我希望暂时无法恢复的任务说明原因，以便决定如何处理。
12. 作为用户，我希望重复点击或重试提交不会重复创建消息和任务，以便接受结果不受通信失败影响。
13. 作为用户，我希望相同提交身份对应不同内容时被明确拒绝，以便原任务不被暗中替换。
14. 作为用户，我希望同一会话一次只有一轮未结束生成，以便回答顺序明确。
15. 作为用户，我希望普通确认提案不会阻止回答结束和下一次提问，以便确认卡可以稍后处理。
16. 作为用户，我希望真正需要决定的轮次显示等待原因和操作入口，以便解除等待。
17. 作为用户，我希望真正等待的轮次可以明确停止，以便之后提出新问题。
18. 作为用户，我希望任务等待后台处理时释放执行槽，以便其他会话仍能推进。
19. 作为用户，我希望后台处理完成后原轮次自动接续，以便看到依赖其结果的回答。
20. 作为用户，我希望原后台任务失败后看到真实失败信息，以便选择已有恢复入口。
21. 作为用户，我希望停止通过后端持久取消指令落实，以便断线后不会继续执行新步骤。
22. 作为用户，我希望无法立即中断的调用显示“正在停止”，以便状态与实际执行一致。
23. 作为用户，我希望停止后保留已提交的结果和回执，以便知道任务完成了哪些工作。
24. 作为用户，我希望取消不被当作撤销，以便业务历史保持真实。
25. 作为用户，我希望停止当前轮次时能控制其专属子 Run，以便取消范围可解释。
26. 作为用户，我希望停止不误伤共享 Job 或其他任务，以便独立工作继续进行。
27. 作为用户，我希望恢复时不会重复创建课程、记录、提案、Run 或 Job，以便重启不会复制业务数据。
28. 作为用户，我希望批量工具部分成功后只补未完成项，以便已完成对象保持原身份。
29. 作为用户，我希望图已完成但最终消息未保存时只补写结果，以便不再支付重复模型调用成本。
30. 作为用户，我希望模型重生成的未完成片段明确标识，以便不会把两份回答误读为连续正文。
31. 作为用户，我希望恢复前后的正文版本可查看，以便保留中断时已经看到的内容。
32. 作为用户，我希望会话降档能够约束后续受控操作，以便授权变化及时生效。
33. 作为用户，我希望会话临时高权限不会因重启自动延续，以便恢复需要的授权仍由我控制。
34. 作为用户，我希望已明确批准的独立 Run 保持既有授权契约，以便本次聊天改造不改变其规则。
35. 作为用户，我希望恢复继续使用原供应商身份和模型，以便任务不会暗中更换处理服务。
36. 作为用户，我希望供应商不可用或外发同意失效时任务等待处理，以便我的内容不会被自动发给另一服务。
37. 作为用户，我希望使用新模型重新生成是明确的新执行，以便原任务与新结果可以区分。
38. 作为用户，我希望隔天恢复时原问题的“今天”仍指提交当天，以便意图不会被悄悄改变。
39. 作为用户，我希望已经进入上下文的材料保留原快照，以便恢复继续处理同一份输入。
40. 作为用户，我希望新检索和业务写入检查当前可访问数据、版本及期限，以便恢复不绕过现实约束。
41. 作为用户，我希望清理历史时不会破坏未结束任务的恢复依赖，以便清理不造成重复执行或结果丢失。
42. 作为用户，我希望删除有未结束轮次的会话时得到冲突提示，以便先决定是否停止任务。
43. 作为用户，我希望失败发生在一个执行槽时其他槽不受影响，以便故障不会中断全部会话。
44. 作为用户，我希望状态、等待原因和控制按钮支持中英文及键盘访问，以便一致地使用现有界面。
45. 作为验收者，我希望自动化证据和真实桌面故障验收分别记录，以便不把模拟执行当作真实交付。

## Implementation Decisions

### 1. 职责与事实源

- ChatSession 管会话归属和历史；ChatTurn 管单轮回答生成；Run 管业务计划执行；Operation 管单项执行事实及回执；Proposal 管待确认建议；ProcessingJob 管持久调度。
- ChatTurn 完成不代表关联 Run 完成，Run 等待不必使 ChatTurn 等待。普通确认卡、学习计划草案审核和长期记忆确认保持独立业务边界。
- ChatTurn Service 提供受理、查询、取消和恢复控制；事件服务只读持久事件，不启动或取消 Agent；领域 Service 继续负责业务校验和提交。
- 既有 ChatResponseProcess 保留过程展示用途，其新轮次状态由 ChatTurn 和工具调用记录投影，不再作为第二套执行状态机。历史消息和过程仍可读。
- 本地业务数据和恢复记录仍落在现有用户数据目录，不引入外部基础设施、账号或额外安装要求。

### 2. Agent 接入与受控执行

- 自然语言任务仍通过现有聊天 Agent、类型化工具和领域 Service 执行；此次改变运行生命周期，不建立另一套 Agent 平台。
- 所有发起聊天的页面入口使用相同受理 API。目标对象、读取范围、页面提示、授权依据分别记录；页面提示与模型判断不构成授权。
- 缺少信息时沿用现有追问和提案路径。普通澄清回答可以完成本轮，让用户下一轮补充；只有已暂停执行确实依赖决定时才使用轮次恢复入口。
- 模型调用前、工具调用前及后台 Job 提交前的取消、权限和预算检查优先放入 Middleware；业务提交处仍须最终检查，不能仅依赖 Middleware。
- 不为 Agent 增加自行批准、任意 SQL、任意路径写、宿主 Shell 或自动扩大范围的能力。

### 3. 持久记录与约束

- 新增轮次、轮次事件和工具调用恢复记录。迁移编号由实施时实际最大编号顺延，不预占其他工作的编号。
- 轮次至少保存会话与输入消息引用、request_id、规范化原请求指纹、解析后的执行快照、状态、取消标记、领取身份、执行尝试、checkpoint 标识、输出版本与快照、last_seq、最终消息引用、等待原因、错误、预算及时间信息。
- 事件至少保存 turn_id、单调递增 seq、attempt、output_revision、类型、正文 segment_id 或稳定 tool_call_id，以及事件载荷。事件载荷可引用业务对象，不复制其权威状态。
- 调用记录至少保存稳定逻辑身份、工具名、参数指纹、调用状态、逐项副作用身份、可恢复结构化结果，以及关联 Proposal／Operation／Run／Job。
- 数据库保证同一会话最多一个非终态轮次、同一轮次事件序号唯一、请求去重身份唯一、逻辑调用与副作用来源键唯一；CHECK、索引、ORM 和公开 schema 同步。
- 凭据不得存入请求快照、事件、展示载荷或恢复审计。供应商身份、同意依据和配置版本可以保存，密钥从现有配置读取。

### 4. 公开 API 与受理幂等

| 操作 | API | 行为 |
| --- | --- | --- |
| 提交 | POST /api/chat-sessions/{session_id}/turns | 原子受理，返回 202、turn_id 和实际状态 |
| 查询会话轮次 | GET /api/chat-sessions/{session_id}/turns | 包含未结束及已结束轮次，支持游标分页 |
| 查询快照 | GET /api/chat-turns/{turn_id} | 一致地返回状态、正文、业务引用、输出版本和 last_seq |
| 补发与订阅 | GET /api/chat-turns/{turn_id}/events?after_seq=N | 返回 N 之后的已提交事件，并持续观察 |
| 停止 | POST /api/chat-turns/{turn_id}/cancel | 持久受理取消，返回实际状态和 cancel_requested |
| 继续 | POST /api/chat-turns/{turn_id}/resume | 校验等待原因、恢复条件及必要决定后重新排队 |

- 继续 API 只接收对应等待原因需要的类型化决定，不允许任意改写原输入、模型、范围或业务参数；新授权仍走既有显式授权入口。
- 客户端为一次提交生成稳定 request_id；未确认受理结果前的网络重试保留该身份。提交成功后才能切换为对 turn_id 的观察。
- 同一会话内相同 request_id 与相同规范化请求返回原轮次；相同身份但内容、范围、联网、页面提示或授权参数不同，返回 409 冲突。原任务终态后也不能复用该身份创建新轮次。
- 请求指纹使用客户端原请求的规范化结果，和读取全局配置后解析出的执行快照分开保存。全局设置变化不能让同一请求的重试误判为内容冲突或新任务。
- 在同一业务事务中校验会话占用并保存输入消息、ChatTurn 和 CHAT_TURN ProcessingJob；任一步失败全部回滚。幂等命中不重复落用户消息。
- 同一会话的新提交遇到未结束轮次返回冲突，不建立隐藏消息队列。等待状态同样占用会话；用户处理等待或停止后才能新问。
- 旧流式生成入口在迁移期间与新入口共用数据库级占用约束；当前前端调用全部迁移后移除旧执行入口，不留下双路径绕过。
- 使用稳定错误码区分会话占用、指纹冲突、依赖失效、恢复条件不满足和版本不兼容，并同步公开契约及错误翻译。

### 5. 输出保存、补发和最终消息

- 采用输出快照和有序事件日志。正文增量可以短时批处理，但必须在同一事务提交事件与对应快照后才通知或发送给客户端。
- 公开过程只包含可展示的说明、工具状态及结果引用，不保存模型私有思维链。
- 查询快照以一致数据库视图返回 last_seq；客户端渲染后从该序号补发。重复 seq 忽略，缺口重新同步；不得依据内存消息重建权威顺序。
- 通知仅降低延迟，丢失通知仍可按数据库游标补发。慢订阅者不能阻塞执行，积压超限断开后允许重连同步。
- 最终正文可能经过引用解析与整理，完成事件必须返回权威最终快照，替换客户端的临时拼接正文。
- assistant 消息、最终引用、轮次终态和完成事件在业务库原子提交；同一轮次只有一条最终 assistant 消息。图完成后的恢复只补写缺失结果。
- 取消、失败和等待时保存部分输出及真实业务引用。前端以轮次引用展示，不把无最终消息简单等同于“需要补答”。

### 6. 状态机与调度

| 状态 | 含义 | 允许推进 |
| --- | --- | --- |
| QUEUED | 已受理，等待领取 | 领取后 RUNNING；取消落实后 CANCELLED |
| RUNNING | 当前有效 worker 执行中 | 完成、失败、真正等待、环境中断或落实取消 |
| WAITING_USER | 继续执行需要明确决定 | 校验决定后 QUEUED，或落实取消 |
| WAITING_JOB | 已提交且必须消费后台结果 | 对账后 QUEUED、失败分流，或落实取消 |
| INTERRUPTED | 执行环境中断，等待对账 | 安全排队、等待用户或失败；已有取消优先 |
| COMPLETED | 最终消息和结果已提交 | 终态，只读 |
| FAILED | 不可恢复或预算耗尽 | 终态；重新生成创建新轮次 |
| CANCELLED | 取消已落实 | 终态，不自动复活 |

- 切换、刷新、断线不触发状态转换。cancel_requested 是控制标记，“正在停止”不是提前写入 CANCELLED。
- 复用 WorkerSpec／JobRunner，CHAT_TURN 初期固定两个执行槽；每槽独立执行，数据库条件领取与提交防止重复运行。其他领域 worker 保持现有调度。
- WAITING_USER 和 WAITING_JOB 释放执行槽，但不释放会话未结束轮次约束。持久等待引用和周期对账弥补丢失通知，不能忙轮询或长期占槽。
- 每次领取使用新的执行身份及增加 attempt。事件、状态、预算和业务提交检查当前有效身份；迟到的旧 worker 不能覆盖新结果或提交新副作用。
- 网络等待不持有数据库写事务。执行重试、预算耗尽和不可重试错误沿现有 JobRunner／领域错误分类，恢复不重置已消耗预算或形成无限重试。
- 运行期执行或写回故障只收口对应轮次与 job，不能调用覆盖全部 RUNNING 的启动恢复逻辑。已提交结果对账补写，未完成任务进入可处理状态；数据库暂时不可写时保留故障身份并重试针对性收口，恢复可写后不能永久占用会话。

### 7. 等待语义（已确认 Q1）

- 普通提案、批量计划卡、记忆确认和内容审核不自动令 ChatTurn 进入 WAITING_USER；Agent 可以说明已提交提案并完成回答，之后确认由现有业务入口独立处理。
- 轮次仅在继续生成必须消费用户决定、恢复授权或故障处理结果时暂停。等待原因及可选动作持久保存，并由公开快照提供给前端。
- 继续前重新核对轮次、等待原因和对应对象版本；重复继续最多建立一个有效触发，不能重复注入用户输入或批准业务提案。
- 真正等待的轮次在原会话提供继续、处理必要授权和停止入口。停止后新问创建新轮次，不改写旧轮次或旧用户消息。
- Run 的 WAITING_USER 独立管理；不把一个 Run 的待确认状态机械复制成回答生成的等待。

### 8. checkpoint 与双库恢复

- 每轮使用独立 checkpoint 身份，命名为 chat-turn-{turn_id}。新轮次构建输入，续跑使用现有图状态，不重新注入原输入、不清空原 checkpoint。
- 使用现有 AsyncSqliteSaver 和框架状态读取／恢复 API；采用同步持久化安全边界保证已记录的调用计划先于副作用开始，不手工查询或维护框架内部表结构。
- 首次执行、未完成图续跑、图已完成仅补写最终结果是三条独立入口。checkpoint 缺失时先核对业务副作用与持久结果；不能一律重新调用模型。
- 业务库和 checkpoint 库不具备跨库原子提交。调用计划、业务回执、逐项来源键与最终结果用于对账，两边任何一侧先落盘都不得产生重复业务对象。
- 已受理但未执行的任务照常领取；模型节点中断保留已提交输出并从安全边界重放未完成节点；工具业务已提交但 checkpoint 未保存时复用原结果。
- 图已完成但 assistant 缺失时从最终图状态／持久结果补写，不调用模型；assistant 与终态已保存时仅查询补发。
- 等待确认不自动批准；等待 Job 对账原 Job；取消已持久受理时优先落实。图版本不兼容或结果无法确定时保留内容并等待处理，不盲目重放。
- 启动对账全局扫描发生在执行槽启动之前；运行期仅针对故障领取身份处理。自动恢复开关只在副作用幂等和完整恢复契约通过验收后启用。

### 9. 工具逻辑身份与逐项幂等

- 工具调用身份来自已持久化的调用计划，包含稳定 execution_id、graph namespace 与 logical_call_id；本期 ChatTurn 提供稳定执行归属，attempt 不进入身份。
- 一次逻辑调用产生多个副作用时，来源键再包含稳定 effect_index。同一身份参数指纹变化拒绝执行；用户新一轮提出相同请求仍是不同逻辑调用。
- 覆盖所有有副作用的工具，不以已有 Operation 工具名称集合代替覆盖清单：创建／修改／归档／移动／删除、记忆和研究入库提案、批量计划与 Run 创建、后台 Job 投递、重试及补偿均须核查。
- 每个本地副作用的来源键、业务写入和可恢复结果／回执同事务提交。恢复命中已成功项返回原对象 ID 和结构化结果，跳过业务写入。
- 多结果工具必须先固定逐项计划及顺序。五项中的前三项成功后中断，只补后两项，并返回包含原五项身份的完整结果。
- 可重试失败通过既有受控重试入口原子领取并重新校验权限、取消及版本，不重新建立来源键，也不把一次失败记录误当作永久成功。
- 已持久化的模型调用计划恢复时复用；未完成模型节点的重生成不能重放已提交副作用。重复恢复、并发重试及迟到写回都服从当前领取身份。
- 外部结果不明的调用不自动重试，进入核验等待；本期不新增外部写工具或通用远端事务框架。

### 10. 恢复上下文与正文版本

- 保存已解析范围、页面提示、已注入上下文和来源版本、模型与供应商身份、系统提示及 prompt 版本、工具集合、图版本、授权来源、外发同意依据、用户时区、提交时刻及已消耗预算。
- 重启不重新从全局配置推导一份不同的原输入；配置变化和运行条件重验与原输入快照分开处理。
- 模型节点重放使用新的 output_revision，替换对应未完成正文 segment；不得把新的半段正文追加到旧半段之后。已完成段落及业务回执保持原身份。
- 旧正文片段保留供用户查看，并明确标注恢复时重新生成的部分；公开快照和事件都能表达当前版本及替换范围。
- 重生成消耗计入原轮次预算和尝试记录，不能恢复时重置调用次数、联网熔断或用量。

### 11. 权限恢复（已确认 Q2）

- 原授权是上限，恢复只能在当前有效授权内推进。升档不自动扩大原对象集合、参数或批准版本，页面上下文和恢复按钮不等于授权。
- 同进程切换页面不撤销授权；会话降档继续约束未提交操作。取消与有效领取身份同样在业务事务提交前校验。
- 保存授权来源，区分全局档位依据、会话临时覆盖和绑定对象集合／参数／版本的明确批准。
- 重启后会话临时高权限失效；需要该权限的未提交写入进入 WAITING_USER，只有显式重新授权后才推进。只读工作可以在当前有效权限内继续。
- 基于全局档位的恢复按当前全局配置重验，同时不能超过原依据；不暗中把全局设置变化扩大为旧任务授权。
- 已明确批准的独立 Run 保持既有契约；已有 Run 的其他授权规则也不借本次改造整体重写。ChatTurn 重新授权不能给关联 Run 增添目标或批准未确认内容。
- 当前权限或外发同意失效后，不复用进程内旧配置绕过校验。未提交步骤等待或拒绝，已提交事实不回滚。

### 12. 模型和供应商恢复（已确认 Q3）

- 绑定原供应商身份、地址身份及模型。凭据从现有配置读取，但原身份／模型不可用时不自动换成当前默认供应商或模型。
- 原身份和模型仍可用时，在当前有效外发同意及记忆外发开关范围内续跑；密钥或地址变化导致同意失效时，先重新确认。
- 供应商不可用、必要同意失效或已注入记忆不再允许外发时保留输出、显示原因并等待用户处理，不默默改变上下文继续出网。
- 用户可以恢复原配置及必要同意后继续，也可停止旧轮次并明确以新配置创建新轮次。更换模型重新生成不得保留为原轮次的静默续跑。

### 13. 时间、来源与现实约束（已确认 Q4）

- 原问题的相对时间绑定提交时刻和原用户时区。周一提交的“今天”在周二恢复时仍指周一，不自动改写为周二任务。
- 同时保留提交时间和当前执行时间，恢复提示明确区分两者。时间工具仍按自身现有语义返回实际查询时间；已完成调用的重放复用持久结果。
- 已进入上下文的材料继续使用原快照和来源身份；尚未发生的检索读取当前可访问数据，维持原范围并记录实际来源版本。
- 当前读取权限、软删／归档和外发边界仍须重验，保存过上下文不构成继续访问或发送的授权。
- 所有新写入重新校验当前对象版本、授权绑定版本和有效期限。日期过期或对象冲突时明确等待或拒绝，不静默重规划日期、覆盖新内容或扩大对象范围。

### 14. 停止、子任务与删除

- cancel API 原子写入取消标记，并尽力唤醒和中止当前调用；取消不依赖下一条 token。排队、模型调用、工具调用及两个等待状态均可停止。
- 取消先提交后禁止该轮次新增副作用；业务先提交则保留真实结果。最终完成先提交时保持 COMPLETED，取消先提交时保存部分成果并收尾，不能同时得到两个终态。
- 只有执行确实停止且该轮次不再推进时写 CANCELLED；无法立即中断时显示“正在停止”，迟到输出不得转回完成。
- 专属子 Run 的取消通过现有 RunControlService 传播。创建时持久保存专属／共享关系及控制范围，以便崩溃后仍能落实取消；不凭同一个 session_id 判断归属。
- 共享 Job、已提交且按原契约继续处理的 Job 保留结果和回执；取消后的轮次不消费结果触发新步骤。已完成 ChatTurn 的独立 Run 继续通过既有 Run 控制入口管理。
- 有非终态 ChatTurn 的会话删除返回冲突，并提供先停止的入口；不隐式取消。不因删除会话清除独立业务执行历史。

### 15. 前端观察与交互

- 保留现有三栏 Chat 工作区和 DESIGN 视觉体系，不新增全局任务平台或重设计页面。复用现有查询缓存、过程组件、确认卡、Run 面板及 shadcn 控件。
- 会话切换和组件卸载只关闭订阅；停止按钮发持久取消请求。前端 AbortController 只管理连接，不能作为业务取消依据。
- 返回会话同时加载消息历史与轮次，包含离开期间已完成的轮次；以 turn_id／最终消息引用合并，避免同一回答出现两次。
- 输入区依据非终态轮次决定可否提交，区分排队、运行、等待用户、等待 Job、恢复中和正在停止；状态不能由“最后一条是 USER”猜测。
- 等待及中断信息在原消息位置展示原因和可执行动作；普通确认卡继续使用原入口。恢复版本以简短标识及可展开旧片段展示，不用模态流程阻塞切换。
- 恢复及出错只提示当前会话实际状态；不每次轮询弹通知，不把切换其他会话当成控制命令。
- 用领域描述呈现错误，内部错误码仍便于日志定位；新增或修改文案同步中英 key。按钮有可访问名称，等待与恢复状态不只依赖颜色，状态更新避免逐 token 屏幕阅读播报。
- 成功业务写入、最终回执及恢复补写沿既有缓存失效路径通知相关页面，不能直到切换页面才发现旧数据。

### 16. 事件压缩、清理和审计

- 对已结束轮次可压缩旧增量事件，但先保留可独立恢复的最终快照、压缩游标、必要正文版本及业务引用；请求早于保留游标时明确返回重置快照，不静默跳过缺口。
- 非终态轮次依赖的 checkpoint、调用结果、逐项来源键、回执和等待关系受保护。既有操作历史清理与会话删除入口也必须执行保护检查。
- 最终正文和业务事实的既有保留策略不变；事件压缩不等于删除消息，清理恢复元数据不能先于依赖解除。
- 日志记录 turn_id、job_id、attempt、稳定逻辑调用身份、状态迁移、等待原因、恢复结果及错误码，不记录密钥或完整敏感输入。
- 不引入可配置保留策略产品页；实施时沿用既有显式清理入口及默认策略，重点验证清理不破坏恢复。

## Testing Decisions

### 验证边界（已确认 Q5）

- 首选最高可用接缝：公开提交／查询／控制 API，加真实 JobRunner、现有领域 Service 和迁移后的临时 SQLite。模型和网络使用可控替身，数据库写入、领取、业务回执和恢复不以 mock 替代。
- 复用既有聊天流、JobRunner、提案、授权、批量 Run 和等待恢复测试的应用工厂、领域请求与故障注入接缝；已有测试足以证明行为时不新增测试。
- 只为本次新行为或新故障窗口增加最小用例，断言用户可见状态、消息、业务对象数量和身份、回执与出网次数，不绑定私有 helper 或实现细节。
- 前端复用既有 chat 集成测试，验证切换、历史合并、控制和事件恢复；不另建通用测试框架。
- 真机采用真实 Tauri、sidecar 和 WebView2，记录环境、提交、轮次与关联任务身份；与自动化证据分开，不代勾用户真机验收。
- 临时数据目录、数据库及 pytest basetemp 均独立于用户数据，测试完清理；不使用生产数据库注入崩溃或验证迁移。

### 必须证明的行为

| 编号 | 场景 | 可观察验收 |
| --- | --- | --- |
| T01 | A 生成时切到 B 再返回 | A 未取消、未重新执行，B 可独立推进，A 输出可恢复 |
| T02 | A 离开期间完成 | 返回直接看到一条最终 assistant 消息及真实回执 |
| T03 | 刷新、断线、重复订阅、事件缺口 | 不重复提交，不丢失或重复正文，游标正确补发 |
| T04 | 相同 request_id 并发提交、内容冲突、设置变化 | 只有一个 user／turn／job；不同原请求冲突，同请求重试不受配置漂移影响 |
| T05 | 普通提案与真正等待 | 普通提案允许回答完成和新问；真正等待占用会话，可处理或停止 |
| T06 | 两槽执行，一个槽写回失败 | 另一个继续；故障轮次能针对性收口，不长期 RUNNING |
| T07 | 模型节点中途强杀后重启 | 已显示内容保留，未完成段落按版本替换，不再次注入用户输入 |
| T08 | 本地业务提交后、调用结果／checkpoint 保存前崩溃 | 复用业务结果，不重复创建对象或回执 |
| T09 | 五项工具第三项提交后崩溃 | 恢复仅补两项，五个结果身份稳定；含提案和 Job 创建路径 |
| T10 | 图已完成、最终消息未提交时崩溃 | 仅补写消息与终态，模型调用次数不增加 |
| T11 | 所有非终态停止与完成／取消竞态 | 取消先落库后不新增副作用，已提交成果保留，终态唯一 |
| T12 | 重复继续、并发恢复及旧 worker 迟到 | 只有一个有效执行，旧身份不能落事件、终态或副作用 |
| T13 | 同进程降档和临时高权限跨重启 | 新写入按当前及原依据检查，需重新授权时等待；不改既有独立 Run 契约 |
| T14 | 供应商／模型变化、同意失效、记忆外发关闭 | 不静默换服务或绕过同意，保留输出并等待处理 |
| T15 | 隔天恢复、来源改动、删除、日期过期 | 原时间语义和已注入快照保留；新检索守范围，新写入冲突或过期被阻止 |
| T16 | WAITING_JOB 完成通知丢失和重启 | 周期对账原 Job，接续不重复投递，等待释放执行槽 |
| T17 | 来源 Job 在执行中被中断 | 走真实来源 worker 恢复／写回，再推进等待轮次；不能仅先标 SUCCEEDED 冒充验证 |
| T18 | 停止专属 Run、共享 Job 和已完成回答的独立 Run | 控制范围准确，共享任务不误取消，已提交事实可查 |
| T19 | 删除活动会话、清理回执／checkpoint | 活动删除冲突，恢复依赖受保护；终态清理按既有规则可用 |
| T20 | 事件压缩后的旧游标重连 | 明确获得权威快照及重置游标，最终消息和引用完整 |
| T21 | 三种调度状态升级与迁移持久化 | 全量迁移库的 CHECK、唯一索引和公开契约成立，不仅测 schema validator |
| T22 | 重试／恢复预算、不可重试错误 | 消耗跨恢复累计，耗尽可解释失败，不形成无限重投 |
| T23 | 真实桌面切换、刷新、退出重启、强杀恢复 | 任务／消息／业务回执一致；记录真实证据，模拟结果不代替验收 |

T01～T06、T11 和基础迁移可在第一阶段验收；T07～T15、T22 在安全恢复阶段验收；等待关联、清理、压缩及完整桌面故障验收在最后阶段完成。任何阶段仍须守住已交付阶段的行为。

## Out of Scope

- 完全退出应用后继续执行、独立后台宿主、系统服务或改变 Windows sidecar 生命周期。
- 新建任务平台、消息中间件、分布式调度、Multi-Agent 自治平台、Skills／MCP 生态或通用远端事务框架。
- 新增无会话 Background Agent 产品入口或全局任务管理页面；本期保持执行边界可复用即可。
- 业务能力扩展、任意 Shell／SQL／文件写、自动批准内容与记忆、授权范围自动扩张。
- 保证重现模型服务端原来的 token 流、保证模型重生成完全相同或恢复模型内部思维链。
- 改写既有独立 Run 的整体授权机制、自动撤销已提交操作或改造无关领域 Job 的恢复策略。
- 重设计 Chat 工作区、补历史测试覆盖率或引入新测试体系。
