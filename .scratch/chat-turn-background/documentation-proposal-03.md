## 数据模型

对 `docs/KnowRealm-AI-数据模型-v3.1.md` 合并登记迁移 0042～0044 的实际实现，按现有文档升版规则统一命名。

- `chat_turns`：生成事实，含原请求、执行配置、取消、执行身份、尝试与正文版本、等待原因；0044 增 `compacted_seq >= 0`、`snapshot_json`。
- `chat_turn_events`：持久增量通知，正文和 revision 投影来源；终态压缩须先保存完整快照与 done 引用，再删除事件。
- `chat_turn_tool_effects`：0043 的逐项来源键及业务事务内结果回执，不因等待或换 attempt 改来源键。
- `chat_turn_runs`：0044 的 `(turn_id, run_id)` 主键、EXCLUSIVE／SHARED／INDEPENDENT 控制范围、取消请求；专属 run 部分唯一索引。共享引用会解除原轮次专属控制，明确批准或回答完成后独立控制。
- `chat_turn_waits`：0044 的稳定 `(turn_id, namespace, logical_call_id)` 唯一关系、RUN／JOB 类型及来源 ID、`source_operation_id`、原生 interrupt ID、冻结结构化结果。JOB 引用只能来自本会话已提交回执。

## 需求和扩展设计

在现有聊天与 Agent 执行章节增补以下契约，不增加产品入口或保留策略设置：

1. POST 受理轮次、GET 订阅持久事件、显式 cancel；切换或卸载仅关闭订阅，完全退出停止本地执行。
2. `wait_for_task` 只在回答需要消费真实结果时使用。普通提案、仅返回创建回执的回答可完成；Run 自身等待不机械阻塞 ChatTurn。
3. WAITING_JOB 释放 ChatTurn 槽但占用当前会话；周期和启动对账原来源任务，经 LangGraph `interrupt`／`Command(resume=...)` 自动接续，失败返回原任务状态及错误。
4. 停止在同一 SQLite 事务保存轮次和专属 Run 控制；共享、独立及已提交领域 Job 保持原生命周期。已完成回答的 Run 继续使用原 Run 控制入口。
5. 活动轮次的回执、来源键、等待和 checkpoint 受清理保护；终态压缩保留最终消息、版本和业务引用，旧游标收到权威快照 reset。
6. 续跑仍重验原模型、图版本、当前访问与授权、外发同意和期限；原时间语义及已注入材料保持。此次工具集合变更图版本 v1→v2，旧图在途轮次保守等待，不能假定跨版本可直接接续。

## 术语与 ADR

`GLOSSARY.md` 增补：**ChatTurn（回答生成轮次）**负责一次回答的受理、输出、等待和恢复；**AgentRun**负责多步业务执行；**ProcessingJob**负责调度。三者是独立生命周期，关联不表示授权或撤销已提交事实。

建议新增 `ADR-0027`（当前最大编号 0026，正式写入前再次核对）：回答生成的持久轮次、checkpoint 生命周期和后台等待。正文落四项决定：业务事实与 checkpoint 分工；业务提交和逐项回执原子性；原生 interrupt 接续与周期对账；控制归属和终态快照压缩。沿用 ADR-0026 授权机制，无新授权类别。
