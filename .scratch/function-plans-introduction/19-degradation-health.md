# 19 - 无 key 降级与健康面板

> Wave: B ｜ PRD: §4.1 服务与用量行 ｜ 决策引用: #38 #51

## 功能描述 / 目标

供应商 key 可缺省的可用性兜底：外部服务（LLM 端点 / 腾讯 ASR）缺 key 或异常时的功能级降级，加健康检查面板与 token 用量展示——"课录完了总结没了"是更坏体验，降级不熔断（#38）。

## 功能范围

**做**：
- 启动健康检查：各外部服务连通性与 key 配置状态
- 功能级降级：缺 key 时对应入口置灰 + 提示缺失项（不做月度 token 熔断，#38）：
  - 无 LLM key（DashScope 与自定义端点均未配）→ 总结 / 知识点 / 习题 / 复习资料 / chat 置灰提示
  - 无腾讯 ASR key / 离线 / 未同意外发 → 录音与导入照常受理；Record 保持 CONTENT_PROCESSING、ASR Job=PENDING 并展示等待原因，条件满足后自动继续
  - 全部 key 缺省（首启跳过配 key）→ 应用照常进入，捕获 / 录音 / 本地浏览可用
- 设置页"服务与用量"分区（#51）：
  - 健康检查面板（各服务状态与缺 key 提示）
  - 近 30 天 token 用量与调用次数（llm_call_logs 聚合、按 model 分组；不做计价展示）

**不做**：
- token 熔断 / 配额限制（#38 明确不做）、计价金额展示、服务自动重连恢复 UI

## 核心业务流程

应用启动 → 健康检查各外部服务 → 结果驱动入口可用性（置灰 / 正常）→ 设置页可随时查看面板与用量

## 关键业务规则

- **降级不崩功能**：与 key 无关的能力（录音 / 导入 / 本地浏览 / 本地转码）照常可用；可恢复等待不得写成 FAILED，也不消耗 attempts
- 降级提示指明缺失项与补救方向（"未配置 DashScope key，总结功能不可用"）
- 健康检查结果缓存（不因面板频繁探测外部服务）
- 用量数据仅来自 llm_call_logs 聚合，不新增统计表

## 前置依赖

- 04（ASR 降级对象）、06（LLM 降级对象）、12（chat 降级对象）

## 验收标准（出口线）

- [ ] 清空 LLM key 启动 → 总结 / chat 入口置灰 + 健康面板标红 + 明确提示；录音与列表照常
- [ ] 缺腾讯 key、离线或未同意时 ASR Job 保持 PENDING 且 attempts 不增加；补齐条件后无需重建 Record/Job 即自动继续
- [ ] 健康面板显示各服务状态
- [ ] 用量卡片显示近 30 天 token 用量与调用次数（按 model 分组）
