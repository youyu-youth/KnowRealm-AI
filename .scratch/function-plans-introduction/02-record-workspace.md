# 02 - 记录列表与详情

> Wave: A ｜ PRD: §4.3.4 / §9.1 / §6.5 ｜ UI 合同: `DESIGN.md` ｜ 决策引用: #7 #40 #41

## 功能描述 / 目标

在 01 已交付的工作台骨架和课程详情内容宿主内，实现 Record 的真实列表、状态展示、详情框架与软删除。02 不再拥有应用外壳，也不等待录音或导入管线；没有记录时展示真实空态，有持久化记录时通过 localhost API 展示真实数据。

## 功能范围

**做**：
- 课程详情 Records 内容：真实空态、时间倒序列表、状态文字/徽章
- 全局 Record 详情路由 `/records/$recordId`：Summary 为默认可进入页并显示真实未生成态；Transcript / 知识点 / 习题 / 复习 / Todo / Ask AI 保留最终信息架构标签但明确禁用，后续 plan 接入真实资产时启用
- 八态业务状态的用户可理解展示；FAILED 只显示通用失败说明和“暂无可用恢复操作”
- 软删除：确认弹窗明示不可恢复；Record 自身删除后所有查询立即不可见；Course 删除时在同一事务软删其下 Record；挂载对话不级联删除（#40）

**不做**：
- 左栏、顶部捕获栏、今日页、全局路由与主题外壳（均由 01 提供）
- Record 创建与任何捕获管线（03/04/05/11）、Transcript 或 AI 产物正文
- `processing_jobs`、轮询、SSE、失败来源和重试命令；由首个真实 worker 与对应来源管线落地
- 资产可用性聚合接口或对子资源端点的预探测；资产存在性由对应资产 plan 接管
- 文件/向量、Chat、Evidence 与业务行 30 天物理清理；由真实消费者扩展并统一验证完整 §6.5 删除链
- 收件箱视图（11）、已删恢复 UI（V1 无）或重复定义 `DESIGN.md` 视觉规则

## 实施顺序

1. **02-A 内容挂载**：复用 01 的路由出口与课程详情 Records 宿主，先接真实查询和空态，不修改应用外壳。
2. **02-B 列表与详情**：使用临时 SQLite 直接植入的持久化集成记录验证列表、八态与全局详情路由；生产页面不内置 mock、示例数据或种子入口。
3. **02-C 删除一致性**：完成 Record 软删除、Course → Record 同事务软删、查询与缓存失效；物理清理随首个真实 worker 激活。

## 核心业务流程

- 知识空间 → 课程详情 → Records → 真实空态或记录列表 → Record 详情
- Record 详情 → Summary 默认页显示真实未生成态；尚无真实资产的其余标签明确禁用
- 删除 → 确认 → 软删 → 列表与详情查询均不可见
- FAILED → 显示通用失败说明和“暂无可用恢复操作”；真实任务接入后再显示来源与重试

## 关键规则

- `record.status` 只表达 8 个业务态：NOTE / DRAFT / CONTENT_PROCESSING / SUMMARY_PENDING / SUMMARY_PROCESSING / SUMMARY_READY / COMPLETED / FAILED；技术任务态只在 `processing_jobs`（#7）
- 普通表查询遵循数据模型的软删规范：恒定过滤 Record 自身 `deleted_at`；直接详情还必须排除父 Course 已软删的 Record
- Course 软删与其 Record 软删在同一事务完成；`records.course_id` 的最终物理删除使用数据库外键级联承接，不能用物理级联代替软删
- 删除不级联挂载对话：会话保留可读并标记“原记录已删除”（#40，随 12 验证）
- Summary 默认页可以进入但不得伪造正文；其余未来标签在真实资产接入前保持明确禁用，不提前冻结资产可用性 API
- 页面复用 01 的连续工作面、间距、字体、主题和响应式能力；本 plan 只定义 Record 内容层
