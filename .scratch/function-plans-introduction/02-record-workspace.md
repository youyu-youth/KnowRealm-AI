# 02 - 记录列表与详情

> Wave: A ｜ PRD: §4.3.4 / §9.1 / §6.5 ｜ UI 合同: `DESIGN.md` ｜ 决策引用: #7 #28 #40 #41 #42 #54

## 功能描述 / 目标

在 01 已交付的工作台骨架和课程详情内容宿主内，实现 Record 的真实列表、状态展示、详情框架与软删除。02 不再拥有应用外壳，也不等待录音或导入管线；没有记录时展示真实空态，有持久化记录时通过 localhost API 展示真实数据。

## 功能范围

**做**：
- 课程详情 Records 内容：真实空态、时间倒序列表、状态文字/徽章
- Record 详情：Summary（默认）/ Transcript / 知识点 / 习题 / 复习 / Todo / Ask AI 的内容宿主；后续 plan 只挂载对应内容
- 八态业务状态的用户可理解展示；处理中状态先轮询，04 引入 SSE 后复用同一状态入口
- 软删除：确认弹窗明示不可恢复，删除后所有查询立即不可见；挂载对话不级联删除（#40）
- FAILED 状态显示失败来源和恢复入口槽位；只有对应 04/05/06 管线提供真实重试命令后才启用

**不做**：
- 左栏、顶部捕获栏、今日页、全局路由与主题外壳（均由 01 提供）
- Record 创建与任何捕获管线（03/04/05/11）、Transcript 或 AI 产物正文
- 在真实管线接入前伪造重试成功；文件/向量 30 天物理清理由首个 worker 管线落地并验证
- 收件箱视图（11）、已删恢复 UI（V1 无）或重复定义 `DESIGN.md` 视觉规则

## 实施顺序

1. **02-A 内容挂载**：复用 01 的路由出口与课程详情 Records 宿主，先接真实查询和空态，不修改应用外壳。
2. **02-B 列表与详情**：使用持久化集成数据验证列表、八态、详情 tab 可用性；生产页面不内置 mock/示例数据。
3. **02-C 删除与刷新**：完成软删除、轮询刷新和 FAILED 恢复槽位；真实重试与物理清理分别随来源管线和 worker 激活。

## 核心业务流程

- 知识空间 → 课程详情 → Records → 真实空态或记录列表 → Record 详情
- Record 详情 → 按业务态显示可用 tab；未产生的资产显示真实空态，不显示虚构内容
- 删除 → 确认 → 软删 → 列表与详情查询均不可见
- FAILED → 显示失败来源；存在真实重试命令时允许重试，否则明确说明尚不可恢复

## 关键规则

- `record.status` 只表达 8 个业务态：NOTE / DRAFT / CONTENT_PROCESSING / SUMMARY_PENDING / SUMMARY_PROCESSING / SUMMARY_READY / COMPLETED / FAILED；技术任务态只在 `processing_jobs`（#7）
- 每个查询恒定过滤 `deleted_at`（单用户库无 `user_id`，#28）；软删 30 天后异步物理清理（#41）
- 删除不级联挂载对话：会话保留可读并标记“原记录已删除”（#40，随 12 验证）
- 详情 tab 的可用性由真实业务状态和资产是否存在决定；禁用态不得看起来可点击
- 页面复用 01 的连续工作面、间距、字体、主题和响应式能力；本 plan 只定义 Record 内容层

## 前置依赖

- 01 已交付工作台骨架、课程详情和 Records 内容宿主
- 04/05/06 不是本 plan 的开工依赖；它们后续提供真实 Record 来源、重试命令和资产内容

## 验收标准（出口线）

- [ ] Records 路由挂载在既有骨架中，真实空态不含示例数据，且未重复实现导航/顶栏
- [ ] 通过 localhost API 读取的持久化集成记录可正确显示排序、时间与八态文字；该证据不冒充捕获链路已完成
- [ ] Record 详情 tab 按真实状态/资产存在性启用或禁用，空内容不伪造
- [ ] 删除确认后列表和详情均不可再查询；所有列表恒定排除软删记录
- [ ] FAILED 仅在真实重试命令存在时启用动作；无命令时不提供假按钮
- [ ] 完成后集中执行构建、最小 API 集成与 Records/详情关键路径验证
