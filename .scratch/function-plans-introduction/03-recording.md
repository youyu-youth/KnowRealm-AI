# 03 - 录音捕获

> Wave: A ｜ PRD: §4.3.1 ｜ 决策引用: #30 #31 #44 #49 #51 #58 ｜ **首张实现票：录音链路 POC**

## 功能描述 / 目标

负责录音发生期间的真实捕获与可恢复暂存：从按下录音到会话 finalize，维护 WebM 分片、录音会话与交接清单，然后把已封口的 staging 输入交给 04。合并、转码、正式文件注册与 ASR 不属于本 plan。

## 功能范围

**做**：
- 开始 / 暂停 / 继续 / 结束 + 实时时长显示；异常中断尽量保留已落盘数据
- 录音前最小对话框：标题可空 + 课程选择器（默认“不选 → 收件箱”，#30）；录音标题规则由本 plan 维护
- 录音入口挂载 01 已提供的顶部快速捕获栏；创建后的 Record 复用 02 的列表与详情
- WebView2 MediaRecorder 录制 `audio/webm;codecs=opus`，每 5~10 分钟分片落盘 `cache/staging/`
- `recording_sessions` 与有序分片清单持久化；崩溃后恢复或结束已有会话
- finalize 时封口分片清单，禁止继续追加或重排，并自动交给 04 处理
- Tauri 防系统休眠；启动时 `isTypeSupported` 探测，不支持时给出明确提示
- 开始前按预估体积校验至少 2× 可用磁盘空间；单次录音会话 ≤3 小时

**不做**：
- 合并 WebM、ffmpeg 转码、正式 `record_files` 注册、缓存清理、ASR 与 Transcript（04）
- 录音中标记 ⭐❓📝（P2 课堂标记）、macOS 适配

## 核心业务流程

录音对话框（可空标题 + 可选课程）→ 录制（有序 WebM 分片落盘 + 会话登记 + 防休眠）→ 暂停/继续 → 结束或恢复后 finalize → 封口 staging 清单 → 交棒 04；未选课不阻止后续转写。

## 关键业务规则

- 分片 5~10 分钟；单次会话 ≤3 小时
- `recording_sessions` 是捕获恢复事实源；分片落盘经 Tauri 壳文件能力，业务状态经 sidecar API 写入
- finalize 后清单不可追加或重排；03 不创建正式 AUDIO/RECORDED `record_file`
- WebM 是 staging 中间产物；仅在 04 已原子注册最终 Ogg 后清理
- 未选课录音照常交给 04 转写，完成后停 `SUMMARY_PENDING`

## 前置依赖

- 02（创建的 Record 在列表与详情可见）
- 04（接收已封口 staging 清单并完成后处理）
- 录音 POC 是本 plan 首张实现票，不是独立前置阶段；通过后才能继续生产实现

## 验收标准（出口线）

- [ ] 首张 POC 用真实麦克风验证开始/暂停/继续/结束、最小化/隐藏/锁屏、长录音分片连续性与强杀恢复，并回填 §11-Q6
- [ ] 录 10 分钟后产生有序 staging 分片；finalize 封口清单并成功交给 04，03 未合并、未注册正式文件
- [ ] finalize 后无法追加或重排分片；重复交接不会生成第二份录音输入
- [ ] 强杀进程后重启，已落盘分片可恢复并继续 finalize
- [ ] 03 出口只证明捕获与交接；最终 Ogg、缓存清理、ASR 与 Transcript 由 04 验收
