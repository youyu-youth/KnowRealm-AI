# 07 — 多资料建课编排

**What to build:** 目标场景跑通："把这五篇论文整理到新的课程中，并生成学习计划。"Agent 给出一张计划卡（来源清单四类＋建课参数＋计划生成意图），一次批准绑定整个 Run 后自动执行：逐份导入解析（提交现有后台 job，WAITING_JOB 接续）→ 建课（课程 id 结果绑定注入后续步骤）→ 资料挂课（改归属或建共享引用）→ 最后一步产出计划草案卡（确认是 Run 之外的人工闸门）。部分资料失败不回滚已完成部分，失败步骤可单独重试。

**Blocked by:** 02 — 计划数据与生成确认链路；05 — 共享来源引用；06 — Run 等待与结果绑定

**Status:** ready-for-agent

- [ ] 多资料建课计划卡：固定来源清单（库内资料 / 本地文档 / URL / 粘贴文本四类，全部走现有导入管线）＋建课参数＋计划生成意图；一次批准绑定（计划版本、固定对象集合；执行中重规划新增目标升回确认，完全访问档亦然）
- [ ] 步骤编排：逐份导入解析（每份提交现有 job、Run 进 WAITING_JOB 自动接续）→ 建课 → 资料挂课（改归属或建共享引用，两种路径）→ 计划草案产出（Run 末步产草案卡，草案确认不算 Run 步骤）
- [ ] 授权与审计：每步落 Operation 审计；总结与学习资产原有采纳审核不被批次授权跳过（测试断言）
- [ ] 部分成功：单项失败不回滚已完成步骤与已建课程，Run 标记部分成功，失败步骤可单独重试
- [ ] 等待与执行状态在聊天卡可见（等待资料解析 / 进行中 / 部分成功 / 完成）
- [ ] 大 PDF 仍按整本一条记录处理（按章拆分属书籍拆章波次，不引入临时解析路径）
- [ ] 测试：编排全链（含结果绑定链）、部分成功与单独重试、重规划升回确认、计划卡授权语义
- [ ] 门禁全绿：pytest（独立 basetemp）+ ruff + pyright + OpenAPI --check + 前端测试（计划卡 / 等待状态呈现）
