# 通用 Agent 第三阶段：知识空间学习计划与多资料执行闭环（spec）

Status: ready-for-agent
定稿依据：开发计划文档 §五（工单 09~12）+ 设计-4 采纳版 + ADR-0026 + 2026-09-29 grill 三轮 Q1~Q14 全部用户确认（首轮 Q1~Q3 交叉讨论定案，Q4~Q14 全按推荐定案）。

## Problem Statement

学习计划是产品规划最久、落地为零的空白层：知识空间（Course）没有学习目标、期限与时间预算字段，目标只能留在聊天里；Todo 强绑 Record、无排期与目标归属，今日页只能聚合记录级待办——用户始终没有可持续使用的"我今天学什么"。同时，用户让 Agent"把五篇论文整理到新课程并生成学习计划"这类多资料长任务跑不通：Run 的依赖只表达先后成功、不能把前一步建课结果绑定为后续参数；WAITING_JOB 只是预留状态，资料解析 job 完成后无法自动接续。同一资料被多个知识空间复用时，现有单归属模型（LibraryItem 单 course_id）只能迁移归属（会搬走资料）或重复入库。

## Solution

按"知识空间目标 → 学习计划 → 执行与调整"为产品主线交付，多资料处理是其中一条生成路径。分两个里程碑、同一份 spec：

1. **里程碑一（领域层，对应工单 09 方向）**：学习目标与学习计划成为真实业务数据——目标（类型/标题/期限/每日投入）挂单个知识空间，单空间同时最多一个进行中目标；AI 生成可编辑计划草案、用户确认后生效；计划项按日排期、手动勾选完成、用户可就地编辑或要求重生成（新版本、锁定项保留）；今日页双源合并展示今日待学；共享来源引用让资料保归属被多空间复用（检索覆盖、资产只读）。**不依赖 WAITING_JOB，交付即可真机使用**。
2. **里程碑二（执行闭环，对应工单 10~12 方向）**：激活 WAITING_JOB（资料解析 job 完成后 Run 自动接续）、步骤结果绑定（前一步建课结果可作后续步骤参数）、多资料建课 Run 一次批准绑定整个计划、启动对账恢复、取消与部分成功语义；故障注入与端到端验收。

Agent 通过类型化工具完成目标制定、计划生成/确认/调整/完成、引用管理与今日查询全流程，与页面共用领域 Service；执行沿用三档授权与 Operation 审计。

## User Stories

**目标制定**

1. 作为学习者，我想为知识空间设定学习目标（标题、类型、期限、每日投入），以便学习有明确方向与约束，而不只停留在聊天里。
2. 作为学习者，我想通过对话制定目标：Agent 追问缺失的期限或投入、无知识空间时先与我确认建新空间，以便不必手动填表。
3. 作为学习者，我想在同一空间换新目标时被提示先完成或归档旧目标，以便空间始终只有一个进行中目标、排期不互相打架。
4. 作为学习者，我的不同空间可以各有进行中目标，以便并行推进多个学习主题。
5. 作为学习者，我想编辑目标（改期限、每日投入）并标记完成或归档，以便目标随实际演进。
6. 作为学习者，目标范围由 AI 推断产生时，我想被明确要求确认后才生效，以便目标范围始终经我确认。

**计划生成与确认**

7. 作为学习者，我想基于库内多份资料请求生成学习计划，以便计划贴着我的真实资料。
8. 作为学习者，我想以纯目标为起点请求学习计划，获得建议学习内容与资料缺口清单，以便知道先补什么资料。
9. 作为学习者，我想在确认卡上编辑 AI 生成的计划草案（改日期、时长、删项、排序），确认后才落库生效。
10. 作为学习者，我想看到每个计划项的生成理由，以便判断安排是否合理。
11. 作为学习者，草案未确认就关闭，不会留下任何半成品计划数据。

**计划执行与调整**

12. 作为学习者，我想在知识空间详情页计划 Tab 看到目标卡（进度、期限、每日投入）与按阶段分组的计划项列表，以便掌握整体安排。
13. 作为学习者，我想逐项勾选完成或跳过计划项，以便记录执行进度。
14. 作为学习者，我想就地编辑单个计划项（改日期、时长、内容），改动立即生效并有操作审计。
15. 作为学习者，我想在目标或偏好变化时要求重新生成计划：新版本生效、旧版本只读保留，我手动锁定过的项原样保留不被 AI 重排。
16. 作为学习者，我想查看历史计划版本，以便追溯之前的安排与进度。
17. 作为学习者，完成计划项不会直接提高概念掌握度——掌握度仍只由测验、总结确认等真实学习证据驱动，我不想看到"点完成＝学会了"的自证失真。

**今日待学**

18. 作为学习者，我想在今日页看到跨空间的今日待学（学习计划项＋记录 Todo 双源合并、分组标注来源），以便每天有明确的执行清单。
19. 作为学习者，我想在今日页直接勾选完成计划项，状态与计划 Tab 一致。

**共享来源引用**

20. 作为学习者，我想把已属于"机器学习"空间的论文引用到"Agent 工程"空间用于学习，原归属不变、不重复入库。
21. 作为学习者，被引用资料的内容进入新空间的课程问答与检索（引用行标注共享来源），以便新空间的 AI 问答能覆盖这份资料。
22. 作为学习者，引用不带来资产生产：新空间不能对引用资料生成总结、知识点或习题，资产仍只在原空间——同内容不重复建资产、不污染掌握度。
23. 作为学习者，被引用资料软删时我看到"来源已删除"提示；30 天回收站内恢复则引用自动恢复；永久删除后引用被清理。
24. 作为学习者，原资料迁移归属不影响我的引用，引用是两个空间的直接关系。
25. 作为学习者，我想增删共享引用（页面或对话均可），删除引用不动原资料。

**Agent 接入**

26. 作为学习者，我想问 Agent"我今天学什么"并获得当日待学清单。
27. 作为学习者，我想让 Agent 代我完成计划项，动作经确认与授权、留有回执。
28. 作为学习者，Agent 对目标、计划、引用的写动作沿用三档授权与确认卡规则，审计链完整。

**多资料长任务（里程碑二）**

29. 作为学习者，我想说"把这五篇论文整理到新课程并生成学习计划"，一张计划卡一次批准后自动执行：逐份导入解析、建课、关联、产出计划草案卡。
30. 作为学习者，等待资料解析时任务显示明确的等待状态，后台完成后自动接续，不需要我逐步确认。
31. 作为学习者，我想随时取消进行中的长任务：未提交步骤停止、已提交 job 有回执、已建课程保留由我处置。
32. 作为学习者，应用重启后未完成的长任务自动对账恢复继续，已完成步骤不重做。
33. 作为学习者，部分资料失败时：已成功部分保留、课程不重建、失败步骤可单独重试、最终如实呈现部分成功。
34. 作为学习者，多资料来源四类（库内资料、本地文档、URL、粘贴文本）都走现有导入通道，长任务不建新的解析路径。

## Implementation Decisions

**里程碑拆分**

- M1＝学习计划领域层（目标、计划、引用、计划 Tab、今日页、Agent 工具族），可独立验收与真机使用，不依赖 WAITING_JOB 与步骤结果绑定；M2＝多资料执行闭环（WAITING_JOB 激活、结果绑定、多资料 Run、故障恢复与端到端验收）。同一份 spec 覆盖两里程碑，工单在 to-tickets 阶段按功能闭环拆分、不拆前后端票。

**领域模型与迁移**

- 落地四表，对数据模型 v3.1 P6 原设计有一处显式修正：`learning_goals` 新增 course_id 必填外键（原设计为全局 learner 视角无归属）。目标必须挂知识空间；目标先于资料但不先于空间——对话中无空间时先建空间再定目标；跨空间目标总览由今日页查询聚合，不建全局 goal 表。课程软删后目标与计划随空间不可用（查询期过滤），恢复课程即恢复，与 Record 同模式。
- `learning_goals`：goal_type、title、target_date、daily_minutes、target_score（可选）、scope_source（USER_CONFIRMED / COURSE_SELECTION / AI_INFERRED；AI_INFERRED 必须用户确认）、scope_confirmed、status（ACTIVE / COMPLETED / ARCHIVED）。**单空间单 ACTIVE**：同一 course 下 status=ACTIVE 至多一条，用部分唯一索引实施（工单内核实 SQLite 部分索引支持）；跨空间不受限。
- `learning_plans`：(goal_id, plan_version) 唯一；status（ACTIVE / SUPERSEDED / COMPLETED）、effective_from / effective_to。同一目标同时至多一个 ACTIVE 版本。
- `learning_plan_items`：plan_id、action_type 收敛为四类——STUDY_RECORD（学一条记录/资料，含课前预习语义，指向 record）、PRACTICE_QUIZ（做习题）、REVIEW_CONCEPT（复习概念，用 concept_id）、CUSTOM（自由任务）；concept_id 可空、目标对象（record 等）关联方式工单定；priority、estimated_minutes、scheduled_date（按日，无时段）、status、user_locked（用户锁定项，重生成时原样保留不被 AI 重排）、reason_json（生成理由）。user_locked 默认 false；用户手动编辑过的项由 Service 置 true。
- 共享引用新表（course ↔ library_item 多对多）：course_id、library_item_id、创建时间，(course_id, library_item_id) 唯一；失效为查询期派生（条目软删即失效、恢复即复活），不设失效状态字段；条目物理删除时引用级联清理。
- **不落三表（deferred 登记）**：learning_agent_actions、learning_agent_feedback（自适应推荐层，本期砍掉）、teach_back_attempts（P5，排在书籍拆章之后）。数据模型升版提案随工单提出、经用户批准后动文档：0030~0033 补登＋本期新表登记＋learning_goals 修正＋deferred 表标注启用条件。

**生成、确认与版本语义**

- 计划生成＝LLM 结构化草案（阶段划分、计划项、时长估算、逐项理由）；日期铺排与预算一致性（不超期限、每日总量与 daily_minutes 相容）由确定性校验与修正承担，符合"脚本优先、LLM 次之"。
- 草案不持久化：确认卡关闭即弃，learning_plans 只在用户确认时写入；重新生成即可恢复。
- 确认流：Agent 生成草案 → 确认卡（可编辑：改日期/时长、删项、排序）→ 确认落库 ACTIVE。与"AI 总结人工确认"同一产品原则。多资料 Run 的最后一步只产出草案卡，草案确认是 Run 之外的人工闸门、不算 Run 步骤。
- 调整两路径：手动编辑单个计划项＝就地改当前版本＋Operation 审计；重新生成（目标变更或用户要求重排）＝新 plan_version、旧版 SUPERSEDED 只读保留、user_locked 项原样带入。
- 完成语义：手动勾选为主（完成/跳过）；完成不产 learning_event、不直接动 Concept Mastery；学习时长统计由 plan_item 完成时间戳单独承载，不进学习证据链。今日页可展示自然证据（如关联习题已做）仅作提示。

**共享引用语义**

- 引用作用范围＝检索覆盖＋资产只读：被引用资料的 Record 内容进入新空间 COURSE 范围问答与检索（引用行标注共享来源）；总结、知识点、习题等资产仍只能产在原空间，新空间对引用资料只读消费；引用不授予改、删、迁移原资料的权限。
- LibraryItem 归属与引用解耦：归属迁移不影响引用；软删/恢复/永久删除按上文失效规则。

**Agent 工具面（能力入口）**

- 目标域：list_goals、get_goal（只读）；create_goal、update_goal（写，确认卡）。
- 计划域：get_plan（只读）；generate_learning_plan（草案，只读不落库）；confirm_plan（草案卡即确认闸门）；update_plan_item、complete_plan_item（写，确认卡）；regenerate_plan（写，确认卡、产新版本）。
- 引用域：list_shared_refs（只读）；add_shared_ref、remove_shared_ref（写，确认卡）。
- 今日：只读查询（Agent 可答"我今天学什么"）。
- 命名与合并粒度工单定；M2 多资料编排复用现有 Run 计划卡机制新增步骤类型，不另起工具体系。工具为领域 Service 薄包装，与页面共用 Service。写动作沿用三档授权与 Operation 审计（ADR-0026）。

**M2 执行闭环**

- WAITING_JOB 激活：Run 步骤提交后台 job 后 Run 进 WAITING_JOB；job 完成主动触发 Run 推进，另设启动对账兜底（扫描 WAITING_JOB 的 Run、核对其等待 job 的终态决定续/败/部分成功；与现有掌握度 consumer 自愈同模式）。
- 步骤结果绑定：Run 计划契约扩展，前一步骤输出（如新建课程 id）以字段路径引用注入后续步骤参数；依赖仍只表达先后与成功。
- 授权：一次批准绑定整个多资料 Run（固定来源清单＋建课参数＋计划生成意图，沿用二阶段批量计划卡先例：计划版本、固定对象集合、执行中重规划升回确认）；每步落 Operation 审计；总结与学习资产原有采纳审核不被批次授权跳过。
- 取消：未提交步骤停止、已提交 job 保留回执、已建课程保留不自动回滚删除（交用户处置）。
- 部分成功：单项失败不回滚已完成步骤与已建课程，Run 标记部分成功，失败步骤可单独重试。
- 运行边界：应用隐藏且 sidecar 运行时可继续；应用完全退出后保存进度、下次启动恢复，不承诺退出期间继续执行。
- 来源四类（库内资料、本地文档、URL、粘贴文本）全部走现有捕获与导入管线；大 PDF 仍按整本一条记录处理（按章拆分属书籍拆章波次，非本期）。

**prompt 与评测**

- chat prompt 版本 bump；计划生成建立黄金集与评分脚本，沿用研究会话模式（评测文档两份 md、脱敏占位符、用户采集→agent 整理→用户标注、回归触发＝prompt 版本或模型变更）。

## Testing Decisions

- 好测试只测外部行为：Service 公共方法语义、API 契约、Agent 工具可见行为、Run 状态机外部观察；不测内部实现细节。
- **M1 seams**（优先复用现有缝，最高层优先）：领域 Service 层（goal / plan / 引用）单测＋FastAPI 路由集成测（TestClient）——沿用 course-brain、mastery、todo 测试先例；Agent 工具按函数级测（工具是 Service 薄包装，直接断言确认卡与 Service 调用语义）；前端以 MSW mock 新端点测 hooks 与计划 Tab、今日页双源组件——沿用 courseBrain hooks 与 TodaySummaryTodos 先例。
- **M2 seams**：Run 推进器与对账器为可注入缝（job 终态与时间可注入）；故障注入＝伪造 job 终态、重启重放（沿用现有 Run 恢复与批量计划卡测试先例）；端到端验收票覆盖故障注入、真实模型任务、Tauri 重启、部分资料继续执行。
- 纯函数黄金样本手算先例（mastery）适用于排期确定性修正逻辑。
- 真机验收项在工单内单列"用户真机验收"清单，不代勾。

## Out of Scope

- 持续自适应重排与主动调整（依据进度、逾期、测验与掌握度变化自动重排计划）——明确的下一层能力。
- 目标驱动的自动联网搜集、筛选、入库资料。
- 到期提醒与系统通知（学习项仅今日页呈现）。
- 计划模板、周期性重复计划、计划导出、时段级排期（上午/下午）。
- learning_agent_actions、learning_agent_feedback、teach_back_attempts 三表落地。
- 完成计划项产 learning_event 或提升 Concept Mastery。
- 书籍按章拆分（大 PDF 整本一条记录进入多资料流程）、轻量 Teach-back、课程大纲初始化、内置 Skills、MCP client——排序与启用条件见开发计划 §六及 09-29 合并终版。
- Research SubAgent：仅当多资料证据规模顶到上下文预算时按设计-4 §9 评审提前，非本期必备条件。

## Further Notes

- 交付节奏：M1 完结即可真机验收并投入日常使用；M2 建立在 M1 领域层之上，两者同属第三阶段交付。
- 工单拆分纪律：闭环功能不拆前后端票，票内 checklist 含各域条目、commit 按 type(scope) 分次（AGENTS.md 规范）。
- 搭车项：数据模型升版提案（0030~0033 补登＋新表登记＋修正＋deferred 标注，先提案经批准再动文档）；prompt_version bump 与计划生成黄金集；真机验收积压分批清偿不在本 spec 内展开。
- 既有红线沿用：跨域整理不绕开 API 既定校验；"完全访问"不扩大已固定计划的目标集合，不暴露物理删除、SQL、任意路径写或宿主 Shell；页面上下文与模型判断不构成授权。
