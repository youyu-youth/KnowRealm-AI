# 01: 实现独立明暗主题系统与恢复验收

**What to build:** 用户可以在现有外观设置中分别选择明亮与暗黑主题；当前模式立即应用，另一模式只保存。手动切换、跟随系统及重启时恢复目标模式的选择，切换过程中保留正在进行的工作和组件状态。

本期完整交付四套内置主题、两组预览与独立选择、持久化及失败恢复、启动恢复、全应用配色与验收。现有明亮和暗黑样式各为默认主题，新增主题分别为柔和青灰与克制墨蓝。

**Blocked by:** None（无前置工单；权威文档提案与批准在本票内处理，见实施约束）。

**Status:** needs-info（存储与契约已实施；等待权威文档具体提案批准）

**规格:** [Desktop 独立明暗主题系统](../spec.md)

## Acceptance criteria

- [ ] T01：旧配置没有独立主题字段时，明亮、暗黑分别使用默认主题；原模式及其他偏好不变，读取默认值不写文件，无需数据库迁移。
- [ ] T02：两套主题目录、ID 归属与选择记录独立；各组主题选择可保存并重新读回，更新一组不覆盖另一组；默认主题选择仍沿用缺键即默认的存储惯例。
- [ ] T03：保留 LIGHT / DARK / SYSTEM 的现有模式含义；模式切换不改写两组已保存的主题，也不将 SYSTEM 建成第三套主题目录。
- [ ] T04：偏好写入口拒绝空值、非法主题与错误模式归属，不将错误选择写入配置；扩展后的 OpenAPI 与生成的前端 API 类型保持一致。
- [ ] T05：读取单组损坏、已失效或归属错误的主题时，只回退该组默认主题，保留另一组、未知配置键和其他偏好。
- [ ] T06：设置页同时展示明亮、暗黑两组主题名称、固定配色预览和独立选中状态；两组预览不受当前应用主题污染，保留现有字号及其他偏好入口。
- [ ] T07：控件级即改即存；当前组选择无需重启或额外保存即可应用，非当前组选择只保存；双向切换恢复对应主题，本地视觉更新在 120ms 内一次性完成。
- [ ] T08：SYSTEM 下实际系统明暗变化自动应用目标模式保存的主题；手动明亮或暗黑模式不受系统变化影响；监听生命周期清理正确。
- [ ] T09：保存失败有可见且可重试的反馈；取消候选态并读回权威偏好，处理请求失败但可能已写入的情况；无法对账时保留最后确认值，不将候选值记作成功缓存。
- [ ] T10：连续及并行保存两组主题、模式和现有偏好不会丢更新；迟到响应不覆盖最新确认值；UI 防止冲突提交，必要修复限于现有共享写入边界。
- [ ] T11：缓存覆盖模式和两组选择，并按当前数据目录隔离；工作区首次可见前核对权威外观；有效、缺失、损坏、失效或错目录缓存均可正确恢复，缓存存储不可用不阻断启动，读取失败按规格降级并反馈。
- [ ] T12：同模式内换主题及跨模式切换时，应用壳、页面专用色值、图表、菜单与浮层一起更新；表单输入、焦点、弹窗、选中项和滚动位置保持，聊天生成、录音及任务订阅不被取消或重启。
- [ ] T13：默认主题与改动前真实界面一致，保留已有页面局部变量；青灰与墨蓝主题覆盖完整视觉语义与层次，只改变颜色、背景层次、边框和允许部位的阴影，不改布局、字体、字号、圆角及交互逻辑。
- [ ] T14：四套主题下 hover / active / focus / disabled / loading / error 状态清晰；主题选择支持键盘与明确的选中语义，不只用颜色区分；主题切换尊重减少动效设置。
- [ ] T15：新增主题名称、状态及错误文案同步中文与英文；现有 i18n 一致性防线通过，辅助技术可以区分两组主题及各组选中项。
- [ ] T16：全量导出、导入与数据目录迁移后可恢复模式及两组主题；现有重启或偏好重载路径同步校正缓存，不被旧目录缓存覆盖；不扩展每日数据库滚动备份范围。

## 实施约束

- 优先复用现有偏好 API、部分更新、原子文件替换、设置行和 shadcn / Base UI 单选组件；主题解析及应用集中在已有外观同步路径，不新增整页保存按钮或通用配置框架。
- 主题登记与样式定义提供明确扩展入口；开发者可只为一种模式新增主题，无需配对另一模式，也不需要逐页面添加主题分支。新语义变量在各模式默认主题定义，并允许该模式其他主题覆盖。
- 两种模式共享组件与语义变量契约，不共享主题方案；非默认主题只能继承所属模式的默认视觉基线。保持现有明暗选择器兼容性和浏览器 color-scheme 正确。
- 主题通过根元素状态与样式变量应用，不使用主题 ID 重挂载 React 组件，不刷新页面。核对计算样式消费方，不能仅凭根元素 class 更新认定图表已换色。
- Desktop 前端负责应用外观，后端仅复用偏好存储及校验；不新增重复的 Rust 原生主题命令、LLM 调用、数据库表、依赖或后台任务。
- 本期不接入 Agent。规格中的原因与范围必须保留；不新增外观 Tool，不以工具直写本地文件绕过现有授权与操作回执。
- 进入新增配色实现前提交设计规范与领域术语的具体修改提案，批准后再写权威文档；固定色值检查限于默认主题，新增主题遵守共同的语义、层次和交互约束。提案批准不是本次工单发布所隐含的授权。
- 只修复本次主题切换暴露的样式或写入问题，保留其他会话改动，不扩大到全仓样式重写或无关偏好重构。

## 真实 Tauri / WebView2 验收

以下各项需记录实际证据；自动化门禁或浏览器模拟通过不能代勾。

- [ ] 四套主题逐一检查应用壳、今日、知识空间、资料库、聊天、设置，以及 Dialog、菜单、Tooltip、Toast 和至少一种图表；与默认主题改动前基线对照，确认页面专用颜色及图表没有残留旧值。
- [ ] 两组主题同时显示正确；在另一模式中配置主题不改变当前工作区，随后切换模式可以恢复选择；返回默认主题可正常恢复原样式。
- [ ] 使用真实系统外观切换验证 SYSTEM 跟随及主题恢复，再验证两种手动模式不被系统变化覆盖。
- [ ] 记录冷启动与重启实际帧：覆盖手动明亮、手动暗黑、SYSTEM、非默认主题、有效缓存、无缓存但已有非默认偏好、损坏或错目录缓存；工作区首次显示没有错误主题闪帧。
- [ ] 在聊天持续输出、活动录音、未提交表单、浮层打开和页面滚动时换主题，确认业务不中断，输入、焦点、选中与滚动状态不重置。
- [ ] 四套主题下验证控件各状态、键盘操作、对比度、三档字号、窄窗和减少动效；不存在截断、遮挡或横向溢出。
- [ ] 验证 200% 缩放，并明确区分 WebView2 内缩放、浏览器视口模拟与真实 Windows 系统缩放；记录 CSS viewport、DPR、系统缩放、字号和主题，未实测部分明确保留待验收。
- [ ] 用独立测试数据确认全量导出、导入及数据目录迁移后的主题恢复与缓存校正；保持真实数据安全，不把数据库滚动备份描述为已覆盖主题配置。
