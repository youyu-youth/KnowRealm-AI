# 03 — 重新生成与转写换代边界

**What to build:** 已确认知识点的记录可以基于当前已确认 Summary 重新生成新候选：审阅期间旧知识点保持可用，确认新批次后旧 AI 批次才过时、手工行永久保留。用户编辑转写导致总结换代时，已保存知识点保持可见可编辑、在途候选的确认被阻止并引导丢弃重生成、新总结确认后重新生成入口自动恢复。本票把「转写编辑路径 × 知识点确认守卫」两条功能线的联动补完并全链路验证。

**Blocked by:** 02 — 候选审阅、手工补充与批次确认

**Status:** completed

- [x] 重新生成复用同一生成管线与前置校验（在途 DRAFT 409 仍生效）；新候选审阅期间旧 ACTIVE 批次保持可用可编辑
- [x] 确认新批次后旧 AI 批次置 SUPERSEDED、手工行与用户编辑行保留、KNOWLEDGE_CONFIRMED 事件仅对应新批次
- [x] 转写编辑换代（保存转写 → Summary 置 SUPERSEDED → Record 回 SUMMARY_PENDING）后：已保存知识点不删除、不改状态，知识点页签保持可见可编辑；「重新生成」入口锁定并说明原因（读端点补齐换代场景的 blocked_reason=SUMMARY_SUPERSEDED）
- [x] 换代后在途 DRAFT 批次的确认被 409 阻止，UI 给出「丢弃后基于新总结重新生成」引导；丢弃动作本身不受阻止
- [x] 新 Summary 确认（Record 回 COMPLETED）后重新生成入口恢复，可基于新总结生成候选并确认
- [x] 后端联动测试覆盖全链路：转写编辑 → 确认阻止 → 丢弃 → 新总结确认 → 重新生成 → 新批确认 → 旧批 SUPERSEDED 且手工行保留；桌面 MSW 测试覆盖锁定/阻止/解锁各状态的界面文案
