## 1. 新增 ADR-0027

已新增 `docs/adr/0027-batch-plan-compilation-and-extension.md`，编号核对无冲突，全文如下：

```markdown
# 批量执行计划采用类型化编译与固定版本延展

Status: accepted（2026-10-12，设计决策已确认；尚未实现）

批量自动提交与计划卡确认重复掌握参数解析、快照对齐、已有步骤分类和依赖序号映射，动作字段并集还让新增动作需要同步多份声明。决定将这些规则收敛到 Agent 的计划 module，直到形成可执行的 Run/Operation 事实；入口保留授权和生命周期接线，Worker 保留推进、等待、取消与恢复。

计划项按动作携带类型化参数，复用现有动作 schema。批量能力显式启用、默认关闭，仅保留当前动作面及 course_id/goal_id 字符串输出引用；新输入拒绝动作无关字段和显式 null。引用的结构与可确定校验在提交时完成，真实值绑定后再次完整校验，不把未校验的载荷视为完整业务输入。

沿用 ADR-0026 的固定集合授权：活跃 Run 新增目标或修改参数均重新确认，包括 AUTO_APPROVE。延展批准绑定确定的 Run 与基础计划版本，提交事务内按版本与任务状态条件写；过期卡不自动合并，任务已结束或取消不另建 Run。新建任务卡明确新建，不按会话当前活跃 Run 隐式合并。

本期延展支持追加与参数修订：相同项复用，待执行项参数修改保留执行身份，成功项参数修改经确认追加新操作且保留历史；删除、重排及修改既有依赖明确不支持。创建步骤只依赖逻辑调用身份保证恢复幂等，不以同名或相似内容推断同一次创建。

计划 module 接收入口事务，内部不自行提交。Run、Operation、计划版本与相关触发、绑定、批准或效果回执原子提交；保留既有独立失败记账和逐步执行最终门禁。旧在途任务继续恢复、旧回执可查；旧待确认卡只能重新预览生成新格式卡，再由用户确认，不批量改写历史。页面与 Agent 复用确定性重新预览入口，任务归属不明时先消歧，原参数不静默改变。

取舍：采用严格任务/版本绑定，放弃旧卡自动合并与 AUTO_APPROVE 运行中自动追加；保留历史兼容读取，放弃把新授权信息补到旧待确认卡后直接执行。此决策收束架构评审候选③，不增加运行时编排器，不改变课程学习计划领域规则。
```

## 2. 更新 GLOSSARY.md

只在现有 Run 与计划卡词条附近插入两条领域定义，并替换计划卡定义；保留其余现有内容。

新增：

```markdown
**批量执行计划（Batch Execution Plan）**:
为一次批量任务确定的动作、目标、参数、依赖与计划版本，是批准范围及逐步执行的依据。
_Avoid_: 学习计划（安排学习活动的领域对象）、计划卡（审批载体）、Run（执行事实）

**计划延展（Plan Extension）**:
在确定的批量任务上追加步骤或修订待执行步骤参数的计划变更，保留已执行历史，并经新的批次批准生效。
_Avoid_: 新建任务、整份计划替换、失败操作重试
```

计划卡定义替换为：

```markdown
批次授权的载体——逐项列明目标、参数、依赖与计划版本；新建卡明确新建任务，延展卡绑定确定任务及基础计划版本，整卡确认批准对应范围。运行中新目标或参数变更在任何档位均需重新确认；任务或基础版本失效后须重新预览。
```
