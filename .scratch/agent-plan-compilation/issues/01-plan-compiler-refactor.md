# 01: 收拢批量计划编译与延展的内部编排

**What to build:** 自动提交与计划卡确认使用同一计划 implementation 完成既有解析、引用延期、快照、步骤分类、序号映射和可执行事实写入。调用方不再配对多份中间序列，用户继续使用原工具、计划卡、执行与恢复流程。

**Blocked by:** None (can start immediately)

**Status:** done（内部重构、相关自动化与两轴审查完成；全量结果及真实模型/Tauri 边界见实施记录）

**Scope:** 2026-10-12 用户决定优先原报告的架构优化；本期只有这张内部重构票，源码已提交 `1f3f70b`；完整协议/审批升级仍在后续阶段。

**Source:** [当前规格](../spec.md)、[当前阶段决策](../grill.md)。后续协议/审批升级不在本票范围。

## Acceptance criteria

- [x] 自动提交与计划卡确认不再各自拆装子批载荷、快照、解析、索引、覆盖/替换映射；这些规则在计划 module 内维护，六元组仅改名或包一层透传不算完成。
- [x] 动作解析与参数校验复用现有 OperationSpec/schema/adapter；允许清理同值映射等重复维护点，保持九动作面与现有外部字段并集，不新增通用 schema/插件框架。
- [x] Tool 参数、提案/快照/Run JSON、结果形状、Prompt、SSE与前端消费契约保持；旧待确认卡、旧在途任务和历史回执按当前路径可用，不新增格式迁移或重新预览要求。
- [x] 普通字段、null/省略/无关字段投影、输出引用接受范围及延期/最终校验保持；内部部分载荷构造不扩大适用范围，不通过重构静默收紧或放宽参数规则。
- [x] 相同项复用、待执行参数修订保留身份/位置、成功后变更追加、失败/跳过及创建类处理均保持；混合分类后依赖与输出引用仍映射到正确 Operation/Run编号。
- [x] 保留既有对象快照策略与提交/执行前重验，包括含引用的已有目标；未创建目标不伪造快照，损坏计划写路径仍拒绝而非覆盖为空计划。
- [x] 当前三档、累计阈值、目标选择、版本递增与旧卡确认行为保真；AUTO_APPROVE 自动延展及旧卡合并差异独立登记，不宣称已修复，不借票改变批准规则。
- [x] 主事务仍由入口拥有，共享 implementation 不自行提交；Run/Operation/投影/触发/绑定/成功回执原子性与入口不同控制语义保持。
- [x] 持久取消/执行身份、Worker最终授权/快照校验、独立失败记账及并发保护保持，不合并掉入口真实事务差异。
- [x] Effect成功重放先于新准入判定，原预算计数与提交上限保持；恢复不重复建Run/Operation、扣提交预算或投触发Job。
- [x] WAITING_JOB/WAITING_USER、部分失败、重试、启动对账保持；真实 SQLite/Worker恢复不重做成功项，不清原身份、尝试历史和等待关系。
- [x] 相关现有批量、引用等待、多资料、轮次恢复测试通过；原行为断言保留。类型/规范/OpenAPI与现有计划卡消费验证通过，不为内部新类型补镜像测试。
- [x] 验收同时给出两条入口删除重复编排的代码证据及持久行为证据；自动化、模型/网络替身、真实 SQLite/Worker与未执行的模型/Tauri范围分开记录。

## 验收边界

通过原公开提交和确认入口验收新建/延展混合步骤、快照、等待、失败与恢复。没有 UI/外部协议行为变化时，只验证现有消费方兼容，不新增页面流程或强制全套新功能真机门禁。

发现与本次无关的现有授权/版本/参数语义问题时登记，不静默修复。第一阶段完成仅表示内部编排收敛，不代表 ADR-0027 完整升级实现或 ADR-0026 差异已经闭合。

## Out of scope

对外类型化协议、严格基础版本批准、新旧卡失效/重新预览、预览去重、授权修正、新动作、任意绑定、通用DAG、数据迁移、UI重设计和历史测试债务。

## 实施与验收

实现及相关门禁已完成，代码、持久行为和验收边界见 [implementation.md](../implementation.md)。当前代码提交 `1f3f70b`，最终相关 136 项后端测试及 29 项前端消费测试通过；全量结果在实施记录中独立登记。未执行真实模型、外部网络及 Tauri/WebView2。既有 AUTO_APPROVE、旧卡合并及原编号策略保留，不宣称完整 ADR-0027 已实现。
