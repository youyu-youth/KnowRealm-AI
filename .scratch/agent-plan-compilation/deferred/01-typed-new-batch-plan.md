# 01: 类型化新建批量任务闭环

**What to build:** 用户通过 Agent 明确新建批量任务时，现有九项动作以专属类型化参数进入同一计划编译 implementation；按三档规则自动受理或出计划卡，确认后真实推进并展示逐项结果。共享校验、快照与可执行事实写入进入计划 module，旧在途任务和历史结果保持可用。

**Blocked by:** 本期内部重构完成后重新收束；不在当前执行队列

**Status:** needs-info（后续阶段，停止按旧拆分开工）

**Scope:** 2026-10-12 用户优先原报告架构优化，本票移入后续阶段。以下为完整协议升级目标，实施与依赖须重核，全部验收项未验证；当前执行入口见 [工单索引](../00-index.md)。

**Source:** [后续升级目标](../upgrade-spec.md)，Q1/Q2/Q4/Q7/Q8/Q9/Q10 及 Q5 的新建任务身份部分。

## 范围与交付边界

- 一张票完成新建任务的模型工具输入、受理/提案确认、Run/Operation 落库、Worker 消费、新旧卡类型显示与相关测试，不拆后端地基/前端接线票。
- 先在票内完成必要内部收敛，再切换公开新建路径；复用既有受控执行、预算、提案与任务机制。仅支持新建路径的半成品 helper 不算交付。
- 同时保留旧在途/回执读取 adapter；旧待确认卡不直接按新契约执行，升级限制明确可见。其确定性重新预览能力由 03 完成，不用临时旧写协议或自行补批准信息绕过该限制。
- 固定版本延展由 02 完成；本票只冻结新建/延展的类型化外壳和新建身份，不能借新建提交偷偷追加已有任务。中间工单在同一集成分支验收，整体对外发布等到 03 汇总验收完成，不添加临时功能开关。

## Acceptance criteria

- [ ] plan_batch_operations 的新请求明确表达新建意图；不按会话当前活跃 Run 自动合并。同卡并发确认/同逻辑调用重放最多建立一份 Run 与相关 Operation。
- [ ] 当前九项动作显式声明批量接入，其他单步动作默认关闭；参数/结果、允许引用的位置与 Tool schema 复用同一动作声明，去除生产新输入的动作字段并集及平行白名单。
- [ ] 新持久提案区分格式标记和计划版本，入口注入可信授权/溯源；模型不能自行填写或放宽这些依据。
- [ ] 新动作专属参数拒绝多余字段、动作无关字段及显式 null；省略字段按原必填/默认规则处理，保持原字段与 model 级业务校验器，不把内部默认空值当用户显式 null。
- [ ] 单批保持 1～50 项、同动作同既有目标不能同批重复；超限整体拒绝，创建类步骤不按同名、URL 或相似内容去重。
- [ ] course_id/goal_id 引用仅来自本批更早步骤，路径与消费位置提交时检查；引用自动形成依赖，仅依赖真实输出值的校验延期，绑定后复用原动作完整校验。
- [ ] 含引用的既有目标仍捕获/重验可确定快照；未创建目标不伪造快照；未校验载荷不冒充完整动作参数进入领域入口。
- [ ] 自动受理与计划卡确认共用编译/快照/落库 implementation，调用方不再拆装各自平行的载荷、快照、解析及序号序列；仅六元组改具名类型不算完成。
- [ ] 新建三档、动作风险规则及会话累计 10 项阈值保持；REQUEST_APPROVAL 出卡，允许的新任务按 AUTO_APPROVE/FULL_ACCESS 原规则受理，内容审核与外发独立边界保持。
- [ ] 入口拥有主事务，计划 module 不自行提交；Run/Operation/计划投影、触发 Job、绑定及 Proposal/Effect 成功回执原子落库，失败回滚后保留既有独立诊断且不覆盖并发成功。
- [ ] 业务提交处的 ChatTurn 取消/执行身份及 Worker 每步最终授权/快照校验继续生效，控制绑定语义不因两路收敛而改变。
- [ ] Effect 指纹反映新建/延展等真实请求语义；成功事实先于新校验/提交额度恢复，既有预算准入、计数和 5 次提交规则不改变，恢复不重复建任务/扣提交/投触发。
- [ ] 旧成功回执可查，旧在途 Run/Operation 身份、参数、版本、等待关系和结果保留；旧待确认卡明确不能直接执行，不兼容且无成功 Effect 的旧 checkpoint 不产生新写入。
- [ ] 前端使用明确后端契约/生成类型显示新建任务、逐项参数/依赖、批准与真实进度；兼容旧历史，保留继续/重试/取消及操作历史，触及文案中英文同步。
- [ ] 通过公开提交/确认与真实 SQLite/Worker 验证九动作多步链、引用失败/快照过期、WAITING_JOB、部分成功、取消和中断回放；前端现有组件测试覆盖新格式与旧卡限制，类型/规范/OpenAPI等范围门禁通过。

## 验收方法与记录

复用规格列出的批量、引用等待、多资料、轮次恢复、授权、预算和计划卡测试，优先现有外部入口，不测内部 helper 布局。每项区分自动化、模型/网络替身、真实 SQLite/Worker、真实模型与真实 Tauri 的证据，未执行的真机项保持未勾选。

本票代码验收的最低演示为：新建课程 → 导入来源/建立引用 → 建目标/产草案的真实 Run 路径，以及阈值内自动受理和默认档确认路径。新旧契约适配必须一并落地，不能等待后续票修复破损调用者。

## Out of scope

固定版本延展、确定性重新预览、新动作、通用 DAG、任意值引用、视觉重设计及历史覆盖率补齐。不新增通用能力 catalog 或第二套执行器。
