# 02: 固定版本的计划延展闭环

**What to build:** 用户明确向一个活跃 Run 添加步骤或修订参数时，Agent 在任何档位先给出绑定确定任务与基础版本的计划卡；确认后计划 module 原子延展并呈现实际变更。过期、已结束或已取消目标持续拒绝，成功历史不被覆盖，覆盖/修订/追加的依赖映射统一处理。

**Blocked by:** 后续类型化协议契约重新收束后确定；不在当前执行队列

**Status:** needs-info（后续阶段，停止按旧拆分开工）

**Scope:** 2026-10-12 用户优先原报告架构优化，本票移入后续阶段。以下为固定版本批准目标，实施与依赖须重核，全部验收项未验证；当前执行入口见 [工单索引](../00-index.md)。

**Source:** [后续升级目标](../upgrade-spec.md)，Q3/Q5/Q6 与 Q1/Q7/Q9 的延展应用部分。

## 范围与交付边界

- 复用 01 的类型化编译、动作声明、快照、入口事务与前端类型；本票打通延展意图的模型工具、提案、条件落库、Worker 与可见回执。
- 01 提供可真实运行的新建闭环，本票在其上实现确定任务的延展，不新造一份分类/映射算法。
- 新建卡与延展卡必须区分；不保留 AUTO_APPROVE 未确认 Run 的运行中自动追加例外，也不保留确认时按当前活跃任务/最新版本自动合并。
- 过期卡显示批准失效并保留内容、禁止直接确认。确定性重新预览按钮/API/Agent 入口在 03 闭环；不能以继续执行旧卡或另建 Run 充当临时恢复。

## Acceptance criteria

- [ ] 延展请求明确指定目标 Run；Agent 能读取真实任务信息，归属不明先追问，页面上下文和模型指定的任务/版本不构成授权。
- [ ] 新增目标或改变参数时，REQUEST_APPROVAL/AUTO_APPROVE/FULL_ACCESS 均先生成计划卡，等待态同样先确认；相同覆盖项不新增写入或提升版本，档位呈现规则保持。
- [ ] 预览固化确定 Run、基础计划版本、目标/参数/依赖与快照；确认不选择另一任务，不将已结束目标的新建意图补到旧卡。
- [ ] 主提交事务内对目标状态、cancel_requested 和基础版本做条件写校验，并检查实际成功条件；不同提案的确认抢占不能替代 Run 上的版本竞争校验。
- [ ] 同一基版本的两张延展卡并发/先后确认最多一张变更提交；另一张批准失效且没有部分 Operation、Job、绑定、计划版本或成功回执写入。
- [ ] 目标不存在、终态或取消已生效持续拒绝旧卡，不转到其他活跃 Run、不新建替代任务；版本失效不能单靠重复请求执行通过。
- [ ] Worker 正常推进、结果绑定和 Job 完成不提高计划版本；实际参数/步骤变更成功后版本与计划投影同源递增，纯覆盖和失败回滚不递增。
- [ ] 相同动作/既有目标/参数及等价依赖的 PLANNED/SUCCEEDED 项复用；分类前对引用身份归一化，局部与全局索引不直接比较。
- [ ] 待执行参数变更经确认原位更新参数/快照/授权，保留 Operation 身份、位置及尝试历史；已成功参数变更追加新 Operation，原成功历史保留。
- [ ] 编译后、确认前 PLANNED 已变 SUCCEEDED 时按提交处真实状态重新分类，不覆盖成功历史；对象快照失效仍拒绝，不以版本未变跳过对象重验。
- [ ] 失败/跳过项的新授权步骤与原身份失败重试明确区分，沿用既有部分完成及重试规则；创建项不做猜测去重。
- [ ] 覆盖、修订、追加混合批次统一映射输出引用和依赖到真实 Operation/Run位置，调用方不掌握多个平行索引集合；实际变更条数不包含纯覆盖项。
- [ ] 删步骤、重排、改变已有依赖及参数引用引入的新既有依赖关系明确拒绝，不接收请求后静默保持旧依赖。
- [ ] 取消先提交时延展不落库；确认先提交时取消按真实新计划收口。成功项、已提交领域 Job 保留，确认不清掉取消标记或复活取消任务。
- [ ] WAITING_USER 的确认沿用明确唤醒语义，WAITING_JOB 不伪造完成；中断恢复不重做成功项，授权降档、执行身份及提交/失败记账继续生效。
- [ ] 前端计划卡显示延展的确定任务及版本、真实变更结果；失效原因稳定可区分，禁止直接确认的状态与服务端一致，现有任务控制/历史、多主题和中英文文案保留。
- [ ] 真实 SQLite/公开确认入口覆盖同卡防重、不同卡版本冲突、两种取消顺序、进度变化交错、混合映射、快照过期和不支持编辑；相关前端和类型/规范/契约防线通过。

## 验收方法与记录

先复用原批量参数修订、混合目标、输出引用延展与等待恢复用例，再对本次改变的授权例外、固定版本并发及依赖拒绝补必要测试。用实际落库身份、参数、版本与回执断言，不仅检查工具返回字符串或 UI 禁用态。

本票演示为：原 Run 仍可执行时出两张同基础版本卡，先确认一张，另一张被拒；已成功步骤保持历史，新增独立步骤继续推进。取消窗口与状态交错使用可重复的事务挂闸验证，不靠随机并发碰运气。

## Out of scope

重新预览能力、整份计划替换、步骤删除/重排、修改已有依赖、新动作和通用 DAG。不扩展单步授权、Undo或Retry能力，不改变预算政策。
