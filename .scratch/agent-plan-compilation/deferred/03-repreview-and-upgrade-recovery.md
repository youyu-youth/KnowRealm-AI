# 03: 旧计划重新预览与升级恢复闭环

**What to build:** 用户遇到旧待确认卡或批准失效时，可通过页面或 Agent 保留原参数、读取最新快照并明确任务归属，得到新格式卡后再次确认；重复和重启不会制造重复批准。完成整个升级的旧数据恢复、真实执行呈现和发布验收。

**Blocked by:** 后续新建/延展及批准契约重新收束后确定；不在当前执行队列

**Status:** needs-info（后续阶段，停止按旧拆分开工）

**Scope:** 2026-10-12 用户优先原报告架构优化，本票移入后续阶段。以下为确定性重新预览目标，实施与依赖须重核，全部验收项未验证；当前执行入口见 [工单索引](../00-index.md)。

**Source:** [后续升级目标](../upgrade-spec.md)，Q4/Q11 与 Q2/Q5/Q9 的兼容、来源关联和最终验收部分。

## 范围与交付边界

- 这是新的恢复能力闭环，包含计划专属确定性公开服务、HTTP/Agent 接入、持久幂等与来源关联、旧卡/新卡呈现及完整路径验收，不是只写测试或整理文档的收尾票。
- 页面与 Agent 共用 01/02 的编译及批准语义，不复制业务参数校验，不调用 LLM 重生成原计划，不把重新预览当作批准。
- 以三票完整能力作为对外发布条件；旧写协议不得在某个入口继续绕过新校验/版本/授权。复核过渡适配只保留历史读取与在途恢复，删除仅因本次改动产生且已无人调用的临时新旧转换代码。
- 不修改父规格内容或将规格状态标成实现完成；本票只记录真实验收范围及待用户真机项，项目交接同步实际状态。

## Acceptance criteria

- [ ] 计划专属重新预览公开入口通过来源提案读取原请求，由 HTTP 与 Agent 薄 adapter 共用；来源类型、状态、归属和可解码性在服务端校验。
- [ ] 旧格式读取集中，旧 null 按历史语义视为省略；原有效参数与依赖保留，不丢字段、不改内容。无法无歧义转换时给出结构化错误或消歧，而非自行补新批准信息。
- [ ] 任务意图可确定时保留原新建/延展；归属不明明确选择新建或一个真实 Run。原目标终态/取消/不存在不能自动切新建，改换任务需要新的明确请求。
- [ ] 重新读取对象快照、确定任务与基础版本后只创建新待确认卡；任何档位都不自动执行，来源旧卡保留且仍不可直接确认，新增来源关联可审计。
- [ ] 同来源、同明确意图且基础版本/快照仍有效时，重复/并发重新预览复用对应新卡或返回其已处理结果；真正失效后须新预览，不重复批准旧内容。
- [ ] 来源关联和幂等使用持久事实，跨重启可对账，不依赖前端 busy、进程缓存或模型临时记忆；继续复用 Effect/提案与现有预算语义，不建通用版本管理框架。
- [ ] 前端旧卡/失效卡保留可核对内容，提供重新预览加载、错误、需消歧和新卡结果；失败不丢参数，新卡确认后接既有 Run 进度，重复点击/网络失败会回查真实结果。
- [ ] Agent 能确定性请求重新预览、如实描述待确认结果并在歧义时追问；不反复尝试执行旧卡，不要求用户必须打开页面恢复。
- [ ] 旧成功回执、旧在途 Run、旧待确认提案、损坏历史及无成功 Effect 的旧 checkpoint 五类均有明确结果；旧任务恢复保留身份/尝试/等待/成功项，损坏计划的写路径拒绝且展示可查询。
- [ ] 新格式已覆盖全部生产新写路径；没有仍接收旧扁平参数并绕过新批准规则的入口，不批量改写历史或为迁移制造重复 Run/Operation/Job。
- [ ] 重新预览→新卡→确认→Worker 的新建与延展两条路径通过真实 API/SQLite/Worker；同基版本冲突、取消与失败原子性及业务先提交后 checkpoint 中断场景联合回归通过。
- [ ] 模型工具 schema、缺参追问、任务消歧及重新预览完成真实模型验收，记录供应商/模型与未覆盖范围；模型/外网替身证据不代替真实模型结论。
- [ ] 新旧计划卡、重新预览/确认、Run 等待与重启呈现完成真实 Tauri/WebView2 验收；触及控件覆盖多主题、窄窗/大字号、键盘/焦点及减少动效。Windows 缩放与视口/DPR 模拟分别记录，不代勾用户真机项。
- [ ] 相关测试、类型、规范、格式、OpenAPI/TS生成类型及错误码/i18n防线通过；新错误原因可穿过现有 Proposal 外层错误包装呈现。仅补本次缺失覆盖，不借机修历史失败。
- [ ] 三票结局及规格行为矩阵逐项登记证据，明确自动化、网络/模型替身、真实 SQLite/Worker、真实模型、真实 Tauri和未验收项；不能用结构检查或旧行为测试代称升级验收完成。

## 验收方法与记录

优先通过现有计划卡查询/确认、确定性重新预览入口与真实持久执行链验收；跨重启复查新卡来源、Run/Operation/Job 身份与成功回执，而不是只断言前端状态或内存去重。

本票必须给出两个可核对的演示：旧待确认卡重新预览为明确新建任务并确认执行；失效延展卡重读基础版本后生成新卡、确认延展且不覆盖已完成历史。再覆盖歧义、重复预览、快照变化、取消及损坏输入的拒绝结局。

真实模型/Tauri无法执行时保留未勾选项并记录原因，自动化完成不能自动关掉真机门禁，也不得越权增加部署、凭据配置或外发步骤。

## Out of scope

LLM 重写旧计划、语义去重、通用提案版本管理、学习计划排期调整、新动作、视觉重设计、历史测试债务修复、权威需求/数据模型升版与编码规范修改。
