# 通用 Agent 第一阶段：可靠的课程与文本记录操作（spec）

Status: ready-for-agent
定稿依据：开发计划文档 + 设计-4 采纳版 + ADR-0026 + 2026-09-21 grill 八问定稿（Q1~Q8，全部用户确认）。

## Problem Statement

学习者目前只能通过表单和专用入口逐个操作课程与记录，对话中的 Agent 只能读、不能做。用户在聊天里说"帮我创建课程""向某课程添加这段笔记"，Agent 无法可靠完成：没有受控写路径、没有幂等保证、没有可恢复的操作回执。同时，产品即将进入大量能力复用通用 Agent 的阶段（自动执行、批量整理、长任务），当前缺少一个可被第二、第三乃至第 N 个动作复用的公共执行地基——如果首批两个动作各自为政，后续每个能力都要重造授权、幂等与回执，返工成本随能力数线性增长。

## Solution

在现有聊天工作区内（不建独立 Agent 工作台），交付两条完整闭环：

1. **"帮我创建课程"** → Agent 澄清缺失必填项（名称、学习场景、阶段/深度）→ 确认卡 → 用户确认 → 课程创建 → 回执卡（课程入口跳转）。
2. **"向指定课程添加文本记录"** → 课程查找与同名消歧 → 确认卡（明示"保存后将尝试生成 AI 总结"）→ 确认 → 记录保存 → 回执卡（记录入口 + 总结任务真实状态）。

底层随首个写动作落地**最小公共执行机制**：操作注册表（动作标识 → 类型化 schema、级别、应用器、结果投影）+ 薄工具 + 既有提案框架 + 结果同事务回写。第二个动作（文本记录）复用第一个动作（课程创建）的公共机制，以此验证地基扩展性。

授权仅"请求批准"档（= 现行 ADR-0024 提案规则，零行为变更）；三档授权随第二阶段。

## User Stories

1. 作为学习者，我想在任意聊天会话中说"帮我创建一个课程"，让 Agent 引导我补齐名称、学习场景和阶段/深度，从而不用离开对话去填表单。
2. 作为学习者，当我只说"创建课程"而没给名称时，我想让 Agent 只追问缺失的必填项，不重复问我已提供的信息。
3. 作为学习者，当课程必填项齐全时，我想先看到一张确认卡，完整列出将创建的课程参数（名称、场景、阶段/深度、可选类型与说明），确认后才真正创建。
4. 作为学习者，我未点确认之前，无论刷新、重启应用还是关闭会话，都不应产生任何课程。
5. 作为学习者，我双击确认按钮、重复提交确认或确认请求超时后重试/查询时，只会有一个课程被创建。
6. 作为学习者，课程创建成功后，我想收到回执卡并能一键跳转到新课程。
7. 作为学习者，当我说"向 Python 学习课程添加一条记录"并给出文本时，我想让 Agent 先查找课程：唯一匹配直接使用；多个同名展示候选让我选；找不到时明确告知，不擅自新建同名课程。
8. 作为学习者，我在任务进行中切换页面后回来，正在确认中的操作目标不会悄悄变成别的课程。
9. 作为学习者，我想在文本记录确认卡上明确看到"保存后将尝试生成 AI 总结"，而不是事后才发现触发了总结。
10. 作为学习者，当我要求"只保存、不要总结"时，我想让 Agent 如实告知当前不支持，而不是绕过总结链或谎称可以。
11. 作为学习者，记录保存成功但总结任务提交失败时，我想在回执卡上看到真实状态（记录已保存、总结提交失败可重试），而不是"全部成功"或"全部失败"。
12. 作为学习者，当目标课程在确认前被归档或删除时，我想让确认失败并得到清晰原因，而不是产生悬挂的记录。
13. 作为学习者，我停止生成或断开连接后，已产生的待确认操作仍保留等我决定，Agent 不再继续产生新操作。
14. 作为学习者，我想拒绝任何待确认提案，且拒绝后不产生任何业务事实。
15. 作为学习者，在自由（FREE）会话里我也能创建课程、向消歧出的课程添加记录；同时资料读取范围不会因页面或操作而被扩大。
16. 作为学习者，查找同名课程时我想看到候选列表（名称、状态、场景、更新时间）供我选择，避免误选。
17. 作为学习者，我提供超限文本（超过 1 MiB）时，Agent 明确告知上限与替代路径，而不是静默失败。
18. 作为 Agent（模型），我需要一个结构化的课程查询工具，按名称查找课程并拿回候选，用于消歧；查课程名不走资料语义检索。
19. 作为 Agent，我调用写工具的语义恒为"完成这件事"，是否需要用户确认由后端决定，不由我判断，工具名称与描述不随授权模式改变。
20. 作为 Agent，我缺必填参数调用写工具时，工具返回结构化的缺失项说明，让我能准确转述给用户继续澄清。
21. 作为开发者，我想通过声明式注册（类型化 schema + 应用器 + 结果投影）接入一个新写动作，公共执行流程零改动、零领域专属分支。
22. 作为开发者，我想用同一模式接入第二类对象查询工具（如未来的记录查询），零公共流程改动。
23. 作为开发者，我想让 HTTP 路径与提案应用器调用同一个事务内业务核心，校验、写入、索引逻辑不出现双份漂移。
24. 作为开发者（未来的自己），我想通过操作回执（结果同事务回写）在超时、崩溃或重启后查明某提案是否已执行、创建了哪些对象、关联了哪个后台任务。
25. 作为学习者，界面语言切换后，确认卡、回执卡与候选卡的文案跟随（zh/en 同步）。
26. 作为学习者，重启应用后回到会话，我能通过持久化查询恢复未决提案的状态视图（不依赖 SSE 仍在连接）。

## Implementation Decisions

以下决策在 grill 中逐项定稿（Q1~Q8），实施不再开放重议；与设计-4 / ADR-0026 冲突时以本文为准并显式提出。

**授权与语义**

1. 第一阶段仅"请求批准"档：所有写操作先提案（PENDING）、用户确认后执行，与现行 ADR-0024 规则零行为差异。"帮我批准""完全访问"档、批量阈值、batch_id、authorization 字段全部归第二阶段。
2. 文本记录语义（Q1）：复用带课程的 PASTE 处理链——创建 SUMMARY_PENDING 记录 + 转写正文 + 搜索索引同事务写入 + 资料库回填 + 总结任务事务外 best-effort 提交。确认卡明示"保存后将尝试生成 AI 总结"。"只保存不总结"如实回答当前不支持；该领域缺口登记在案，需求真实出现另立领域票，不在本阶段用工具绕过。工具参数对齐领域限制：正文上限 1 MiB、标题取首行 100 字，超限返回稳定错误码由模型转述。

**公共执行机制（模块边界）**

3. 公共执行机制落在 agent 模块的 operations 子包（Q2）：操作注册表以稳定动作标识注册类型化 payload schema、操作级别、应用器与结果投影；写工具是薄壳（docstring 面向模型 + 参数 schema 直接来自注册项）。术语钉死：**动作（action）= 模型可调用的工具语义；操作（Operation）= 一次受控执行的事实记录（回执）**。
4. 既有提案框架（列表/创建/确认/拒绝 + payload 判别校验 + 应用器注册）留在 library 域原位不动，operations 只调用它；ORGANIZE / RESEARCH_INGEST / MEMORY 三个既有应用器零迁移。依赖方向：agent → library（提案框架）、course、capture，无环。公共执行流程不得出现课程或记录专属分支。
5. 新增提案类型 COURSE_CREATE 与 TEXT_RECORD_ADD，payload 采用 Pydantic 判别 schema（未知键拒绝），注册进既有判别校验表；沿用"创建提案不改任何业务事实"纪律。

**事务与业务入口**

6. 抽取课程创建与文本捕获的**事务内核心**（不自行开事务、由调用方拥有事务）；HTTP 路由与提案应用器共用同一核心。业务写入、搜索索引、提案 APPLIED 与结果回写在同一事务原子提交；总结任务维持事务外 best-effort 提交（沿用现有错误码与日志语义）。应用器在确认事务内执行领域写入，沿用既有应用器契约（不得自行开事务、失败抛带码异常由框架转 FAILED + 稳定错误码）。
7. 执行前重新校验目标：课程不存在 → 稳定错误码失败；课程已归档 → 沿用"归档课程不能接受新资料"语义，提案落 FAILED 而非产生悬挂记录。

**持久化与幂等（Q3/Q4）**

8. 迁移为 agent_proposals 增加 `result_json` 一列（可空，APPLIED 时同事务回写类型化结果：课程创建 → 课程 id；文本记录 → 记录 id + 总结任务 id 或失败错误码）；结果进入提案输出契约。幂等键 = 提案 id：APPLIED / REJECTED 为终态、重复确认 409，天然覆盖双击、重放、超时后重查。batch_id、authorization 等字段留第二阶段。
9. 持久化面收窄为"提案 + 操作结果"两项：不建澄清草稿表、不给消息表加页面快照列。跨轮澄清靠聊天历史 + 提案创建时的 schema 校验兜底（缺必填 → 创建被拒 → 工具返回缺失项 → 模型追问）；"固定目标"由提案 payload 承载（解析出的课程 id 固化进提案，切页不影响）。
10. 版本纪律：提案 payload 与结果的形状以提案类型 + 判别 schema 为版本边界；schema 变更必须保证旧数据可解释或显式失效并要求重新确认，不预建物理版本字段与通用迁移框架（首个真实不兼容变更时再评估）。

**上下文与装配（Q5/Q6）**

11. 每条消息携带轻量页面快照（页面类型、当前实体 id、选中对象 id、时间），仅运行期注入模型上下文；后端重新校验对象存在性与状态。页面快照不落库、不构成授权、不扩大读取范围。
12. 操作工具组（课程查询、创建课程、添加文本记录）**恒挂载全部会话类型**（先例：记忆提案工具）；**写操作的目标解析与会话范围解耦**——自由会话可创建课程、可向消歧出的课程添加记录；会话范围只约束资料正文读取（自由会话不因操作或页面获得资料检索能力）。装配维持既有声明式静态组合，不引入动态选择机制。
13. ContextVar 收敛：建立单一 Agent 运行时上下文（会话工厂、会话 id、范围、课程/记录/资料条目 id、模式等）与单对绑定/重置；**新操作工具与现有四个工具（资料检索、联网搜索、记忆提案、入库提案）同票迁移**到统一上下文，消除每工具一对绑定的复制增长。
14. 对象查询工具族契约（Q6）：结构化对象查询 = 每个对象族一个类型化只读工具（禁万能 query 工具，同写侧禁万能 action+payload 的纪律）；本阶段仅交付课程查询（名称子串 → 候选：id、名称、状态、场景、更新时间），计入工具调用预算。不交付课程详情读取工具（确认卡预览用既有课程 API 拉取）。验收锚点：第二类对象查询接入时公共流程零改动。

**结果、预算与取消（Q7/Q8）**

15. 总结任务对账口径：记录创建是事实、总结提交 best-effort；总结任务提交失败时回执如实呈现（记录已保存 + 总结提交失败 + 可在记录页重试），不在提案层做自动重试，不出现第二条执行通道。"已保存 ≠ 总结已生成 ≠ 可检索"三态在回执文案中区分。
16. 预算：每轮操作类提案上限 5 条（对齐既有提案工具先例，超限拒绝而非截断）；课程查询计入既有工具调用预算（调用数与字符数累计）。
17. 取消语义：确认前取消 = 拒绝提案（REJECTED，不改业务事实）；执行中为单步原子事务、不可中断；SSE 断开仅停止接收，不影响已产生提案；待确认提案维持现状不过期（本阶段显式声明该行为，不做过期清理）。
18. 结果状态统一表达：查询结果 / 待确认 / 执行中 / 成功 / 失败不混同；提案 APPLIED、后台任务成功与用户任务完成是三个不同层级，回执按真实返回值报告。

**SSE 与前端**

19. 零新 SSE 事件类型：完成载荷新增操作提案列表（先例：研究提案、记忆提案的完成载荷模式）；确认卡 / 回执卡复用既有提案就地卡模式（确认与拒绝按钮、失败原因展示、APPLIED 后转回执态）。断线与重启后经既有提案查询恢复状态视图。
20. 回执卡跳转复用既有课程 / 记录导航；确认卡字段预览直接读提案 payload。
21. 新增文案 zh / en 双语同步；新增稳定错误码进错误码清单并同步双语文案。

## Testing Decisions

测试只断言外部行为（提案状态、业务对象存在性、回执载荷、幂等结果），不断言注册表内部结构或私有函数。优先复用现有测试资产（课程、文本捕获、提案、研究提案、聊天流测试）；全部使用既有测试缝隙，不新建缝隙：

- **工具层**：直接调用工具函数（绑定统一运行时上下文）断言提案创建与结构化返回（缺失项、超限、上下文未绑定各分支）——先例：研究提案工具的往返测试。
- **确认与应用层**：经既有提案确认端点应用 COURSE_CREATE / TEXT_RECORD_ADD，断言业务对象创建、结果回写、索引写入、双确认 409（幂等）、归档/不存在目标的失败路径——先例：library 提案测试。
- **事务核心复用回归**：现有课程创建与文本捕获的 HTTP 路由测试在改造为零改动通过（证明共用核心无行为漂移）。
- **上下文收敛回归**：既有聊天流、研究提案、资料检索测试全绿。
- **前端**：确认卡 / 回执卡 / 候选卡组件测试（MSW mock 提案与课程端点），断言确认后状态流转与文案——先例：研究提案卡组件测试。
- **故障场景**（综合验收工单）：确认超时后重查、重启后待确认/已应用提案恢复查询、总结任务失败回执呈现、停止生成后无新提案。

## Out of Scope

- 三档授权的另外两档、批量阈值、batch_id / 授权依据字段、操作历史页（第二阶段）。
- 修改、归档、软删除、批量整理、计划卡、有限 Undo（第二阶段）。
- 多资料长任务、课程级学习计划、多步骤自主恢复、跨重启接续（第三阶段）。
- "只保存不总结"的轻量课程记录能力（领域缺口已登记，需求真实出现另立票）。
- 独立 Todo 操作与资料治理操作。
- Skills / SubAgent / MCP、动态工具选择或意图分类机制。
- 课程详情读取工具与其他对象族的查询工具（随对应闭环落地）。
- 独立 Run / Operation 表、通用迁移框架、提案过期清理。
