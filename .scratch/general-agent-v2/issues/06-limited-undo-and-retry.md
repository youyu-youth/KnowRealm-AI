# 06 — 有限 Undo 与重试

**What to build:** 首批动作提供有限撤销（重命名、归类变更、归档 / 恢复、跨课迁移、条目软删——反向走既有回收站恢复链），撤销是新的受控补偿操作（undo_of 链、保留原执行历史），撤销前重验版本与依赖、不覆盖用户后续修改；批次撤销按依赖逆序补偿并保留逐项结果；记录软删、课程删除与课程级联删除不提供 Undo 并明确告知原因。重试分自动（瞬时故障原身份 ≤2 次）与手动（原身份 attempts 递增），失败项重试不重复成功部分。用户可演示：改名后点撤销 → 旧名恢复；期间又手动改过名 → 撤销明确拒绝并说明。

**实施约束:** 实施决策见 [spec](../spec.md) 决策 19~20（取消不冒充撤销；未知结果先对账——operation 行与业务写同事务即对账锚点；UI 显式动作＝用户授权直接建补偿 operation，经 Agent 的 undo 工具走三档）。

**Blocked by:** 03 修改与归档动作、04 删除与跨课迁移、05 批量计划卡与 Run 推进。

**Status:** ready-for-agent

- [ ] operation 级 Undo：校验终态 SUCCEEDED、未被撤销、快照版本重验、领域恢复条件完整 → 创建补偿 operation（undo_of 关联）执行；跨课迁移 Undo＝反向迁移过全部校验；条目软删 Undo＝既有回收站恢复链
- [ ] Undo 入口：回执卡 / 操作历史按钮（POST operations/{id}/undo，UI 显式动作即授权）＋Agent undo 工具（走三档授权）；撤销后原 operation 标记 undone_by、历史保留
- [ ] run 级批次 Undo：按依赖逆序补偿、逐项结果如实呈现；单项补偿失败不谎报整体成功
- [ ] 不可撤销动作（记录软删、课程软删、课程级联删除）明确原因呈现（可撤销性在注册项声明，工具结果与回执透出）
- [ ] 自动重试：瞬时故障分类（如 SQLITE_BUSY / 临时 IO）原身份自动重试 ≤2 次，每次重验授权 / 版本 / 取消；参数 / 领域 / 版本 / 权限错误不自动重试
- [ ] 手动重试：失败项重试端点沿用原 operation 身份（attempts 递增），用户明确要求重复执行才新建 operation；attempts_json 逐次尝试错误历史可查
- [ ] 未知结果对账：operation 行与业务写同事务（崩溃＝未发生可安全重试、行在＝已执行）断言测试
- [ ] 撤销与取消语义分离断言（取消停止后续、不补偿已完成）
- [ ] 前端撤销 / 重试按钮状态（可撤销性、已撤销标记、重试中）＋zh/en 双语同步；新增错误码登记；api-types regenerate
- [ ] 门禁全套过（后端 pytest / ruff / pyright、前端 vitest / lint / build、OpenAPI --check）

**用户真机验收（单列，不代勾）：**

- 真实改名 → 撤销恢复旧名；撤销前再次手动改名 → 撤销被拒并说明版本冲突。
- 批量归类后整批撤销：按逆序恢复、操作历史逐项呈现补偿结果。
- 构造失败项（如目标课程被归档）→ 手动重试沿用原操作、成功后无重复副作用。
