# 02 — 三档授权与自动执行

**What to build:** 上线「帮我批准」「完全访问」两档（默认档=请求批准零行为变更）。设置页新增「Agent 自动化」分区选全局默认档；会话内可临时切换（右栏开关，按会话内存，重启回落全局默认）；提交路径按档位确定性分流——默认档落提案（现状），自动档 L0/L1 校验通过即执行并给含授权依据的回执，L3 删除类在「帮我批准」下仍逐项确认、「完全访问」下自动执行；模式切换全程审计。用户可演示：切「帮我批准」→ 会话说建课 → 免确认直接创建＋回执标注档位与指令原文；切回默认档 → 一切回到确认卡流程。

**实施约束:** 实施决策见 [spec](../spec.md) 决策 9~11、23（Memory / 内容审核 / 外发任何档位不变；禁止项任何档位不暴露；每轮操作预算上限 5 不变、提案与直执行同计）。直执行回执的「历史已清理」降级占位随本票回执卡一并交付（数据源是 01 的 operation 查询）。

**Blocked by:** 01 执行事实地基与操作历史。

**Status:** ready-for-agent

- [ ] 全局默认档：settings.json 偏离项（默认=请求批准不写键，learner_memory 外发开关先例）＋设置页「Agent 自动化」分区三选一
- [ ] 会话档位：前端按会话内存（web_search 开关先例）＋聊天右栏授权模式开关；消息请求携带会话档位覆盖（不带=全局默认）；重启应用回落全局默认（安全方向）
- [ ] 模式切换审计 API：全局切换改 settings.json＋写 agent_activity；会话切换仅写 agent_activity（from / to / 作用域 / 会话 / 时间）；01 的审计区从空态接真
- [ ] 运行时上下文新增授权档位字段（消息流入口解析：全局默认＋请求覆盖）
- [ ] 提交路径分流（执行端执法，提示词与工具描述不随档位改变）：默认档=落提案零变化；AUTO_APPROVE=L1 直执行、L3 恒落提案确认；FULL_ACCESS=L1/L3 均直执行；档位对本票已注册的建课 / 加文本记录（L1）生效，后续票新动作按注册表 level 自动继承
- [ ] 直执行：单事务写 operation＋业务结果（回执记录档位、触发指令原文与时间）；失败独立小事务落 FAILED＋稳定错误码（_mark_failed 先例）；工具返回结构化回执载荷
- [ ] L0 读取恒自动；Memory 写入、AI 总结与学习资产采纳、外发同意在任何档位走原确认规则（断言测试）；禁止项任何档位不暴露
- [ ] done 载荷新增直接执行回执键（零新 SSE 事件类型）；前端直执行回执卡（授权依据呈现＋「历史已清理」降级占位）＋断线 / 重启经 operation 查询恢复
- [ ] 降档后后续动作重新按新档位检查授权（不沿用旧自动授权）；升档不自动执行积压提案（断言测试）
- [ ] 新增错误码登记＋zh/en 双语同步；默认档阶段一测试全量零回归
- [ ] 门禁全套过（后端 pytest / ruff / pyright、前端 vitest / lint / build、OpenAPI --check）

**用户真机验收（单列，不代勾）：**

- 真实模型三档走查：默认档确认卡流程与第一阶段一致；帮我批准建课免确认＋回执含档位与指令原文；完全访问下说「删掉这条记录」仍出确认（L3 在帮我批准）或直接执行（完全访问）。
- 会话内切档即时生效；重启应用后会话回落全局默认档；设置页改全局默认只影响新会话。
