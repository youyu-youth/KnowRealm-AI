## 第一轮：已确认（2026-09-22）

用户答复「全部按推荐」，确认 Q1～Q6。以下决定描述第二阶段目标，不代表当前已实现。

### Q1 同一任务等待与恢复

- 批次遇到冲突后，保留原任务及成功结果，允许用户稍后处理并继续，跨应用重启仍可接续。
- 第二阶段即触发设计-4 的独立 Run / Operation 模型评审；具体表结构尚未决定。
- 验收：十项任务前两项成功、第三项冲突，重启后处理冲突，不重做已成功项，继续原任务剩余项。

### Q2 跨课程整理的领域边界

- 资料条目归类与学习记录跨课程迁移是两种能力。
- Record 跨课程迁移纳入第二阶段独立闭环，先明确知识点、Concept、学习证据、后台任务及掌握度的处理规则。
- 验收：HTTP 与 Agent 共用完整领域入口；不能仅修改 course_id，不能由 Tool 绕过当前禁止重新归类的规则。

### Q3 授权模式切换

- 全局默认只影响新会话。
- 会话降档后，后续动作重新检查授权；已提交的单步事务不强行中断。
- 对象、参数和版本仍匹配的显式批准可以保留，撤销批准是独立操作。
- 升档不自动执行积压的待确认提案。
- 模式变化、执行依据和撤销均留历史。
- 验收：降档不使剩余动作沿用旧自动授权；升档不扫描执行旧提案；显式批准的有效性按绑定内容重新校验。

### Q4 批次部分失败

- 独立项继续，依赖失败项的后续步骤阻塞；保留成功结果并如实呈现部分完成。
- 授权失效、取消或系统性故障停止后续推进。
- 普通单项失败不默认回滚整个批次。
- 验收：单条归档失败不阻断独立条目；建课失败阻断依赖它的导入；重试不重复成功操作。

### Q5 有限撤销

- 按动作提供 Undo，首批优先重命名、归属变更、归档及已有可靠恢复链的资料删除。
- 各动作仍须检查当前版本、新增依赖与完整领域恢复条件；不满足条件时明确不支持。
- 撤销是新的受控补偿操作，保留原执行历史；不把取消当撤销。
- 课程级级联删除在完整恢复能力具备前不提供 Undo。
- 验收：不会覆盖操作后用户的新修改；批次补偿保留逐项结果；无法恢复时给出明确原因。

### Q6 任务独立于聊天展示

- 关闭页面和 SSE 断线不取消已提交任务；停止回答与取消任务是不同操作。
- 删除会话不自动删除执行历史或撤销授权；有运行任务时提供明确处理选项。
- 应用完全退出后停止进程，下次启动依据持久状态恢复；不承诺退出或关机期间继续运行。
- 验收：断线仍能查询任务；删除会话后历史可达；取消经持久化执行入口生效。

## 已核对的实施起点

- 第一阶段已有类型化 OperationSpec（含 level / payload_schema / result_schema / applier）、业务与回执同事务、同 proposal 并发确认防重。
- 同 proposal 幂等不等于任务恢复后的操作幂等；稳定任务/操作身份待定。
- Chat checkpoint 当前每轮清理，任务恢复不能依赖聊天流；JobRunner 可复用执行壳，批次推进与恢复规则尚需实现。
- 通用提案当前归属 library；旧 ORGANIZE 与新操作注册项的授权、版本纪律须统一评审。
- Record 已归类后跨课迁移当前被拒绝；课程删除的掌握度重算仍在 HTTP 路由；资料删除与课程级联删除的恢复能力不同。

## 第二轮：已确认（2026-09-22）

用户答复「全部按推荐」，Q7～Q13 定稿：

- **Q7 执行事实模型**：独立持久化 Run 与 Operation；Run 保存任务/计划/等待/取消，Operation 保存稳定执行身份/参数/版本/结果/补偿关系，proposals 保存审批，Job 保存后台执行。新执行结果只以 Operation 为事实源，旧接口投影兼容、明确旧数据迁移，避免双写结果；公共执行归 agent 内职责明确的子包，领域适配器分离，继续复用 JobRunner 与既有框架。
- **Q8 级联影响授权**：批准绑定直接目标及领域计算的影响范围；执行前对象版本与影响范围均重验；删除课程预览后新增记录等实质变化使旧批准失效（重新预览授权）；正常派生索引维护不按新增业务目标处理。
- **Q9 自动批量阈值**：「帮我批准」档同一任务当前计划的直接业务目标数与写操作数均 ≤10；计入已完成项，拆 Tool 调用/分段执行/重启不重置；同一 Operation 失败重试不重复计项（受独立重试预算约束）；级联影响按动作风险规则处理、不按底层 SQL 行数计数；L3 逐项确认，Memory/审核/外发边界不变；完全访问不受此确认阈值限制。
- **Q10 重试身份与未知结果**：瞬时故障在原 Operation 身份下自动重试 ≤2 次，每次重验授权/版本/取消；参数/领域拒绝/版本冲突/权限失效不自动重试；未知结果先查询对账，不能确认安全重试时转用户处理；用户明确要求重复执行才创建新 Operation；尝试数与错误历史保留。
- **Q11 跨课迁移历史**：记录内容及记录级总结/知识点/Todo/复习资料随记录移动；原课程 Concept、历史作答、已完成测试与学习证据保留历史归属；不自动继承掌握度、不按同名自动匹配；目标课程当前概念关联重新校验/审核；不清空历史绑定绕过校验。
- **Q12 旧写路径兼容**：本期接入的新旧整理/修改路径共用版本与授权纪律；旧待确认提案缺对象版本/影响快照时重新预览、生成新批准，不按新自动模式直接执行；既有成功回执保留可查；Memory 与内容审核保持专属确认规则，研究入库按动作与外发边界分类。
- **Q13 历史与隐私删除**：执行历史独立保留本地，只存必要指令原文/授权/变更/结果；删除聊天不删任务历史（界面说明），另设「清理已结束任务历史」显式入口（同时失去对应 Undo 与历史回查）；活动任务先结束或取消才可清理。

## 第三轮：已确认（2026-09-22）

用户答复「全部按推荐」，Q14～Q22 定稿（原建议表述如下，代码事实锚点已核实）。

- **Q14 执行事实落库与推进机制**：建议新增 `agent_runs` + `agent_operations` 两表（0030）；operation 自始为执行事实唯一源（单步操作不建 run、run_id 可空）；proposal.result_json 降级为 operation→proposal 单向投影缓存（旧接口零破坏）；工单 07 批次载体由「编排型 Job＋batch_id」修订为「Run＋JobRunner 内 AGENT_RUN 推进 worker」（确定性推进器，不破「不叠运行时编排器」红线）。
- **Q15 Run 状态机与唤醒**：六态 RUNNING/WAITING_USER/COMPLETED/PARTIAL_COMPLETED/FAILED/CANCELLED，WAITING_JOB 枚举预留第三阶段启用；唤醒仅显式动作（继续指令/重试失败项/解决冲突/取消）触发并原子抢占；推进 worker 只认 RUNNING，不自动猜测 WAITING_USER 可继续。
- **Q16 版本与影响范围载体**：操作 payload 固化「执行前快照」三用（预览展示/执行前重验/Undo 补偿数据）；直接目标用 updated_at（微秒精度）+ 修改动作 before 值，级联影响用清单快照（如课程→record id 集合）；不给业务表加 version 整数列。
- **Q17 档位存储与 Run 授权固化**：全局默认档落 settings.json 偏离项（learner_memory_outbound_enabled 先例）；会话档位前端按会话内存（web_search 先例，重启回落全局默认=安全方向）；Run/Operation 固化授权依据（模式+指令原文+proposal 引用），跨重启接续按固化授权 + 每步重验，不回放会话档位。
- **Q18 操作历史入口与审计**：新增 GET /api/agent/runs、GET /api/agent/operations 查询；模式切换审计落轻量 agent_activity 表；设置页新增「Agent 操作历史」分区（run/operation/模式切换/清理入口）；V1 不做按对象聚合视图。
- **Q19 跨课迁移触碰面**：新领域服务 move_record_cross_course（HTTP 与 Agent 共用，活动处理 Job 进行中 409 拒绝）；不触碰 quiz 存量绑定/quiz_test_items/learning_events/learning_evidence/record_concepts（course_id 写入时固化=历史归属天然成立；record_concepts 靠读取期过滤防污染）；_bindable_concept 同课程规则仅管新绑定、不回溯存量；知识点/总结/Todo/复习资料挂 record_id 天然随走；Undo=反向迁移（存原 course_id 快照，过全部校验）。
- **Q20 动作清单与课程归档去留**：L1=课程修改（复用 CourseService.update）、条目重命名/归类/归档/恢复；L2=Record 跨课迁移、条目批量归类/归档（计划卡）；L3=Record 软删、课程软删（删除编排收拢 course 域应用函数）；Record 重命名无领域端点、登记缺口本期不做；课程归档建议随本期收口（翻案历史推迟决策，待用户拍板，备选=维持推迟）。
- **Q21 历史保留细节**：默认永久保留、无自动过期（本地优先，Undo 依赖历史）；「清理已结束任务历史」入口在操作历史页、仅终态 run 可清；清理后消息流回执卡降级为「历史已清理」占位（不删消息）；runs/operations 在 SQLite 内随全量导出/备份自动包含。
- **Q22 最小重构与模块归属**：新代码落 agent/runs/ 子包（models/service/worker/queries），operations 不动；课程删除编排收拢为 course 域应用函数（soft_delete+重算+重试一体，create_core 先例，路由换用零行为变化）；ORGANIZE 类型不迁 operations（兼容零 churn），应用器补执行前重验 + before 快照（Q12 纪律）；提案框架留 library 不动。
