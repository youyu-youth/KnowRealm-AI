# Agent 会话上下文管理 V1

Status: ready-for-agent

日期：2026-10-12。Q1～Q30 均已确认；用户明确调用 to-spec 授权将设计汇总转为本规格。测试边界沿用 Q30 已确认的公开执行链路、真实 SQLite/Worker、真实模型和真实桌面分层验收。本文件就绪表示规格可交接，不表示能力已实现，也不授权自动开工或拆票。

## Problem Statement

用户在长期对话中提出的目标、约束和决定，会随着当前固定十轮窗口裁剪而不再进入模型。原消息虽然保存在本地，Agent 没有一套可追溯摘要承接它们，也缺少受限查回压缩历史的能力。

当前初始上下文按六万字符裁剪，工具另有调用次数及部分输出字符控制。这些规则未统一检查系统提示、工具定义、材料、同轮工具结果与输出预留，不能保证完整模型请求适配实际窗口。自定义兼容端点又不能仅凭模型名推断真实能力，用户难以判断超限原因和消耗。

用户不能可靠查看本轮实际使用了哪些上下文，也无法固定重要内容、持续排除指定来源或重新开始历史承接。现有右栏窄窗会隐藏；若直接增加独立管理页面，未发送草稿还需要跨路由保留。上下文控制必须同时覆盖页面和 Agent 调用，并兼容授权、取消、后台任务和重启恢复。

## Solution

在现有 Agent 中建立会话级上下文管理：每次实际模型调用前检查完整请求预算，按需将较早对话及必要工具结果压缩为有来源的分栏摘要，保留近期完整轮次，并允许在受限范围内查回原文。

用户可固定短文本、决定或资料片段，排除轮次或资料来源，并通过重置开启新的上下文段。原数据保留，调整从下一轮生效。自动摘要不会替用户修改这些设置，不会写入学习者长期记忆，也不会构成业务执行授权。

聊天标题栏提供独立上下文管理页面入口，带当前会话进入并可切换会话，明确区分本轮实际使用与下一轮设置。页面显示预算、摘要覆盖、来源、压缩进度和恢复动作。离开聊天不取消生成，返回保留未发送草稿。状态和版本持久保存在用户原有本地数据目录，用户无需额外安装服务。

## User Stories

1. 作为用户，我希望长对话仍能承接早期目标，以便不必反复描述任务。
2. 作为用户，我希望明确约束在历史压缩后仍可追溯，以便发现遗漏时能回到原消息。
3. 作为用户，我希望近期对话尽可能保留原文，以便继续追问时保有细节。
4. 作为用户，我希望窗口由实际预算决定，以便大窗口模型不被固定十轮限制。
5. 作为用户，我希望自由聊天、资料问答和研究会话都适用管理机制，以便行为一致。
6. 作为用户，我希望不同会话内容保持隔离，以便管理一个会话不会影响其他会话。
7. 作为用户，我希望资料作用域继续有效，以便压缩或历史读取不会扩大访问范围。
8. 作为用户，我希望系统知道模型真实窗口，以便发送前发现不可容纳的输入。
9. 作为用户，我希望可信模型能力自动提供且允许覆盖，以便适配实际供应商部署。
10. 作为用户，我希望未知或自定义模型提示配置能力，以便系统不猜测窗口。
11. 作为用户，我希望区分输入额度、输出上限和总窗口，以便正确配置预算。
12. 作为用户，我希望工具定义和工具结果计入输入，以便同轮执行不会失去预算约束。
13. 作为用户，我希望看到计量精度及安全余量，以便理解估算的局限。
14. 作为用户，我希望普通回答和摘要有可调整的输出上限，以便控制消耗。
15. 作为用户，我希望接近窗口时自动压缩，以便尽量继续完成当前问题。
16. 作为用户，我希望摘要有固定栏目，以便查看目标、约束、决定、对象、未完成事项和待澄清问题。
17. 作为用户，我希望所有待压缩内容都参与处理，以便早期消息不被悄悄跳过。
18. 作为用户，我希望长历史分块压缩并显示进度，以便理解额外等待。
19. 作为用户，我希望完整处理成功才替换摘要，以便失败不损坏已有承接信息。
20. 作为用户，我希望摘要与回答分别记录调用和用量，以便评估成本。
21. 作为用户，我希望自动压缩请求数有限，以便一次发送不会无限追加模型调用。
22. 作为用户，我希望额度耗尽后保存进度并由我选择继续，以便决定是否增加消耗。
23. 作为用户，我希望固定明确约束和关键决定，以便它们不被自动裁掉。
24. 作为用户，我希望固定消息或资料片段并保留定位，以便核实其内容。
25. 作为用户，我希望固定资料对象后优先选用相关内容，以便无需强制注入整份资料。
26. 作为用户，我希望固定过多时收到可处理的超限提示，以便自行解除或调整。
27. 作为用户，我希望排除指定轮次或资料来源，以便后续组装和检索共同遵守。
28. 作为用户，我希望可恢复排除且不删除原数据，以便撤回会话设置。
29. 作为用户，我希望固定与排除冲突有明确结果，以便不会悄悄重新纳入来源。
30. 作为用户，我希望来源变化或失效时有提示，以便不继续使用过期片段。
31. 作为用户，我希望重置开启新历史段，以便停止旧对话自动影响后续回答。
32. 作为用户，我希望重置保留固定项、排除项和材料范围，以便不丢失主动设置。
33. 作为用户，我希望明确选择旧历史范围重新纳入，以便有控制地恢复承接。
34. 作为用户，我希望上下文重置不取消后台任务，以便已提交业务继续沿原执行链推进。
35. 作为用户，我希望看到未结束任务真实状态，以便重置后不误认任务从未发生。
36. 作为用户，我希望压缩后能按需查回当前段原消息，以便获得被摘要省略的细节。
37. 作为用户，我希望大工具结果可限长读取且继续读取，以便无需开放任意文件访问。
38. 作为用户，我希望取回能力遵守排除、次数及输入预算，以便不能借读取绕过限制。
39. 作为用户，我希望通过自然语言管理固定、排除和重置，以便无需强制离开聊天完成设置。
40. 作为用户，我希望这些 Agent 写操作遵循现有三档授权，以便确认和回执行为可预期。
41. 作为用户，我希望缺少目标项或历史范围时追问，以便模型不猜测修改对象。
42. 作为用户，我希望独立页面从当前聊天直接进入，以便不用重新寻找会话。
43. 作为用户，我希望在页面中切换会话并清楚识别对象，以便不会修改错会话。
44. 作为用户，我希望区分本轮实际使用与下一轮设置，以便理解修改生效时机。
45. 作为用户，我希望离开页面后生成不中断且返回可恢复观察，以便同时处理上下文设置。
46. 作为用户，我希望返回聊天时保留未发送草稿，以便页面导航不丢输入。
47. 作为用户，我希望窄窗、键盘和不同主题下都能操作，以便桌面使用不受布局限制。
48. 作为用户，我希望取消压缩后不自动续跑，以便停止请求有效。
49. 作为用户，我希望崩溃后复用已完成分块且不重置额度，以便恢复不会重复消耗或越限。
50. 作为用户，我希望迟到结果不能覆盖新设置，以便排除或重置后状态一致。
51. 作为用户，我希望摘要失败保留原消息及旧有效摘要，以便能安全恢复。
52. 作为用户，我希望真实模型超限有有限兜底，以便不会无限重试或重做业务操作。
53. 作为用户，我希望旧会话按需启用，以便升级不批量调用模型或重写历史。
54. 作为用户，我希望已受理旧轮次安全收口，以便升级不改变其输入及恢复协议。
55. 作为用户，我希望更换模型重算预算并重新检查同意，以便不沿用不适用的窗口或授权。
56. 作为用户，我希望原文覆盖、摘要遗漏和真实验证范围分别报告，以便能判断实际可靠性。

## Implementation Decisions

### 1. 范围、事实源与责任边界

- 覆盖现有全部会话模式及 FREE、RECORD、LIBRARY_ITEM、COURSE、ALL 范围；不扩展检索或授权作用域。
- 上下文业务集中在现有 Agent 模块中的领域 Service。Tool、HTTP 页面入口、模型 Middleware 与轮次执行复用该 Service，不各自复制组装、版本、排除或预算规则。
- 保留深度 Agent 主骨架、ChatTurn 执行生命周期、Run/Operation/Proposal/Job 的事实边界。Checkpoint 仅承载当轮运行态，不成为用户设置或执行审计的事实源。
- 学习者长期记忆与 Learner Context 复用既有服务和同意机制。会话摘要是派生内容，不通过普通压缩静默新增业务记忆。

### 2. 持久数据契约

| 记录 | 必要信息与约束 |
| --- | --- |
| 会话上下文状态 | 所属会话、单调递增设置版本、当前上下文段、有效摘要引用及并发更新依据 |
| 固定项 | 所属会话、类型、短文本或对象/片段引用、来源版本、有效/过期/暂停原因 |
| 排除项 | 所属会话、明确轮次或来源身份、当前是否生效；恢复不删除原数据 |
| 历史段与显式纳入范围 | 重置边界及用户选择的旧范围，使用持久有序身份而非展示行号 |
| 摘要版本 | 所属会话和段、基准设置版本、栏目内容、程序确定的覆盖范围及来源版本 |
| 压缩进度 | 关联轮次和输入身份、分块完成结果、真实请求计数、可继续原因及激活状态 |
| 轮次上下文快照 | 实际设置/摘要/策略版本、模型能力与输入恢复依据、每次请求计量和取回引用 |
| 受控输出快照 | 无领域入口可重建的工具输出，关联所属轮次/调用/来源，用于限长取回 |

上述为责任与最小信息要求，物理表拆分遵守现有存储方式，不为每个概念机械建表。全部随原本地数据目录迁移、备份和生命周期管理，业务后端仍是唯一写者。

用户设置是持久事实；摘要和选材为可重建派生状态。设置版本、输入覆盖和调用计数由程序决定，模型不能自行扩大覆盖或替代有效性校验。旧版本可服务已绑定轮次的恢复，但不能覆盖新的会话设置。

### 3. 模型能力与完整预算

- 可信能力元信息自动提供并展示来源；用户覆盖优先。配置绑定供应商端点及模型，不能因第三方沿用相同模型名就默认信任官方窗口。
- 分别解释输入上限 I、总窗口 C、供应商输出上限 M 和本次输出预留 O。未声明的约束不伪造成已知；没有可靠输入/窗口依据时要求配置。
- 普通回答默认 O 为 4096，摘要默认 1024；允许模型设置调整，按已知输出和窗口约束收紧。必要输出及输入无法共存时反馈配置/窗口不足，不擅自发起请求。
- 有 I 时输入不得超过 I；有 C 时输入加 O 不得超过 C。两者均有时取更严格限制。对上述有效输入容量预留安全余量后得到可用输入预算 B；可靠计数适配预留 10%，近似计数预留 20%，余量向上取整。
- 每次实际调用前覆盖最终模型可见系统提示、工具 schema、消息协议开销、tool calls/结果及材料。SDK tokenizer 或消息计数能力仅在适配范围内使用，不能将忽略工具 schema 的函数当作完整计数器。
- 统一闸门位于实际模型调用边界，中间件顺序必须保证检查后不再未经计量追加提示或工具；摘要模型调用执行同样规则。
- 实际输入达到 0.8B 时按需压缩，目标不超过 0.6B；无可压缩内容或目标达不到但仍不超过 B 时允许继续。超过 B 且可调整后仍无法容纳则阻止调用。
- 将输入预算和事后供应商 usage 区分展示；缺失 usage 显示未知，不填零或用估算冒充真实计费值。

### 4. 选材与完整历史

- 取消最多十轮的硬窗口。近期历史按完整用户/助手往返保留，孤立当前提问及必要工具闭环始终保护。
- 工具调用消息与对应结果保持合法配对，不截断 JSON 或业务回执制造无效输入。
- 必需规则、工具定义、当前提问、有效固定短文本/片段及当前工具闭环优先；其次为摘要和近期完整往返；材料片段及早期工具细节随后按相关性选取。
- 不因整份资料挤掉所有对话承接，也不为填满窗口加载无关材料。小材料在预算允许时仍可全文提供；超限改为复用领域检索/读取的有来源片段。
- 现有资料引用、证据与范围过滤继续生效；共享引用保持只读。会话摘要不得代替逐字原文或 Source Anchor 校验。

### 5. 有来源的增量摘要

- 固定六类栏目：用户目标、明确约束、已确认决定、相关对象和来源、未完成事项、待澄清问题。
- 输入为当前段的旧有效摘要及新增待压缩历史和必要工具结果；独立系统规则、固定块、Learner Context 和整份原始资料不重复摘要。
- 当前段待压缩原文全部参与处理，过长分块。不得沿用默认摘要件仅保留待总结消息末尾的静默裁剪；程序保存完整覆盖范围，不能把请求成功等同于全覆盖。
- 摘要输出通过栏目、来源归属和覆盖校验；覆盖事实从分块输入记录产生。摘要可表达未澄清或冲突，不将推测升级为已确认决定。
- 复用当前会话供应商及模型，不新增摘要供应商配置。摘要请求和普通回答分别记计数与用量。
- 分块结果暂存，全部完成后先检查最终摘要尺寸和来源/版本，再激活；摘要自身超预算需继续合法归并并消耗剩余额度，不能截断结构或静默跳过分块。
- 摘要覆盖并不保证语义无损；重要固定内容以独立原文保留，取回能力补足细节。

### 6. 压缩额度、失败与执行状态

| 条件 | 对外行为 |
| --- | --- |
| 未达阈值或无须压缩 | 在完整预算内正常调用 |
| 压缩执行中 | 显示处理阶段、已完成分块与请求消耗，可停止 |
| 整批成功且有效 | 原子激活新摘要，重新检查预算后继续回答 |
| 瞬时摘要错误 | 同一失败请求最多自动重试一次，消耗四次总额度 |
| 配置、同意或额度错误 | 直接反馈，不自动反复调用 |
| 摘要失败但旧输入仍安全 | 保留旧内容，显示降级并继续 |
| 摘要失败且输入不安全 | 停止本轮并保留数据，提供可操作恢复原因 |
| 四次摘要请求耗尽且未完成 | 持久保留进度，等待用户明确继续，不激活部分摘要 |
| 用户取消 | 沿既有持久取消收口，不自动继续，不激活迟到结果 |
| 主模型实际超限 | 缩减可调整内容后最多重试该次模型请求一次，不重做已提交工具 |

每次自动压缩最多四次实际摘要模型请求，包含显式及 SDK/供应商自动重试；实现必须防止底层重试绕过此计数。同一已完成分块恢复不扣新请求，真正再次出网调用需计入。请求准入在出网前持久化，不从展示事件推算消耗。

用户明确继续后每次追加同样四次请求额度，不得由 Agent 自行循环批准继续。复用现有轮次等待/继续语义，新增等待原因承载上下文压缩额度耗尽，不另造聊天执行状态机。部分失败、额度等待与取消分别呈现，不把等待伪装成完成。

### 7. 设置操作与冲突

- 固定范围限当前会话；可固定短文本、明确约束、决定、消息或片段。固定资料对象表示优先取材，正文仍受预算限制。
- 固定内容不扩大访问范围、不成为长期记忆，不自动裁去有效短文本/片段。放不下则提示用户解除或调整。
- 片段固定来源版本，原文变化标过期，用户更新或解除；对象固定按当前有效版本取材。
- 排除按轮次或资料来源身份持续生效，组装、摘要重建、检索和取回复用同一过滤规则；原数据保留，可恢复。
- 排除优先于固定。冲突固定项保留但暂停注入；恢复来源后重新检查有效性。已排除来源不能通过再次固定偷渡恢复。
- 排除只能保证可追溯来源过滤；无法声称清除其他消息中未标注来源的转述。系统规则与执行权限校验不可排除。
- 重置开启新段，旧消息可读但不自动注入或查回；清空有效摘要和旧段历史承接，保留固定、排除、材料范围及独立长期记忆。
- 重新纳入旧历史必须明确选择范围，按新设置版本生效且仍遵守排除；不默认恢复全部旧段。
- 固定、解除、排除、恢复、重置和旧历史纳入均从下一轮生效。当前轮不会被页面变更静默改写；立即改变须先停止当前轮。
- 上下文变化不取消独立 Run 或既有业务写，不扩大授权；未结束任务真实状态仍可提示。

### 8. 来源有效性、取消和恢复

- 来源删除、归档或离开作用域后停止后续自动使用，相关固定项保留失效标记，摘要失效或按过滤后的原消息重建。
- 原会话挂载对象失效沿用既有拒绝发送，不能以固定或摘要让失效会话继续。
- 新轮次绑定上下文设置、段、摘要及预算策略版本；同轮恢复沿用原输入快照，当前权限与外发同意仍须校验。
- 分块和激活提交处核验轮次执行身份、持久取消、输入身份及设置版本。迟到执行者不得更新消费、进度或激活状态。
- 当前轮在旧设置快照下合法处理的内容不因此写回新会话版本；它可以用于该轮输入，但不得覆盖用户重置/排除后的有效摘要。
- 崩溃恢复可复用已提交分块和计数，输入身份或来源不再匹配时不能直接复用；失败收口保留已受理用户消息及可恢复数据。

### 9. Tool/API 契约与权限

| 能力 | 参数与校验 | 结果要求 |
| --- | --- | --- |
| 查看上下文 | 绑定当前会话；页面明确选择会话 | 状态版本、范围、摘要来源、设置、当前实际快照、下一轮预估、计量来源和错误原因 |
| 查找/读取历史 | 当前会话、段、可访问原消息/轮次身份与继续游标 | 有来源的限长结果，是否还有内容；默认不跨段 |
| 读取资料/工具输出 | 范围内来源或本会话输出身份与游标 | 预算内片段、定位、来源版本，不暴露任意本地路径 |
| 修改固定/排除 | 明确对象、动作、预期设置版本 | 新版本及有效/暂停原因，Agent 提案或直执行回执 |
| 重置/纳入旧历史 | 当前会话、预期版本、明确纳入范围 | 新段/承接范围和保留设置说明 |
| 继续压缩 | 有效等待轮次及进度身份，用户显式动作 | 可继续条件与追加额度；不扩大原业务授权 |

- API 和 Agent Tools 调用同一领域 Service；Schema 和类型走既有 OpenAPI 生成链，不由前端维护另一套业务类型。
- Agent 运行时绑定会话及作用域，参数不能跨会话读取输出或修改设置。缺少目标/范围时追问，模型提示不替代执行端归属校验。
- 设置修改属于单会话可恢复 L1，复用现有 OperationSpec、三档分流、Proposal、领域执行和回执；默认档等待确认，其他档位按现有 L1 规则执行。
- 页面显式设置动作表达用户授权，与 Agent 路径复用 Service、版本校验和结果记录，不要求先通过聊天转发。
- 确认绑定目标、参数及版本，过期提案拒绝执行；提交处检查取消、执行身份、当前授权，不能仅依靠工具调用前 Middleware。
- 自动压缩只维护派生状态，不生成或修改用户设置，不从摘要中的“已同意”推导授权。
- 模型可执行读取计入现有共享工具次数及完整请求预算；历史消息查看等普通页面只读查询不占 Agent 调用次数。

### 10. 超大工具结果与框架复用

- 优先通过既有领域查询重建资料或业务事实；不可重建临时输出保留受控快照，来源和调用身份不能丢失。
- 使用公开配置关闭当前文件卸载后无可见读取入口的行为；不开放框架任意文件、Shell 或 SQL 工具。
- 新读取能力具备游标/范围限长与耗尽提示，返回内容仍受完整输入预算；不得以文件指针替代不可取回正文。
- 使用现有公开 Middleware 接缝、模型计数及工具合法切点，不复制 Agent 循环、不更改 SDK 私有状态结构。
- 压缩前后的系统提示注入通道保持正确，最终请求与预算计量一致。默认件的触发行为不能替代产品全覆盖与激活校验。
- 原工具次数、字符消费、业务提交预算与幂等回执保留；上下文选材是模型可见投影，不反向改写业务结果或消费事实。

### 11. 独立页面与事件投影

- 聊天标题栏入口带当前会话进入独立路由；页面可切换会话，有明确返回聊天动作，不增加侧栏一级入口，不以右栏/Sheet 作为管理主体。
- 页面显示概要、本轮实际使用、下一轮设置及按需详情。实际快照必须有轮次和版本；下一轮输入是预估，不能伪装成已发送。
- 概要包含材料范围、能力与计量来源、输入占用、输出预留、安全余量、压缩阶段；详情显示摘要栏目、来源覆盖、固定/排除原因、分块和摘要用量。
- 复用轮次持久事件与公开快照呈现受理、压缩、等待、取消、失败和完成；SSE 只通知，断线或页面返回能够查询恢复，不能仅存在客户端内存。
- 固定超限、未知窗口、来源过期、排除冲突、额度耗尽均给出准确原因和恢复动作；避免按钮显示成功而后端状态未提交。
- 离开聊天只关闭订阅，不取消生成。按会话保留未发送草稿，返回正确会话时恢复；不得将草稿放 URL、上传模型或混到另一会话。
- 保留原聊天右栏现有功能，不顺带实现其示意工具开关。独立页面适配窄窗、所有已支持主题、键盘、zh/en 和 reduced-motion。
- 复用现有 UI 组件及设计语义令牌，局部滚动、焦点回归、错误和禁用状态完整；不改权威设计风格或添加新品牌色。

### 12. 升级、生命周期与文档边界

- 迁移只建立所需结构和兼容字段，遵守既有迁移规范；不在启动事务中调用模型、摘要全库或重写历史。旧会话下次发送按需初始化。
- 升级前已受理非终态轮次保持原协议。若无法安全提供原运行兼容性，走既有兼容等待及停止后新问路径，不能伪造零预算或用新规则强行恢复。
- 更换模型重新计算窗口和输出预算，保留仍有效摘要和用户设置；同意按现有供应商变更规则重验。
- 派生内容和临时输出关联会话生命周期，删除或失效会话无法通过取回 API 访问；终态清理不能删掉仍被有效摘要、取回或恢复引用的数据。
- 不额外记录完整提示、材料或记忆正文到日志。用量、策略、版本及失败元数据沿既有日志/观测能力。
- 新错误码同步既有错误清单和双语；API 契约、类型和过程投影相应更新。
- 本规格显式提出替代 ADR-0018 的默认摘要禁用及既有轮初裁剪策略，同时保持其主骨架、公开 API 和长期记忆边界；ADR-0025、ADR-0026 的记忆/同意/授权继续有效。
- 新 ADR 和术语表增补需按仓库流程先提供具体提案并获得批准，本次只发布本地规格，不擅自修改权威文档。

## Testing Decisions

主要 seam 是用户已经确认的公开 ChatTurn 提交/等待/继续/取消/恢复和受控操作链，配真实迁移 SQLite 与原 Worker；模型可见输入由受控模型替身观察。既有领域检索和会话 HTTP 入口验证范围与设置，前端通过公开 API 验证独立页面闭环。不为各内部函数建立一套全新的测试体系。

优先复用现有 Chat 流式及上下文、ChatTurn 恢复/事件/效果、工具预算、Learner Memory、资料检索、授权/Operation 与前端聊天导航测试的工厂和故障注入。只在新增行为没有覆盖时补必要测试；不补无关历史覆盖，不用断言代码结构代替用户行为。

Q30 已确认这些测试边界；本轮不新增访谈或要求用户重新决定内部测试实现。

| 编号 | 可验收外部结果 |
| --- | --- |
| C01 | 窗口及输出能力正确绑定供应商/模型，未知配置明确反馈，模型更换不复用错误能力或同意 |
| C02 | 系统提示、工具定义、协议开销、材料和同轮结果均参与完整计量；检查后无未计量追加 |
| C03 | 80%/60% 阈值、10%/20% 余量及默认输出额度边界正确；不可容纳必需项时无实际模型请求 |
| C04 | 十轮以上按实际预算保留，当前提问不丢；工具调用/结果合法配对、业务 JSON 与回执完整 |
| C05 | 原文待压缩范围全覆盖，早期约束参与；栏目及来源归属校验，摘要不充当资料引用或授权 |
| C06 | 分块未完成不激活；最终摘要过大合法归并，所有请求/重试计入额度，崩溃不归零 |
| C07 | 四次上限、一次瞬时重试、明确继续追加额度与主模型一次超限兜底无隐藏重试或重复业务写 |
| C08 | 摘要失败保留原内容，安全时降级继续、不安全时停止；等待、失败、取消状态可区分 |
| C09 | 固定优先、不自动裁去；过多阻止调用，来源变化/删除/归档/越界正确失效 |
| C10 | 排除约束组装、摘要、检索与取回，冲突固定暂停；恢复和重新固定不绕过排除 |
| C11 | 重置不删除消息，保留固定/排除/范围，旧段不自动查回；显式纳入仍受排除和权限约束 |
| C12 | 页面调整只对下一轮生效，本轮恢复使用原快照；旧版本摘要不覆盖新会话状态 |
| C13 | 取消、claim 变化、重置/排除及来源失效竞态阻止迟到计数、进度和激活提交 |
| C14 | 三档 L1 分流、默认确认卡、过期版本拒绝及提交处权限校验完整；普通摘要无设置写操作 |
| C15 | 历史和输出取回限制会话/段/归属/来源/游标，计数与预算有效，不可读取任意文件 |
| C16 | 已受理用户消息、压缩过程和等待原因及时可查；事件重放与断线不改变执行事实 |
| C17 | 独立页面正确会话进出/切换，实际快照与预估清楚，草稿保留、生成继续、返回恢复观察 |
| C18 | 旧会话按需初始化，升级不出网、不重写历史；旧活跃轮次兼容收口、回执与独立 Run 保留 |
| C19 | 关闭记忆外发不重新注入独立记忆块，供应商同意失效拒绝出网；日志无新增完整正文泄漏 |
| C20 | 派生摘要及输出的备份/迁移/删除可访问性正确，必要恢复数据不提前清理 |

自动化先完成相关现有回归与必要新增覆盖，类型、规范及 OpenAPI 门禁按触及范围执行。真实 SQLite/Worker 证明事务和恢复；网络、模型和故障替身明确标注，不冒充真实服务。

真实模型验收至少一条超过三十轮的会话及分块场景，覆盖首轮固定约束、普通摘要承接、原消息取回和超限处理。分别记录输入覆盖与语义遗漏、压缩前后占用、请求次数、供应商实际用量及耗时；模型数据与外发范围须经现有同意机制。

真实 Tauri/WebView2 验收独立页面往返、草稿、生成/取消/等待、窄窗、所有支持主题、键盘及 reduced-motion。覆盖 Windows 125%/150% 缩放及 200% 放大下的可达性；记录实际系统缩放、CSS viewport 和 DPR，浏览器模拟不代替系统缩放验收。

规格发布阶段不执行模型计费请求或运行验收；实现交付报告必须分别列自动化、替身、真实 API/SQLite/Worker、真实模型及真实桌面范围和未验证项。

## Out of Scope

- 跨会话共享上下文、全局记忆库、静默从聊天新增学习者长期记忆。
- 通用 Agent 平台重写、框架升级、独立模型供应商或摘要专用服务。
- 任意文件/Shell/SQL 权限、扩大资料范围、摘要授权或取消已有后台业务的快捷通道。
- 手动编辑完整模型 Prompt、任意修改系统规则、无来源摘要充当逐字引用。
- 新建侧栏一级入口、用右栏/Sheet 替代独立管理页面、聊天示意工具开关实现。
- 全库升级时摘要、历史消息重写、扩大无关测试覆盖或清理相邻代码。
- 修改编码规范、未经批准修改权威 ADR/术语/设计文档。
- 本次自动拆工单、提交代码或开始实现。
