基点：`d6f48a8`，分支 `feat/extend-dev-09`。已阅读 04 提交 `7eac5d94630807044550b7fbb5ded0f1107b6134` 及实施记录；本票沿用其固定项、版本 CAS、OperationSpec、三档授权、原轮快照和来源重验。用户已有 `.scratch/agent-context/baseline/` 不改动。

## 实现

- 0050 仅增加 DDL：会话状态和轮次输入各保存 `rules_json`。规则包含排除轮次、排除资料身份及明确纳入旧轮；新段由已有 segment 持久承载。迁移不重写消息、不调用模型。
- 页面 POST `/api/chat-sessions/{id}/context/rules` 与 Agent `change_context_rules` 共用 `change_rules_core`；页面记 USER_MANUAL 回执，Agent 复用可恢复 L1、默认确认卡及 AUTO_APPROVE/FULL_ACCESS 直执行。确认绑定参数、会话、来源版本及设置版本，提交处沿原执行身份、取消和授权检查。
- 用户通过历史轮次列表选择排除/恢复或逐轮纳入；Agent `list_context_history` 仅枚举身份、段、状态，不把旧段正文或标题提供给模型。未明确范围必须追问，缺范围/跨会话/未完成或非旧段的纳入拒绝。
- 没有 ChatTurn 的升级前原消息按用户/助手往返生成 `legacy:<用户消息身份>` 的只读选择身份，仍属第 1 段；不补写或修改原消息。它们可以排除、恢复、明确纳入。
- 排除优先于固定与纳入。冲突固定项保留并显示 EXCLUDED，恢复后重验正文/版本/范围；再次固定不会修改排除规则。重置保留固定、排除、材料范围、长期记忆和授权，清空摘要指针及旧历史纳入范围，不取消独立 Run。
- 新轮受理时冻结规则，初始组装、模型边界、资料检索、历史/工具输出读取及摘要提交沿该快照。页面查询使用当前版本，显示实际绑定段/规则与下一轮规则的区别。旧轮合法派生摘要只能服务旧轮，不能激活到新的设置版本。
- 摘要设置变化后重建；已保存分块仍遵守执行 claim、取消及来源重验，迟到结果不激活新段。资料排除过滤正文、已标记引用及检索导航；历史检索/读取、固定载荷和工具输出递归重验来源，保留合法工具调用配对与持久回执。
- 排除挂载记录仍保留空材料容器，确保系统指引、独立课程记忆及任务提示不会因正文为空而丢失；开关关闭时记忆仍零注入。导航标题重验复用既有导航 SQL 范围，标题可见不扩大正文读取权限。
- 有引用身份的普通历史回答在初始组装和恢复后的模型边界重验；存在失效引用时回答正文仅投影为暂停提示，合法引用独立重验后仍可提供原文摘录，持久消息保持不变。无法清除没有来源标记的转述，页面和 Tool 均说明该边界。
- 独立页面沿现有 shadcn、语义主题和局部滚动结构扩展；历史分页走 URL，规则/确认后失效上下文、历史、原文与回执查询。重置弹窗固定打开时的版本并恢复键盘焦点；失败不显示成功。
- 同步 OpenAPI/TS、两项错误码及 zh/en；历史状态复用 ChatTurnStatus。图协议升为 v6，旧在途图按既有兼容等待/停止后新问路径收口。

## 验证路径与数据

1. 公开 ChatTurn 提交 → 真实 JobRunner/Worker → 轮次快照/模型请求 → 页面规则提交 → 后续组装/摘要及公开来源读取。模型仅在供应商边界替换，SQLAlchemy、迁移 SQLite、受控操作和消费事实使用生产实现。
2. 首轮独有文本固定为消息片段 → 排除其轮次（固定暂停、读取拒绝）→ 重置新段 → 明确纳入该旧轮（排除仍优先）→ 恢复排除 → 下一轮模型输入重新包含选定旧轮，不包含其他旧轮；原消息全部保留。
3. RECORD/COURSE 语料复用 `test_shared_refs.seed_full_corpus`；排除资料后检索、固定和原文取回共同停止；来源版本变化时旧引用回答与工具缓存不再回喂，原数据不删除。
4. 摘要请求挂起时交错重置/排除/取消，查询分块进度、实际原轮快照与会话有效摘要；重开应用 lifespan/Worker 后检查段、排除、旧轮纳入和独立 WAITING_USER Run 的 SQLite 事实。
