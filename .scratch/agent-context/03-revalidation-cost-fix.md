# 03 原文重验证成本修复

核实日期：2026-10-13。

## 事实与改动

- `InputBudgetMiddleware` 在 compact 前逐条重验证历史只读结果，此位置保留，避免摘要覆盖已失效来源。
- 真实 SQLite 调用计数复现：12 条 search_library 各含两个同源命中，加 read_context 与另一条摘录，原实现加载同一资料 26 次；修复后同一校验批次加载 1 次。
- read_context 原消息/持久输出改为按 ID 查询，保留原会话、段与来源版本边界；两条原消息只加载两条正文。
- 旧工具原文回退从全量 ORM 快照加载改为逐个读取、命中停止；本批次复用工具消息索引并按时间及 ID 续扫，每个请求快照最多反序列化一次。
- 验证结果按来源、预期版本和摘录复用；不同摘录仍分别验证，正文读取及来源不可用结果也在本批次复用。

## 缓存边界

缓存仅属于一次 validate_read_results，下一次模型请求重新读取数据库。没有跨请求缓存，也不回写历史工具消息、回执或消费账本。共享关系移除、删除或归档不一定改变正文版本，不能仅凭正文版本长期复用可见性校验。

未知旧来源仍可能需要扫描全部候选快照；本改动消除同批次重复读取与反序列化，没有新增历史索引或数据库迁移。
