# 06: 升级回归与真实链路验收

**What to build:** 用户升级后可在旧会话中安全使用完整上下文管理，原在途轮次、资料与后台任务保持正确；真实模型和真实桌面能完成整套管理流程，交付记录准确区分实现、自动化、替身及真实证据。

**Blocked by:** 05 — 排除、重置与旧历史纳入。

**Status:** ready-for-agent

依据：[规格](../spec.md)的实施决策 8、11～12 和 Testing Decisions；完整核对 C01～C20，重点负责 C18/C20 组合生命周期及真实模型、Tauri/WebView2 验收。

## 交付边界

这是完整用户链路的发布验收票，不是把前五票的取消、恢复或权限实现延期到此。复用各票证据并开展必要组合回归；发现真实相关缺陷在对应边界修复并复验，不借机修无关基线债务或扩大测试体系。

## 验收清单

- [ ] C01～C20 均有对应功能票的实现与有效验证记录，跨票组合通过；无以模拟结果、disabled 按钮或客户端缓存冒充真实管理能力。
- [ ] 旧会话升级不批量模型调用、不重写消息，按需初始化；旧活跃轮次可按原协议安全收口或进入既有兼容等待，不改原输入、消费或执行事实。
- [ ] 更换端点/模型重算窗口和输出额度，同意按既有规则重新校验；已有有效摘要/设置保留，不静默扩大权限。
- [ ] 会话删除、资料归档/删除/移出范围、备份/迁移与恢复交错后，派生摘要及输出不能越界访问，也不提前清理有效取回/活跃恢复所需数据。
- [ ] 独立页面进出、切换会话、未发送草稿、等待继续、取消和后台生成组合流程成立；REST/事件断线恢复不丢事实、重扣额度或重做业务操作。
- [ ] 真实 API/SQLite/Worker 完成压缩准入、分块、激活、版本、取消与 claim 交错验收；模型/网络替身和故障注入单独标识，不能冒充真实服务。
- [ ] 真实模型至少一条超过三十轮的会话及分块场景，覆盖首轮固定约束、普通摘要承接、原消息取回、排除/重置和超限处理；记录全输入覆盖与语义遗漏的区别。
- [ ] 记录压缩前后占用、实际请求/重试次数、摘要与回答独立供应商用量和耗时；供应商缺 usage 标未知，真实外发沿现有同意，不泄漏正文至日志。
- [ ] 真实 Tauri/WebView2 验证所有支持主题、窄窗、鼠标/键盘、焦点、错误恢复和 reduced-motion；Windows 125%/150% 系统缩放及 200% 放大下主要动作可达，记录 CSS viewport、DPR 与实际系统缩放。
- [ ] 相关现有测试、必要新增覆盖、触及类型/规范/OpenAPI、错误码和双语防线通过；既有基线失败单独登记，不以无关失败或历史测试绿灯代替本链路证据。
- [ ] 提交新增上下文 ADR 及四类术语的具体可审阅提案，明确与 ADR-0018 的阶段性差异并保持 ADR-0025/0026；批准前不修改权威文档，不更改编码规范。
- [ ] 用户批准的文档提案才落盘；未经批准部分标明待批。项目进度和交接保留准确状态，规格、工单与真实能力一致，进度总览始终小于 200 行。
- [ ] 每项证据注明自动化、替身、真实 API/SQLite/Worker、真实模型或真实 Tauri 范围；未完成真实项不代勾，不能把本票或整个功能标为已完整真实验收。

## 完成证据

汇总前五票验收及本票组合/真实记录，给出可重现输入、会话和版本身份、计数与结果，不记录不必要敏感正文。真实验收需用户操作或环境仍不具备时明确保留待验收状态，不用测试替身关闭该项。
