# 02: 自动摘要、额度与持久恢复

**What to build:** 用户在长对话中继续发送问题时，系统按预算将早期历史压缩为可追溯分栏摘要，展示进度与独立用量；取消、错误、额度等待及重启后保留正确内容和进度，不跳过历史或重复业务执行。

**Blocked by:** 01 — 模型预算与独立页面查看。

**Status:** in-progress

依据：[规格](../spec.md)的实施决策 3～6、8、11；主要覆盖 C03 的阈值、C04～C08、C13 的取消/身份校验、C16；延伸 C12/C17/C19。

## 交付边界

依赖 01 的能力、输入闸门、轮次快照和独立页面，交付自动压缩到继续回答的真实路径。复用框架公开中间件接缝、工具安全切点和原 ChatTurn 等待/继续/取消，不另建执行状态机。分块、计数、激活及恢复在本票内完整实现，不能推给 06。

## 验收清单

- [x] 取消固定十轮硬窗口，按预算保留近期完整往返；输入达到可用预算 80% 才压缩，目标 60%，目标不能达到但仍安全可继续，无合法空间则明确阻止调用。（06 已修小窗口预留误拒绝和实际累计摘要重新分块；覆盖片段完整拼接、计次与安全准入由生产 API/SQLite/Worker＋模型替身验证，真实五块另见 06。）
- [x] 摘要固定六类栏目，输入覆盖当前段全部待压缩原文及必要工具结果；采用旧有效摘要加增量内容，过长分块，不沿用默认摘要的静默尾部裁剪。
- [x] 原消息保留，程序记录覆盖范围和来源；栏目、来源归属及输出结构校验有效，模型不能扩大有效范围、把推测升级为决定或生成执行许可。
- [x] 系统规则、固定块、独立 Learner Context 和整份原始资料不重复进入摘要；摘要不作为逐字证据或长期学习者记忆。
- [x] 摘要复用当前供应商/模型及现有外发同意，独立输入预算和输出上限生效；最终摘要过大则在剩余额度内合法归并，不能截断结构或丢分块。（供应商格式兼容：真实 SDK＋HTTP 替身验证 json_schema 拒绝后降级 json_object，逐次计量/扣额度，恢复沿用降级格式；真实供应商语义/成本仍归 06。）
- [x] 一次自动压缩最多四次实际摘要请求，含 SDK/供应商自动重试；准入在出网前持久化，恢复不归零，不从展示事件反推计数。
- [x] 四次耗尽未完成则保存进度并进入可查询的等待原因；用户明确继续每次追加四次，Agent 不自批；未覆盖全部材料不激活摘要。（并发继续按等待快照在同事务中条件领取并追加额度；迟到请求不自动为后续新等待追加额度，取消先提交后不复活。）
- [x] 分块结果可复用但整批成功、来源/版本/输入身份有效才原子激活，之后完整重新计量再回答；部分失败保留原有效摘要及消息。
- [x] 瞬时摘要错误最多自动重试一次并计入总额度；配置/同意/额度错误不盲重试。失败时安全可降级继续，非安全停止并保留恢复信息。
- [x] 主模型真实超限最多缩减可调整内容后重试该次请求一次，不删除有效固定内容、不重放已提交工具或重置原工具预算。（06 已修明确兼容超限文案，真实 SDK＋HTTP 替身覆盖标准/百炼超限及普通参数错误不重试、已提交业务不重放；真实供应商超限未触发，该真实项仍待 06。）
- [x] 取消、claim 变化和重启故障窗口下，提交处校验身份和持久取消，迟到结果不能写计数、进度或激活；同轮恢复沿原输入，真正再次出网计入消耗。
- [x] 用户消息受理及时可见，聊天过程与独立页面显示压缩、分块、用量、等待、取消、失败和完成；REST 快照可恢复，SSE 重放不改变事实。（旧摘要按所属轮次读取额度/累计次数；单批次数与所属轮次累计/额度分开显示。API/SQLite 投影、组件双语及浏览器模拟通过，真实 Tauri 仍待 06。）
- [x] 真实 SQLite/Worker 验证请求准入、分块提交、激活前后崩溃及取消窗口；公开执行链与受控模型替身验证十轮以上历史、四次限额、工具配对、有限兜底和无重复业务写，相关类型及契约门禁通过。
