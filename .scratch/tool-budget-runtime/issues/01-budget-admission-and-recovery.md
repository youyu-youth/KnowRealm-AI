# 01：统一工具预算准入、持久消费与恢复

**What to build:** 同一 ChatTurn 的查询、生成、等待和联网调用使用一致的 6 次预算；已准入的参数错误/失败计数，同逻辑调用恢复不重扣，字符消费跨恢复累计。预算执行和持久恢复收拢到一个 module，原工具挂载、业务授权、结果结构及独立 5 次操作提交预算保持。

**Blocked by:** None（Operation 重构已交付；不依赖能力 catalog、结果投影重构或草案 Job 身份问题修复）。

**Status:** done（代码与本票自动化验收完成；全量基线失败及真实模型/Tauri 未验收见实施记录）

**Parent:** [工具预算执行与恢复闭环](../spec.md)

日期：2026-10-12。用户调用 implement 授权实施；16 项工具准入、持久消费和恢复已交付。最终预算/ChatTurn 74 项通过，分组全量 1191 通过、2 个既有失败已在原始基点复现。证据见 [implementation.md](../implementation.md)。

## 交付范围

一张工单完成持久准入、Middleware 接入、全部计数工具迁移、字符计量及 ChatTurn 恢复的完整闭环。必要预算记录 DDL 属于票内；优先复用既有持久化，但不能以简单内存累计或展示事件统计替代原子消费事实。

本票允许且要求改变参数错误扣数、等待恢复口径、字符恢复归零和 web_search 不计数的现状；其余行为按父规格保留。不得将 Operation 注册动作、模型工具、计数工具和回执投影名单当作同一集合。

## 实施顺序

1. 复核当前计数集合及字段计量分支，记录相关基线、直接调用/框架调用的差异和现有取消/身份/清理接线。
2. 实现一个内聚预算 module：策略声明、稳定调用准入、并发原子消费、持久字符计量和恢复；所选最小存储满足身份唯一与生命周期要求。
3. 接入既有 Middleware 和 16 项计数工具，迁移等待预算职责；保留工具领域判断、结构化拒绝载荷、裁剪 adapter 与业务最终 guard。
4. 完成恢复、事件压缩与升级兼容接线，通过真实迁移库/框架/Worker 验证，再审查调用方编排是否减少并记录实施结果。

## 验收标准

- [x] **B01**：预算策略声明一次，执行与恢复同源；无每工具重复准入/递增或恢复名单手工同步。职责对照体现 Depth。
- [x] **B02**：参数结构/语义错误、缺配置、不存在目标和执行失败均按已准入逻辑调用扣一次；未知/未挂载/无上下文/超限/取消身份拒绝不新增消费。
- [x] **B03**：6 个名额正确执法；不同调用并发争最后一个名额不超卖；同身份并发不重复扣。
- [x] **B04**：准入提交后、工具执行前中断，恢复仍能沿同身份接续；额度满时旧身份可继续、新身份拒绝；身份工具/参数冲突拒绝。
- [x] **B05**：wait_for_task 新调用先准入，无效引用计数；已有等待接续不重扣；超限不新建等待、绑定或投递任务。
- [x] **B06**：业务提交后/保存 checkpoint 前重放，仍复用原 Proposal/Operation/Run/Job/Undo 回执，不重复副作用；5 次提交预算与 effect 协议保持。
- [x] **B07**：实际字符计量持久化在模型消费前；重启后不归零；已恢复输出不重复计量，新产出按实际累计；覆盖与 checkpoint 提交交错。
- [x] **B08**：检索沿原结构裁剪和提示；原单次 4,000/累计 12,000 参数保持；计划 JSON、操作回执及任务结果完整，不新增统一字符串截断。
- [x] **B09**：web_search 纳入共享 6 次，超限时真实请求次数不增加；原错误语义、重试提示和单轮熔断保持。
- [x] **B10**：恢复不再靠展示事件估算新策略次数/字符；事件重复、补发、压缩不影响消费，旧 worker 迟到不能改计量。
- [x] **B11**：版本固化及旧非终态轮次兼容明确；无新事实的旧轮次不按零额度恢复。无法证明安全兼容时使用原等待/停止/新问路径；保存内容、回执和独立 Run 保留。
- [x] **B12**：工具挂载、公开 payload/SSE/回执、领域校验与事务最终授权/取消 guard 保持，非计数工具及原独立限额不被顺带改变。
- [x] 若需要新增预算存储，DDL/真实升级链/唯一约束/活跃记录保护/终态清理全部验证；不增加无需求存储字段或完整参数/结果副本。
- [x] 运行相关既有测试、触及代码规范/类型及契约检查；仅为本次明确行为变化补必要覆盖。相关基线失败单列，不删无关断言或借机修复。
- [x] 给出执行前后职责与故障窗口证据，区分自动化、替身、真实 SQLite/API/Worker、真实模型/Tauri；未验证项不代勾，完成后同步项目进度。

## 验收证据要求

通过原公开 ChatTurn 和真实框架工具执行，核对持久消费、等待、业务结果与实际模型/网络调用次数。直接工具入口测试继续保留，但不能单独证明 Middleware 计数生效。

至少覆盖：第 6/7 调用、参数错误与执行失败、最后名额并发、同逻辑身份重放、等待前后恢复、消费提交后执行前中断、业务已提交而 checkpoint 未保存、字符计量跨重启和事件压缩。网络与模型可用受控替身；数据库消费、取消身份和恢复不能只用 mock。

升级前存在 QUEUED/RUNNING/WAITING_JOB/WAITING_USER 旧轮次的场景单独记录；原字段缺失不补造精确历史消费。公开结果形状与非计数能力的行为回归必须同时通过，不能只验预算 helper。
