# 工具预算执行与恢复闭环

Status: done（代码与本票自动化验收完成；验证范围见 implementation.md）

日期：2026-10-12。基线：`c43e3954467f92e16771965f01b522183dc65568`。

用户已确认 Q1～Q5 全部按推荐：仅收拢预算；纳入预算的已知工具进入处理即扣数，参数错误与失败计数；同一逻辑调用只扣一次；字符消耗跨原 ChatTurn 累计；web_search 纳入共享 6 次。写操作提交预算仍独立为 5 次。用户本轮调用 implement 授权实施；当前已实现，最终验收范围见 [implementation.md](implementation.md)。

## Problem Statement

工具内部各自检查并递增预算，运行时另维护工具名单，恢复又根据展示事件重新计数。空检索词和无效资料类型目前不扣数，无效时区及缺少模型配置则扣数；恢复只看到调用事件，不能准确重建这些区别。后台等待重放也存在执行与事件计数口径不同的问题。

字符累计恢复归零、联网搜索未计入共享次数，使同一问题在首次执行和续跑时受到不同约束。维护者接入工具时需要理解多个平行维护点，单纯移动计数代码无法解决恢复一致性。

## Solution

建立内聚的预算 module，在现有 Middleware seam 后集中准入、消费和恢复规则。工具通过小 interface 声明真实预算维度，保留类型化工具、原结果形状和必要的结果裁剪 adapter。用户继续通过原对话入口执行任务，恢复不重置额度，超限时收到可解释的工具结果，模型仍可基于已有信息回答。

Depth 体现在调用方不再掌握重复的预算检查、扣数与恢复顺序；Locality 集中在预算 implementation，Leverage 覆盖普通查询、生成、等待和联网调用。挂载、预算、回执投影是不同维度，本票不创建通用能力 catalog。

## User Stories

1. 作为用户，我希望同一问题的首次执行、后台接续和重启恢复遵循同一预算，以便行为可预期。
2. 作为用户，我希望工具参数错误与执行失败按一致规则计数，以便工具循环不会绕过限制。
3. 作为用户，我希望恢复同一逻辑调用不再次扣数，以便已经消耗过的额度不会重复扣减。
4. 作为用户，我希望成功业务重放仍返回原对象和回执，以便不会重复创建数据或投递任务。
5. 作为用户，我希望联网搜索也有调用次数约束，以便不会在共享额度之外持续出网。
6. 作为用户，我希望恢复后检索仍受原累计字符消耗约束，以便重启不获得新的检索输出额度。
7. 作为用户，我希望结构化计划、操作回执及任务结果保持完整，以便预算控制不破坏后续执行。
8. 作为维护者，我希望新增计数工具只声明一次预算策略，执行和恢复共用该声明，以便无需同步多套计数规则。
9. 作为维护者，我希望预算记录与展示事件分离，以便过程展示、压缩或断线补发不改变执行额度。

## Implementation Decisions

### 已确认的行为取舍

| 决策 | 本次交付 |
|---|---|
| Q1 范围 | 只完成预算执行与恢复；能力挂载、结果投影及领域执行规则保持 |
| Q2 扣数时点 | 已知、纳入预算的工具在有效运行上下文中获准进入工具处理时扣一次；参数校验错误、目标不存在、配置缺失、执行失败均不退还 |
| Q3 恢复身份 | 同一逻辑调用只扣一次；等待接续和恢复重放不重复扣；新逻辑身份正常扣；成功业务重放返回原回执 |
| Q4 字符恢复 | 按原计量范围跨同一 ChatTurn 累计，不在恢复时归零；不对所有工具施加统一字符串截断 |
| Q5 联网 | web_search 与当前查询/生成/等待工具共用每轮 6 次；原联网熔断、错误分类和重试提示保留 |

1. **三维预算分立**：共享调用次数、既有回喂字符计量、操作提交次数分别表达不同事实。6 次限制不扩大到全部写工具；5 次是原提交预算，不改成按 Run 步骤数计数。记忆、研究入库等原特殊限额保持。
2. **计数集合**：共享次数包含当前 15 项及新增 web_search：convert_time、diff_datetime、generate_learning_plan、get_current_time、get_goal、get_plan、list_course_records、list_goals、list_library_items、list_shared_refs、regenerate_plan、search_courses、search_library、shift_datetime、wait_for_task、web_search。工具挂载仍按原模式和范围决定，列入计数集合不使工具自动可见。
3. **准入先于处理**：Middleware 在已有逻辑身份绑定后，对已知且实际可调用的工具进行预算准入，再进入工具参数/领域处理；结构错误和语义错误都属于已准入调用的失败。未知或未挂载工具、无有效运行上下文、预算超限、取消/领取身份失效拒绝不新增消费。预算拒绝不调用领域查询、LLM、网络或 prepare_wait。
4. **稳定消费身份**：复用 ChatTurn 归属、graph namespace 和 logical_call_id；attempt、重启、等待接续及展示事件序号不成为新消费身份。工具名与参数指纹用于校验身份一致性；同身份换工具/参数不能绕过预算。没有持久身份的直接工具测试使用受同一策略约束的临时计数，不宣称该路径可跨重启恢复。
5. **持久准入**：新消费事实与是否获准处理在工具执行前原子落定，再允许 handler 执行；占用成功但尚未执行就中断，续跑复用占用，不重复扣。并发的不同调用不能超卖最后一个名额，同身份并发不能产生两份扣数。持久更新验证当前领取身份与取消状态；预算记录不构成业务授权，业务提交事务的最终 guard 保留。
6. **存储职责**：预算事实只保存恢复所需身份、策略版本、参数指纹和数值，不额外存完整敏感参数/结果，不把业务成功写入预算状态。优先复用现有 ChatTurn 持久化能力；无法满足原子准入、身份唯一和独立清理时，最小预算记录表及 DDL 迁移属于本票必要范围。存储选择由实施依据真实约束决定，不能另造任务或账本平台。
7. **消费与恢复同源**：恢复读取实际准入及字符计量事实，不从 tool_call/tool_result 展示内容估算新策略消耗。事件重复、补发、压缩或清理不影响预算。操作提交次数继续复用原注册表/effect 恢复口径，包括原 PLANNED 残留的保守统计，不借本票改变该维度算法或合并账本。
8. **重放不等于缓存**：同逻辑调用已准入时，即使额度已满仍允许安全接续；不重扣调用次数。普通只读工具是否重新读取沿原框架行为，不因去重预算新增通用结果缓存。写操作继续在原受控入口 prepare/complete effect；已成功业务重放优先返回原回执，不重新执行领域副作用。
9. **字符计量**：当前会累计 chars_fed 的工具与返回分支保持原范围，联网只新增次数计数，不顺带纳入字符计量。按实际模型可见序列化结果计量；只恢复上下文/重放同一已记录输出不重复增加，重新执行产生并实际纳入上下文的新输出如实累计。计量须在输出交给后续模型前持久化；不能仅在回答完成时保存。计量采用独立输出事实身份区分已恢复输出和新产出，不能靠字符串展示摘要推算。
10. **裁剪保持**：search_library 沿原结果结构裁剪，单次 4,000、累计 12,000 字符参数不变；累计额度由恢复后的数值约束。现有提示/结构固定开销与不可裁剪内容按原规则处理，不把 12,000 宣称为全部工具结果或全部模型上下文的硬上限。计划 JSON、操作回执、任务结果不能通用切字符串；时间/列表等原有对象数量和字段限制保持。
11. **超限反馈**：保留工具各自的结果形状及可解释提示，由少量明确 adapter 提供原拒绝载荷，不能让每个工具再次自行检查和扣数。web_search 超限返回原 hits/ok/error_code/retryable 形状，明确不再出网；超限不强制整轮终止，不新增页面或 SSE 类型。若公共文案/错误码确有新增，按现有契约链同步登记和双语。
12. **特殊工具**：wait_for_task 的引用校验、等待持久化、interrupt 和结果恢复保留；只移出预算职责，新逻辑调用的无效引用也消耗一次准入，已登记等待接续不再扣。regenerate_plan 同时使用调用及操作提交维度，不强行归为互斥工具类别，不改变生成/授权/业务幂等协议。联网供应商内部一次搜索的重试仍属原调用，不新增全局重试机制。
13. **框架复用**：使用现有异步 Middleware seam 和逻辑身份接线；官方 ToolCallLimitMiddleware 的 invocation/thread 计数不能直接代替产品持久准入协议。不引入新依赖、不关闭全部并行调用以掩盖竞态，不改变 checkpoint 表内部结构。
14. **升级与生命周期**：新轮次固化预算策略版本；旧非终态轮次缺少精确准入/字符记录，禁止把缺席当零额度或从展示事件伪造新事实。无法证明可安全迁移时使用既有图/工具兼容性门禁等待并说明停止后新问，不盲目套新规则继续；已保存内容、Proposal/Run/Operation/Job 与回执查询保留，独立 Run 不被此兼容等待取消。终态查询不依赖预算记录；清理沿 ChatTurn 生命周期，活跃恢复所需记录不因事件压缩消失。

## Testing Decisions

测试 interface 优先使用真实框架工具调用及公开 ChatTurn 提交/恢复入口，配真实迁移 SQLite 和原 JobRunner。直接调用工具的既有用例继续验证领域行为，但不能单独证明 Middleware 准入或持久恢复。沿用现有测试工厂和故障注入，不创建通用测试体系。

| 编号 | 必须验收的结果 |
|---|---|
| B01 | 同一策略集合同时服务执行和恢复；调用方无重复检查/递增及手工恢复名单 |
| B02 | 空检索词、无效类型/时区、框架参数错误、目标不存在、缺配置及执行失败各消费一次；未知/不可调用/超限/取消拒绝不消费 |
| B03 | 前 6 个新调用可准入，第 7 个被拒；并发竞争最后额度不超卖；同身份只产生一份消费事实 |
| B04 | 准入落盘后、handler 前中断可续跑；同身份在额度满时接续不重扣，新身份仍受限；换参数/工具的同身份拒绝 |
| B05 | 等待登记后接续及重复恢复不重扣；新无效引用扣一次，拒绝不新增等待或触发任务 |
| B06 | 成功业务已提交而 checkpoint 未保存时返回原 ID/回执，不重复写业务；Operation、批量和 Undo 原 5 次预算行为保持 |
| B07 | 字符跨重启累计；已恢复输出不重复计量；新输出继续累计；输出计量提交与 checkpoint 提交交错不会归零放宽 |
| B08 | 字符耗尽后检索沿原结构裁剪/提示；计划 JSON、操作回执与任务结果仍有效完整 |
| B09 | web_search 使用共享额度，超限实际网络请求数不增加；401/429/不可重试熔断等原行为保持 |
| B10 | 事件重复、补发、压缩不影响新策略预算；迟到 worker 无权修改持久消费或字符事实 |
| B11 | 新/旧轮次升级兼容、等待、停止、新问及终态查询正确；旧记录缺席不伪装为零消耗，独立 Run 与既有回执保留 |
| B12 | 工具挂载、公开结果/SSE/回执形状、领域授权与取消 guard 保持；架构职责对照证明实现知识集中 |

优先复用工具查询、时间、学习计划、联网挂载/熔断、Operation 和 ChatTurn 恢复相关现有测试。因为本票明确改变行为，现有覆盖不足的准入/并发/持久故障窗口允许补最小必要回归；更新旧断言应说明对应 Q 决策，不删除无关行为断言。

准入和字符持久化至少验证真实 SQLite/框架/Worker；模型、网络及崩溃窗口可以使用受控替身并明确说明。验收分别标记自动化、替身、真实 API/SQLite/Worker、真实模型和真实 Tauri/WebView2；基线失败单列，不把历史绿灯当本票证据。

## Out of Scope

- 通用能力 catalog、全面挂载重构、统一结果 envelope、回执投影或前端工作流改造。
- 改变 Agent 授权档、Operation 执行、Run 计划/等待/恢复状态机，或统一全部特殊工具限额。
- 全局 Token/费用计费、全部模型上下文硬上限、所有输出统一截断、通用读取缓存。
- 禁用并行调用、引入新框架/依赖、直接操作 checkpoint 内部表、无关基线修复。
- 修复草案 Job 身份关联或自动执行独立失败事务的旧 guard 问题。

## Further Notes
