# 工具预算实施与验收

日期：2026-10-12。实施基点：`c43e3954467f92e16771965f01b522183dc65568`。

## 实际实现

`agent/budget/` 集中声明、准入、输出消费和恢复。16 项工具在 `@tool` 下用 `@budgeted` 声明共享次数策略，原拒绝载荷由各工具 adapter 保留；实际字符分支使用 `mark_output` 标记。工具挂载仍由原 AgentConfig 决定，不因预算声明扩大可见能力。

Middleware 放在逻辑身份绑定之后、框架参数校验之前；未知或未挂载工具不进入预算。直接工具调用复用装饰器与相同策略，缺少 ChatTurn 的测试上下文只进行临时累计，不能冒充持久恢复。

迁移 `0045_tool_budget.sql` 新增准入和输出两张事实表，仅 DDL。准入来源键为 turn/namespace/logical_call_id，工具名与参数指纹校验身份一致性；策略版本同时固化在新轮次执行快照和准入记录。表中没有完整参数、结果正文、业务成功状态或新任务机制。

准入事务先经 `turn_write_allowed` 条件 UPDATE 取得 SQLite 写锁，再核对既有身份或竞争新名额，提交后才执行 handler。同身份已准入时额度满仍允许接续；参数错误、目标不存在、配置缺失和执行失败不退还消费。

字符消费在原计量分支标记真实序列化长度，由统一执行边界在结果交给框架前提交。每次新执行产出拥有独立输出身份；checkpoint 中的既有 ToolMessage 恢复无需重跑工具，故不重复计量。重新执行实际产生的新结果继续累计；checkpoint 回退不能覆盖先提交的消费事实。旧 worker 迟到输出仍须经过持久身份/取消校验。真实 Worker 故障窗口另外发现计量处取消拒绝会被视为未知失败；Middleware 现将该拒绝转为已有 TurnCancelledError，收口 CANCELLED，未改旧失败记账事务。

`search_library` 的 `format_output` 在同一短写事务刷新持久累计、运行原同步裁剪 adapter 并提交字符，领域查询仍在锁外。实测发现累计 8,000 时两个检索各返回 3,070、总数达到 14,140 的竞态；持久和临时上下文回归已验证修复且不重复计量。保留原结构裁剪、4,000/12,000 参数和提示分支；该数值不是所有工具结果或完整上下文的硬上限。计划、回执、后台任务结果不进行通用字符串截断，web_search 只新增次数计数，原错误分类与熔断保留。

`wait_for_task` 不再在 `prepare_wait` 内维护预算；新调用在引用查询之前准入，无效引用也消费一次，已登记等待恢复不重扣。独立 5 次业务提交预算仍按原 effect 注册面恢复，不计入共享 6 次。

审查发现 regenerate_plan 的既有重放路径会重新生成草案，可能因生成漂移无法取回原回执。现在先由预算核对原工具参数，再在受执行身份/取消保护的短事务读取原 SUCCEEDED effect，成功结果优先于配置检查、领域读取和模型生成；原业务提交与授权协议保持。

旧轮次没有兼容预算版本时，不伪造历史次数/字符，也不按零额度执行。QUEUED/RUNNING 经 worker 进入现有 GRAPH_INCOMPATIBLE 等待；已有 WAITING_USER/WAITING_JOB 保持等待，实际接续时复用兼容门禁。停止后新问可正常执行，已保存内容及独立业务账本保留。活跃消费事实不随事件压缩删除；终态压缩和会话物理删除沿原生命周期清除预算事实，终态查询无需预算记录。

## 职责变化

| 调用方 | 实施前 | 实施后 |
| --- | --- | --- |
| 计数工具 | 各自检查次数/递增，若干参数分支早退绕过计数 | 声明策略，保留领域判断、拒绝 adapter、结构裁剪和实际字符分支 |
| prepare_wait | 校验引用、登记等待并维护次数 | 只处理真实引用、等待关系、interrupt 与原结果 |
| ChatTurn worker | 从展示事件与手工工具名单估算次数，字符归零 | 次数/字符读取持久消费；操作提交仍使用原 effect 口径 |
| Middleware | 取消检查、逻辑身份绑定 | 身份后原子准入，结构参数错误同样计数；输出提交后才返回框架 |
| regenerate_plan | 生成后才发现已提交 effect，可能指纹漂移 | 原参数准入核对后优先恢复成功业务回执 |
