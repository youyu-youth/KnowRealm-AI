# 05 — 生命周期、AI 整理与提案闭环

**What to build:** 资料的完整生命周期治理（重命名、归类、归档/恢复、软删回收站 30 天、删除前展示关联、重新抓取=新条目、Course 移动不级联、失败重试、索引重建）；「AI 整理」先做确定性重复与处理异常检查，再给出结构化标题与 Course 归类建议供逐项确认；研究会话可对 web_search 候选来源提出「建议保存」提案，确认后经业务入库；全部提案经 `agent_proposals` 持久化、跨重启不丢失、确认前零事实变更；数据目录导出/恢复包含资料。

**Blocked by:** 03 — 统一入库与网页剪藏闭环; 04 — RAG Agent 闭环.

**Status:** ready-for-agent

- [ ] 生命周期动作全套 API + UI：重命名、归类/取消归类、归档/恢复（退出默认浏览与来源召回，`include_archived=false` 统一过滤）、软删（不级联 Record）、删除前展示派生 Record、失败重试、重建索引
- [ ] 资料条目回收站智能视图：仅含软删资料、30 天内恢复（校验 content_hash、索引缺失幂等重建）、UI 明示不含 Record/学习资产；归档智能视图接内容；物理清理仅在保留期届满且无活动引用时执行
- [ ] 重新抓取/重新导入：同 URL/路径内容变化创建新条目，不覆盖旧快照、不建版本表；Course 移动重新计算可见范围、派生 Record 不静默跨 Course 移动
- [ ] AI 整理闭环：确定性重复项与处理异常检测（不耗 LLM）+ LLM 结构化标题与 Course 归类建议（ORGANIZE 提案）+ 逐项确认应用；拒绝不改事实；标签建议不在本票
- [ ] 研究入库提案（RESEARCH_INGEST）：研究会话 web_search 候选 →「建议保存」提案卡（来源/标题/目标 Course 逐项确认）→ 业务 ingest 创建资料条目与处理任务；搜索摘要不成为资料事实、未成功抓取前不进 RAG、不生成锚点
- [ ] 提案持久化闭环：PENDING/APPLIED/REJECTED/FAILED 状态流转、payload 按 proposal_type 判别校验（禁任意 SQL/路径/Shell）、确认后领域 Service 原子应用、失败留稳定错误码可重试；跨重启待审提案不丢失（不依赖 Graph 悬挂）
- [ ] 全量导出 → 空库恢复：资料条目、快照、关联、引用仍可用；派生索引可重建不作为不可替代内容
- [ ] 自动化用例：提案未确认零事实变更、资料软删/归档零级联误删 Record 与学习资产、回收站恢复后可检索性恢复；zh/en 文案同步
