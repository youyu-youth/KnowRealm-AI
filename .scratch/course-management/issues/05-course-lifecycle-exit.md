# 05 — 热词、软删除与计划出口

**What to build:** 让学习者在课程设置中维护手动热词并安全删除课程，同时完成工作台与课程管理的真实端到端出口验证，使计划 01 可以在明确证据边界下交付。

**Blocked by:** 03 — 课程搜索与筛选; 04 — 课程详情与编辑.

**Status:** ready-for-human

- [x] 学习者可在课程设置中查看、添加、移除并按输入顺序保存手动热词；热词与课程编辑共用 PATCH 事务，不新增第二份设置事实源。
- [x] 热词最多 100 个，每项清洗后必须非空；100 个可保存，101 个或无效项使整次更新失败且旧数据不被部分覆盖。
- [x] 删除课程前显示明确确认和“当前无恢复 UI”的说明；取消不会产生任何请求或状态变化。
- [x] 确认删除后课程在单一事务内写入软删时间，并立即从列表、搜索、筛选和详情中消失。
- [x] sidecar 启动后非阻塞清理超过 30 天的课程墓碑；测试可控时间下证明未到期墓碑保留、到期墓碑物理删除。
- [x] 当前计划不为后续 Record 功能预建空业务表；计划 02 引入后代实体时必须扩展同一删除事务和清理顺序后再验收级联。
- [x] 创建、编辑和删除成功后精确失效课程列表与详情 query；课程数据不复制进 Zustand 或持久化前端缓存。
- [x] API/SQLite 集成测试覆盖热词边界、原子失败、删除 204、所有读取路径软删过滤和 30 天清理。
- [x] 前端行为测试覆盖热词错误、删除确认、取消、删除失败重试和删除后的导航恢复。
- [ ] 主验收接缝完整跑通：真实空态 → 新建 → 列表 → sidecar 重启仍存在 → 搜索/筛选 → 详情 → 编辑/热词 → 删除后不可见。
- [ ] 主验收同时记录真实 Network：随机 `127.0.0.1` 端口、`X-KnowRealm-Token`、FastAPI 响应和 SQLite 持久化；fixture、MSW、静态页面或 Query 缓存不得冒充端到端证据。
- [ ] 1440×900、1280×800、1099×720 一次批量检查亮色、暗色、键盘焦点、disabled 状态、Dialog/Select 键盘行为和整体横向溢出。
- [x] 只有真实动作和导航具有 hover 与 pointer；静态信息、Records 未接入宿主及不可用入口不伪装可点击。
- [ ] 桌面构建、lint、后端静态检查、迁移/API 集成、真实 HTTP、重启持久化和最终渲染检查均通过；测试不使用 Docker。
- [ ] 验收报告分别列出源码/静态、组件、API/SQLite、真实 HTTP/Network、重启持久化和渲染证据，任一较低层结果不得升级描述为完整 E2E。
