# 界面语言切换（中 / 英）

Status: ready-for-agent

## Problem Statement

工作台只有中文一种界面语言。产品定位是「给一切学习知识的人」的开源工作台，英文用户（以及任何非中文用户）打开应用面对的是纯中文界面，没有选择机会：新装英文系统的用户被直接送进中文首启向导；报错信息（后端 200+ 处中文 detail、托盘菜单、参数校验提示）即使看不懂也无从切换。同时，AI 生成物的输出语言由中文 prompt 隐式固定——英文材料的导入者也得到中文总结，中文界面用户用英文提问可能得到不确定语言的回答，内容语言从未被显式设计。

2026-09-08 两轮 grill 定稿：范围取**全覆盖**（用户终裁，推翻「先前端后错误消息」的分阶段推荐）；默认语言取**首启向导询问**；AI 内容语言**动态跟随输入、与界面语言解耦**。本 spec 固化该轮全部裁决。

## Solution

1. **设置页语言切换**：外观（Appearance）分组新增「界面语言」两选（中文 / English），切换即时生效、无需重启，经偏好接口持久化。
2. **首启向导语言步骤**：向导新增第一步「界面语言」（三步变四步），预选系统语言结果，「下一步」即确认；跳过即接受预选项。存量用户升级后界面保持中文、无闪烁。
3. **错误消息双语**：后端错误响应附加稳定错误码（中文 detail 保留），前端在错误构造层按码表翻译——英文界面下用户看到的全是英文，包括参数校验、服务器内部错误与对话流式错误。
4. **壳层跟随**：系统托盘菜单、Rust 命令错误按同一错误码协议翻译；日期 / 时间格式跟随界面语言。
5. **内容语言与界面语言解耦**：AI 生成物（总结 / 知识点 / 习题 / Todo / 复习资料 / 对话回答 / 评分反馈）的输出语言由各 prompt 显式指令约束为「跟随输入（材料或用户消息）的语言」；已生成内容永不随界面语言翻译。

## User Stories

1. As an 学习者, I want to 在设置页外观分组把界面语言切到 English, so that 界面文案（菜单、设置、提示、空态）即时变英文且无需重启。
2. As an 学习者, I want to 把界面语言切回中文, so that 随时可以换回来且同样即时生效。
3. As an 新用户, I want to 首启向导第一步就选择界面语言, so that 第一次打开应用就能用我读得懂的语言走完引导。
4. As an 新用户, I want to 向导语言步骤预选系统语言, so that 什么都不改点下一步也是对的语言。
5. As an 跳过向导的新用户, I want to 跳过（全部步骤）后界面语言仍是预选的系统语言, so that 「跳过=接受默认」的心智在语言上同样成立。
6. As an 存量中文用户, I want to 升级应用后界面仍是中文且无闪变, so that 升级对我完全无感。
7. As an 英文界面用户, I want to 看不到任何中文界面残留（侧栏、命令面板、资产库、捕获流程、错误提示、确认对话框）, so that 全界面语言一致。
8. As an 英文界面用户, I want to 后端报错（如「请先配置 LLM Provider」「归档课程不能生成知识点」）显示英文, so that 出错时知道该做什么。
9. As an 英文界面用户, I want to 对话流式错误（发送失败、在途限制等）显示英文, so that 聊天里的报错也能读懂。
10. As an 英文界面用户, I want to 参数校验错误显示通用英文提示, so that 不再看到拼出来的技术串。
11. As an 英文界面用户, I want to 服务器内部错误显示英文且保留请求编号, so that 报障时仍能提供排查凭据。
12. As an 英文界面用户, I want to 系统托盘菜单显示 Show / Exit, so that 托盘入口也是英文。
13. As an 英文界面用户, I want to 日期与时间格式跟随英文习惯（如趋势图坐标轴、记录时间戳）, so that 排版与语言一致。
14. As an 英文界面用户, I want to 切语言后重启应用仍然是英文, so that 语言偏好被持久记住。
15. As an 中文材料学习者, I want to 界面切英文后中文录音的总结 / 知识点 / 习题 / 复习资料仍是中文, so that 内容语言跟材料走、不被界面绑架。
16. As an 英文材料学习者, I want to 导入英文文档后生成的学习资产是英文, so that 产出与我输入的语言一致。
17. As an 对话用户, I want to 用英文提问就得到英文回答、中文提问就得到中文回答（逐条动态）, so that 对话语言自然切换。
18. As an 对话用户, I want to 明确要求「用某语言回答」时 AI 照做, so that 我对内容语言有最终决定权。
19. As an 作答者, I want to 简答题评分反馈的语言跟题目走, so that 批改结果与试卷语言一致。
20. As an 屏幕阅读器用户, I want to `<html lang>` 随界面语言切换, so that 读音引擎用对语言。
21. As an 快捷键用户, I want to 快捷键提示与改键界面的文案跟随语言, so that 设置键位时描述可读。
22. As an 学习者, I want to 导出学习资产时文件名模板跟随界面语言（内容仍跟材料）, so that 文件系统里的产物名与界面一致。
23. As an 开发者, I want to 错误响应带稳定错误码与可选参数, so that 前端翻译不靠中文串匹配、契约可演进。
24. As an 开发者, I want to 新增后端错误漏配错误码时测试防线失败, so that 覆盖率不随迭代回退。
25. As an 开发者, I want to zh / en 资源 key 集合不一致时构建测试失败, so that 漏翻立即暴露。

## Implementation Decisions

- **范围=全覆盖**：前端 UI 文案、后端错误消息、壳层（托盘 / Rust 命令错误）、Intl 日期格式四层一并落地；AI 内容语言为独立正交维度（见下）。
- **偏好模型**：偏好接口的读 / 写模型新增 `language`（枚举 `zh | en`），**缺省值 zh**——存量用户读取即中文，升级无感。设置页外观分组新增两选 RadioGroup，复用「改动即 PUT、成功回写缓存、失败回显服务端事实」的既有偏好控件模式。
- **首帧语言策略**：应用启动时界面语言 = localStorage 缓存值 ?? 系统语言（navigator.language 以 zh 开头则 zh，否则 en）；偏好查询成功后校正实际值并写缓存，防止异步窗口闪变。已知边缘：系统英文的存量中文用户升级后首帧英文、校正后回中文，闪一次后永久消失（接受，不为此引入三态）。
- **首启向导**：新增第一步「界面语言」（置于数据目录之前，原三步编号顺移）；该步界面语言用首帧语言渲染；完成向导（含全部跳过）时把当前选中项写入偏好。
- **i18n 资源**：en 资源全量对齐 zh（约 1040 个叶子 key，AI 全量翻译 + 人工抽查），`fallbackLng` 保持 zh 兜底后续新增 key 的漏翻。领域术语英文对照定稿：Record / Knowledge Point / Quick Note / Review Material / Capture / Course / Inbox / Mock Test（已沉淀 CONTEXT.md「界面语言 / 内容语言」词条与四步向导描述）。
- **错误响应契约（γ′ 附加字段）**：`detail` 中文原文保留不动，响应附加稳定错误码；带动态值的错误附参数对象，形如：

  ```json
  {"detail": "请先配置 LLM Provider", "code": "LLM_PROVIDER_NOT_CONFIGURED"}
  {"detail": "导出包不存在：C:\\x", "code": "EXPORT_ARCHIVE_MISSING", "params": {"path": "C:\\x"}}
  ```

  后端引入带错误码的 HTTPException 子类 + 统一异常处理器序列化上述形状，全部错误 raise 点机械替换（约 200+ 处，生产代码）；错误码命名 `MODULE_RESOURCE_PROBLEM` 大写下划线风格。共享错误响应 schema（全路由共用的那个）加可选 `code` / `params` 字段，openapi 导出后 api-types 重新生成。**后端既有测试断言 detail 中文 → 零改动**（选型主因）。选型权衡（纯结构化方案被否）记 ADR-0017。
- **两个 handler 的通用码**：请求参数校验错误（422）统一 `REQUEST_VALIDATION_FAILED`（不再逐字段翻译，现状拼接的技术串本就不可读）；未捕获异常（500）`INTERNAL_ERROR` + `params.request_id`（翻译文案保留请求编号）。
- **SSE 对话错误**：流式 error 事件已带 code 字段，对齐补全 code 值集即可，事件形状不变。
- **前端翻译入口唯一**：API 错误在构造层（抛出 ApiError 时）用 i18next 实例完成码表翻译——命中错误码则按 key + params 插值取译文，未命中回显 detail 原文；所有现有 `error.message` 展示点零改动自动受益。SSE 错误载荷在同一入口翻译。错误文案 key 收进 i18n 资源 `errors` 命名空间（前端单一文案来源）。
- **Rust 命令错误码化**：托盘无关的命令错误（录音电源管理、sidecar 透传等用户可见串，约 5 条）仿数据目录迁移已有的 `CODE: 明细` Display 协议，前端码表映射翻译（扩展既有迁移错误码表的同类模块）。
- **托盘菜单**：切换语言时前端调用命令通知壳层重建托盘菜单（显示 / 退出 ↔ Show / Exit）。
- **日期格式**：现有 Intl 调用点（趋势图、记录时间等 4 处）从界面语言派生 locale（zh→zh-CN、en→en-US），不引入日期库。
- **AI 内容语言指令**：全部 LLM prompt 模板统一追加一行显式指令「用与输入内容相同的语言输出」（对话=当前用户消息、生成类=输入材料、评分=题目），不信任模型隐式模仿；与界面语言完全解耦，**不做内容翻译**。`<html lang>` 随界面语言切换；导出文件名模板走 i18n（内容语言跟材料不变）。
- **两道防线**：
  1. 后端扫描测试：生产代码中不得直接 raise 裸 HTTPException（必须用带码子类），防新增错误漏配；
  2. 前端资源一致性测试：zh / en 递归 key 集合 diff 为空（含 en 复数后缀 key 的容忍规则）。
- **测试环境语言固定**：vitest setup 固定界面语言 zh（CI 的 en-US 系统语言会让中文断言全炸）；i18next 实例在 React 外可用的翻译入口照常可测。

## Testing Decisions

- 好测试只断言外部行为：渲染出的文案、API 响应形状、prompt 字符串内容；不断言内部实现（缓存写入时序、异常类层次等）。
- 缝隙（全部复用现有缝，经用户确认）：
  1. 语言控件与向导步骤 → RTL 组件测试 + MSW（断言 PUT 请求体、i18n 语言切换、文案随之变化）；先例：设置页各分区组件测试与 MSW 偏好桩。
  2. 首帧语言策略 → 独立 hook 单元测试（mock localStorage / navigator.language / 偏好 GET），断言 i18n 实例语言的迁移路径与缓存写入。
  3. 错误码翻译 → ApiError 构造层单元测试（mock 响应 detail+code+params → 断言翻译文案；未命中 code → 回显原文）+ 一个组件端到端用例；先例：chat API client 层测试。
  4. SSE 错误翻译 → 现有对话流测试模式，断言错误载荷按码翻译。
  5. 后端错误码落位 → 既有 pytest 路由测试零改动（γ′ 红利）；新增代表性抽查（409 / 422 / 500 响应含 code）+ 防线扫描测试。
  6. prompt 语言指令 → Fake 模型捕获 prompt，断言含语言指令行；先例：习题 / 总结的 prompt 断言测试。
  7. zh / en key 一致性 → 新增轻量脚本测试。
  8. 托盘跟随与壳层错误 → 自动化止于前端 invoke mock 断言；真机验收单列用户清单（仓库惯例）。

## Out of Scope

- 内容翻译：已生成学习资产的语言转换、跨语言检索。
- 第三种及以上界面语言（locale 资源架构按 zh/en 两档设计，未来扩展时再议）。
- 伪本地化（pseudo-locale）测试、RTL 布局。
- OpenAPI 文档描述、README、docs 的双语化。
- ASR 语言边界：腾讯 ASR 中文识别是既有能力边界，英文录音转写不在本期。
- 语言包按需加载 / i18n 资源懒加载（资源体积可控，静态打包）。
- 偏好保存失败的错误提示本地化之外的偏好新项。

## Further Notes

- 拆票预估 5~6 张：① 前端语言切换链路（偏好字段 + 控件 + 首帧策略 + 托盘跟随）② en.json 全量翻译 + 一致性防线 ③ 错误码化基建（错误子类 + handler + 契约 + ApiError 翻译层 + 422/500 + SSE + 扫描防线）④ 各模块错误码补配 ⑤ 向导语言步骤 ⑥ 测试环境适配。
- 错误码契约选型（γ′ 附加字段 vs 纯结构化）满足难逆 / 无上下文会困惑 / 真实权衡三条件，随基建票落 ADR-0017。
- PRD 决策表建议新增「界面语言与内容语言」条目（中英两档、向导询问、内容语言跟随输入），随首票升版处理。
- 真机验收清单（用户执行，agent 不代勾）：托盘菜单跟随、切换即时生效无重启、首启向导四步流、存量升级无闪变、英文界面下错误消息全英文抽查。
