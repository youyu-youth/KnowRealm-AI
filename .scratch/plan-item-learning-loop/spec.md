# 计划项学习闭环 V1

Status: ready-for-agent
日期：2026-10-17
依据：[Grill 定稿 Q1～Q23](./grill.md)、[ADR-0029](../../docs/adr/0029-plan-practice-frozen-content-and-independent-results.md)、现行领域术语与授权规则。
用户已批准产品决策及领域文档，并确认本规格的测试接缝。本规格是开发输入，不代表代码或验收已完成；当前未创建实施工单。

## Problem Statement

学习者在课程计划中看到“学习 Docker 资料”或“做 15 道 Redis 基础概念题”，仍需要自行查找材料和题目，学习后再回来勾选。计划项无法准确关联本次学习结果，中断后也无法从该计划项可靠接续。

已有计划支持生成、版本、编辑、完成与跳过，已有测试支持作答和评分，但没有接通“计划要求—相关题目—独立练习—本次结果”的链路。课程随机抽题、题少时降量、普通习题只记录首次作答，均不能兑现按计划主题提供精确题量并支持多轮练习的要求。实时引用原题还会使已开始的练习受来源修改或删除影响。

## Solution

首版覆盖“学习资料”和“做习题”两类计划项。学习资料可直接进入关联记录，恢复上次页签；做习题则先合并确认主题、题量、题型和资料范围，从本课程归属资料的已有已采纳习题中匹配足量题目，创建独立的计划练习。

计划要求 N 题，就提供 N 道相关且不同的题；不足、匹配失败或需要新增来源确认时不创建可作答练习。已有练习可中断继续、重启恢复，主动重练才创建下一轮。每轮固定启动时要求、题面及判分依据，结果可追溯；用户在计划中查看最近一轮进度和评分，再自行确认计划项完成。页面与 Agent 使用同一领域能力，练习结束、评分完成、计划项完成及掌握度分别表达。

## User Stories

1. 作为学习者，我希望从学习资料类计划项直接打开正确记录，以便减少寻找材料的步骤。
2. 作为学习者，我希望从计划再次打开资料时恢复上次内容页签，以便接续阅读。
3. 作为学习者，我希望只有从计划明确启动的学习被关联到该计划项，以便其他入口的历史活动不被误当成本次成果。
4. 作为学习者，我希望旧计划项缺少资料关联时能首次补齐并保存，以便已有计划也能使用新闭环。
5. 作为学习者，我希望系统或 Agent 推荐关联资料但由我确认，以便避免标题相近时绑定错误来源。
6. 作为学习者，我希望原资料已删除或不可达时看到明确说明，以便自行更换关联而不是进入失效页面。
7. 作为学习者，我希望首次练习时一起确认主题、数量、题型和来源，以便在一个步骤中发现理解偏差。
8. 作为学习者，我希望匹配主题来自计划项标题并经过确认，以便题目围绕计划要求，而不是课程随机抽题。
9. 作为学习者，我希望计划要求 15 题时得到恰好 15 道不同的相关题，以便实际练习与计划一致。
10. 作为学习者，我希望题量未写明或标题与正文冲突时先询问我，以便不靠默认数量或模型猜测执行。
11. 作为学习者，我希望确认后的要求保存下来，以便后续开始或继续时不重复配置。
12. 作为学习者，我希望练习只使用已有已采纳习题，以便题目可追溯且不会临时编造。
13. 作为学习者，我希望优先使用已经确认的资料范围，以便学习内容保持集中。
14. 作为学习者，我希望选定资料不足时可以看到本课程其他资料的推荐，并确认后扩充来源，以便补齐题量。
15. 作为学习者，我希望系统明确显示不足的题量，并在不足时不建卷，以便不会把少题练习误报成达标练习。
16. 作为学习者，我希望取题仅使用本课程归属资料，以便其他课程和共享引用资料的资产不会未经明确设计参与练习。
17. 作为学习者，我希望支持单选、多选、判断、填空、简答，以便复用现有题库。
18. 作为学习者，我希望计划指定的题型得到遵守，未指定时允许五类参与，以便题型设置不会被擅自改变。
19. 作为学习者，我希望开始后获得独立的一轮计划练习，以便本次答案和成绩不会与普通习题首次作答混在一起。
20. 作为学习者，我希望重复点击开始仍进入同一轮，以便不会误开多份练习。
21. 作为学习者，我希望离开页面、切换聊天或重启应用后仍能继续未交卷练习，以便学习进度不依赖页面内存。
22. 作为学习者，我希望修改标题、题量或资料范围后，当前轮仍保持原要求和题目，以便不中途加题或换题。
23. 作为学习者，我希望新的要求经确认后用于下一轮，并能看出当前轮使用的是原要求，以便理解要求与结果之间的关系。
24. 作为学习者，我希望原题修改、删除或资料移出课程后，已开始练习仍保留当时题面和判分依据，以便继续及重评都有稳定依据。
25. 作为学习者，我希望来源失效时明确标注并停止原资料入口，以便知道练习副本与当前资料的区别。
26. 作为学习者，我希望删除原资料不会被旧练习引用阻碍，同时清楚知道旧练习保留题目副本，以便正确理解删除范围。
27. 作为学习者，我希望课程被删除后相关练习也随之不可见，以便新增入口不绕过课程生命周期。
28. 作为学习者，我希望主动选择重新练习才创建新轮，以便普通继续操作不丢弃已有进度。
29. 作为学习者，我希望重练优先使用本计划项此前各轮未用过的相关题，新题不足时允许明确提示后复用旧题，以便兼顾覆盖面和可用性。
30. 作为学习者，我希望放弃未交卷旧轮前看到已答进度并确认，以便不因误触结束学习。
31. 作为学习者，我希望新轮准备失败时旧轮仍可继续，以便为换题付出的尝试不会破坏原进度。
32. 作为学习者，我希望旧轮答案与结果保留，且一个计划项最多一轮可继续作答，以便继续入口始终明确。
33. 作为学习者，我希望已交卷旧轮能够继续评分，同时允许明确开始新轮，以便评分等待不占用可作答轮次。
34. 作为学习者，我希望计划项默认展示最近启动轮次的真实状态，旧轮结果另行查看，以便旧成绩不会冒充本轮结果。
35. 作为学习者，我希望分别看到已答数、已评分数、未评分数及总题量，以便知道结果是否完整。
36. 作为学习者，我希望成绩注明实际评分分母，并能表达简答部分得分，以便不会把部分成绩误当成整轮正确率。
37. 作为学习者，我希望评分失败保留答案和已成功评分结果，只重试未评分题，以便无需重新作答或重复支付成功题的评分成本。
38. 作为学习者，我希望评分或模型暂时不可用时看到可恢复状态和重试入口，以便能够离开等待而不丢失成果。
39. 作为学习者，我希望作答前不能通过新入口提前获取参考答案，以便练习仍具有检验意义。
40. 作为学习者，我希望由自己确认计划项完成，即使成绩不理想也能区分“完成练习”和“已经掌握”，以便学习记录真实。
41. 作为学习者，我希望重练不撤销已完成状态或重复计算完成数量和首次完成时间，以便计划进度稳定。
42. 作为学习者，我希望在目标进行中且计划生效时，已完成项仍可打开资料或主动重练，以便进行巩固。
43. 作为学习者，我希望历史计划版本及已完结目标只查看既有结果，以便历史不因新的作答操作发生混淆。
44. 作为学习者，我希望打开资料和勾选完成不直接增加掌握度，以便掌握度继续来自真实验证性证据。
45. 作为学习者，我希望通过 Agent 查询练习要求、进度和结果并取得准确站内入口，以便自然语言可以衔接学习。
46. 作为学习者，我希望 Agent 能准备、继续、明确重练和重试未评分题，同时遵循当前授权与必要确认，以便减少页面操作而不失去控制。
47. 作为学习者，我希望 Agent 在目标或题量不明确时询问我，实际阅读和答题仍由我完成，以便不会把模型代答算成学习。
48. 作为学习者，我希望请求已受理、执行中和完成分别可见，取消、失败及重启后可查实际状态，以便不用猜测操作是否发生。
49. 作为学习者，我希望多主题、键盘、窄窗口及字体缩放下仍能完成开始、继续、返回和确认，以便桌面学习不中断。
50. 作为学习者，我希望计划练习、题面副本与结果保存在现有本地数据目录，且现有普通习题与模拟测试继续正常使用，以便升级不破坏已有数据和习惯。

## Implementation Decisions

### 领域职责与复用

- 学习计划域管理计划项关联、已确认练习要求、计划执行上下文和完成约束；测验域复用既有建卷、独立作答、交卷、评分、放弃及恢复能力，承载计划练习。资料阅读复用记录详情与已有页签恢复能力。
- 计划练习与普通习题首次作答分开。优先扩展现有测试能力并明确区分计划练习与普通模拟测试的用途，不能复制一套作答或评分引擎，也不能让课程随机抽题接口悄悄改变语义。
- 学习事件、证据消费与掌握度沿用既有规则；打开资料、保存练习要求、准备题集、创建题面副本及人工完成不额外生成验证性学习证据。
- 本地优先：新增数据进入现有数据目录及数据库，沿用备份/恢复流程，不要求额外部署、登录或新增外部服务。代码实施时同步契约类型、双语文案、必要错误码登记与进度状态。

### 持久化与关联契约

- 已确认练习要求关联具体计划项，包含主题、正整数题量 N、允许题型、确认的资料对象集合、来源确认事实、关联的计划内容版本及要求修订版本；保存时校验计划项类型、目标、版本和课程归属。首次合并确认，后续沿用；业务确认事实和执行授权分别校验，不能仅凭授权档位将未确认要求当成已确认。
- 计划项文本中缺题量或数量冲突时返回待消歧，不能自动使用原模拟测试的固定题量。用户确认数量为执行口径，界面清楚展示；保存要求不静默重写原计划正文。
- 一轮计划练习关联具体计划项、所属课程、要求修订版、启动时间及顺序，固定当时的要求和有序题集，保存独立答案、逐题评分/错误及可恢复执行状态。最近一轮按启动事实确定，不能按最后评分时间误选旧轮。
- 每题保留题型、题干、选项、参考答案、解析及实际评分所需内容，保留原题/记录身份和当时的来源、概念归属信息。原题身份用于追溯，不能成为删除来源后无法读取题面或阻塞清理的强依赖。
- 新增迁移按现行连续编号追加，不修改已发布迁移；扩展现有模型时保留普通模拟测试及历史数据的兼容分支。新增计划练习的固定内容必须完整，不能将既有未冻结历史伪装成已有完整快照；普通历史试卷不靠推测回填。
- 来源清理、备份和恢复必须覆盖新的关联与固定内容。只做本闭环必要的引用处理，不借机重构或修复全库无关清理路径；发现阻塞闭环的既有约束须以迁移及可复现案例说明。
- 阅读关联记录明确的计划项启动事实、目标记录及可恢复页签；沿用已有访问元数据和导航能力，不新建计时或阅读百分比系统。其他入口访问不能反向补成本次计划学习结果。

### 主题匹配与精确取题

- 确定性程序先限定题库：当前课程归属、记录与习题未删除、习题已采纳、来源与题型满足已确认要求；共享引用、其他课程、未采纳题及网络来源均不参与。
- 主题理解与相关性判断可以使用现有模型供应商能力，但模型只选择已有候选并说明匹配依据，不生成、改写题干或答案，不凭空返回题目身份。统计、权限、数量和身份校验由程序完成。
- 模型外发限于匹配所需主题、候选题面及必要来源说明，不默认外发整门课程原文、用户答案或其他学习历史；遵循现有外发同意、供应商、预算及用量记录规则。外部内容不构成执行指令或授权。
- 对模型返回的题目身份重新校验候选成员关系、当前状态和来源范围，去除重复身份及题型/题干/选项规范化后完全相同的副本；语义相关性与近似重复纳入真实样本评测，不能只用数量检查宣布匹配成功。
- 最终提交恰好 N 道相关且不同的题。原 5/10/20 限制及允许少题策略不用于计划练习；不静默截断、跨范围补题、复制题目或生成新题凑数。
- 扩充来源先给出本课程其他归属资料的建议和题量信息，用户确认对象集合后保存新的要求修订，再取题；课程可见或模型建议不等于来源已获确认。
- 匹配失败、预算耗尽、模型不可用与确定的题库不足分别反馈。只检索了部分候选时不能声称全课程没有足量题，须说明匹配未完成或已检索范围；保留要求和已有练习并提供重试。
- 重练使用已确认要求，优先该计划项此前各轮未使用的合格题，新题不足允许复用旧题并显示复用事实；本轮内部仍须去重且足量。每次创建均重验来源有效性，固定旧卷面不能授权从失效来源创建新轮。

### 启动、状态与事务

- 对外提供按计划项查询学习状态/要求、确认关联/要求、准备并开始或继续练习、明确重新练习、查询某轮结果、交卷、重试未评分题及人工完成等能力。页面通过 HTTP 使用，Agent 经 Tool 与受控 Operation 使用；两者复用同一领域结果和执行约束。
- 启动、重练及重评请求携带稳定请求身份，绑定计划项、要求修订及预期当前轮次。重放返回同一已受理任务或结果；同一请求参数变化拒绝执行。以数据库事务及约束兜底每项最多一轮可作答，并发入口不能各自创建一轮。
- 普通开始优先返回已有可继续轮次；已交卷正在评分则返回对应状态和入口，用户明确重练时才准备新轮。一个计划项最多一轮可作答，已经交卷的评分任务可与下一轮并存。
- 明确重练时展示旧轮已答进度及放弃影响。先准备并验证新题集，提交时再次核对原轮次及要求；将旧轮放弃和新轮创建放在同一成功事务，任一步失败或取消均保留旧轮可继续。不能先放弃再异步尝试取题。
- 延迟的主题匹配及评分复用既有 JobRunner 持久任务、恢复与错误反馈机制；不新建独立队列。受理时可查询任务身份，执行中有状态，完成后可取得固定练习入口或明确缺口；离开页面或关闭订阅不等于取消业务。
- 提交处重验当前计划版本、目标状态、请求身份、取消、执行身份及有效授权。取题期间范围失效、要求变更或旧轮进度变化造成基线过期时，返回可重试的冲突结果，不能覆盖新状态。
- 新增准备任务或等待原因需要同步调度持久约束、启动接线、取消及重启对账。等待外部条件不丢已确认要求和已受理事实，不以页面临时状态替代数据库事实。
- 当前轮使用启动时固定内容；修改要求只影响下一轮，当前轮显示原要求。来源后续修改、删除或移出课程时按 ADR-0029 继续既有轮次、停止失效来源跳转；课程删除仍整体不可见。
- 历史计划版本、已完结目标及已跳过项不提供新的用户作答、重练或修改要求入口，执行端与页面一致；当前生效计划且目标进行中时，已完成项允许继续/重练并保留首次完成事实。已受理评分的后台收尾保留实际结果，不因查看历史而新建评分请求。

### 结果、评分与学习事实

- 沿用既有题型判分、交卷和答案揭示规则；评分及仅重试未评分题都使用当轮固定依据。新增 API/Tool 投影区分作答可见字段与事后揭示字段，查询或准备入口不能把完整内部题面副本返回前端或聊天模型；评分模型仅取得本次评分所需的题面、用户答案及固定判分依据。
- 结果至少包含轮次/要求标识、总题量、已答数、已评分数、未评分数、评分执行状态及完整性、成绩与实际分母、来源失效状态、继续或重试入口。已有“整卷结束”状态不能替代评分完整性判断。
- 成绩沿用现有逐题分数等权平均，支持简答部分分数；未评分题不按错题计入。全部评分前标注部分成绩与已评分覆盖数，零题已评分时无成绩，不显示伪 0 分或完整正确率。
- 对已结束但仍有未评分题的计划练习也提供重试，不能只接受整轮评分失败状态。只处理已交卷轮次；未交卷不触发评分，已有评分任务则返回该任务状态。重试只选尚未评分的题，成功结果和用户答案不变，保持并发幂等及任务恢复能力；未评分错误可定位到题并有重试反馈。
- 单题真实作答与评分结果复用既有事件写入和消费口径，以轮次及题目事实去重；重放、重新观察和评分重试不重复产生同一学习事实。不同轮次相互独立，固定的概念归属不绕过现行概念有效性及来源过滤规则，不为历史无归属题猜测概念。
- 计划项完成仍复用现有完成入口，首次完成时间幂等保留；不以答题数或分数自动完成，也不因练习、重评或结果刷新重复累加计划完成数量、估时或掌握度。

### 页面与 Agent 接入

- 计划页补“开始/继续学习”“查看本轮结果”“重新练习”和适用的“重试未评分题”；旧项缺关联时展示首次配置入口，阅读与练习都可明确返回原计划项。最近轮次与历史结果分开，不复制完整资产编辑器。
- 练习要求首次合并确认，题量冲突、来源扩充及明确放弃分别展示实际对象与影响。匹配等待可离开、可取消、可恢复；保留列表位置与必要焦点，失败不清空已保存进度。
- 复用现有作答界面和页签导航，区分“计划练习”与普通“模拟测试”；普通测试列表、路由及统计不得因新增用途而意外混入或漏掉数据，学习事实统计保持原有口径。
- 页面业务状态来自服务端查询，URL 保留必要的计划项/轮次上下文；服务端数据复用既有查询缓存，写后精确刷新要求、计划项、当前轮、历史和相关今日完成投影，不另建业务事实状态仓库。
- 支持现有明暗及其他主题、窄窗和字体缩放，主动作与错误反馈键盘可达，返回后焦点可恢复。沿用现有设计令牌与局部滚动，不增加页面级滚动、独立计时器或无关仪表盘。
- Agent 提供查询、确认要求、准备/继续、明确重练、重试未评分及完成计划项的能力；通过查询取得真实计划项/轮次身份，信息缺失时追问，返回可用站内入口、结构化缺口或持久任务状态，不猜 ID、不代替用户作答。
- Agent 写操作走现有 Operation、授权模式、对象快照、必要确认及回执，执行端校验对象与参数范围；要求确认和页面上下文不能替代执行授权。新能力复用现有预算及中间件入口，不新增通用权限或编排平台。

## Testing Decisions

### 接缝与范围

- 用户已确认：以现有真实 HTTP API＋SQLite 集成为主接缝，经实际迁移与应用生命周期验证“确认要求→准备/建卷→作答/恢复→评分/重试→人工完成”。必要时直接查询 SQLite 核对持久事实，不为内部函数调用次数写镜像测试。
- 沿用计划编辑和模拟测试的现有集成测试惯例：临时本地数据目录、完整迁移链、应用生命周期、带启动令牌的客户端，以及可控评分模型。控制模型仅替换外部推理，不替换领域服务、事务、数据库或 Worker 结局。
- 页面在现有查询/路由/网络替身接缝补交互测试；Agent 经已装配工具与受控执行链验证领域结果及回执，不能只直接调用业务函数宣称已接通。
- 优先运行与改动相关的现有测试；只有本次新增行为未被覆盖时补测试，不补齐无关历史覆盖率。下面是验收场景，不要求为每条故事新增一个测试。

### 自动化核心验收

1. 混合题库含不相关主题、未采纳题、已删题、共享题和跨课程题；要求 15 题时最终恰好 15 道合格且不同的题。重复身份、重复副本、模型伪造身份、少题、越权来源和不完整匹配均不能落成可作答卷。
2. 题量缺失/冲突先消歧，首次确认及来源扩充准确保存对象与要求修订；要求或原题在匹配期间变化时拒绝过期结果。页面与 Agent 不能分别绕过范围确认。
3. 正常继续、重复请求、两个并发入口及重启后恢复指向同一轮；明确重练成功后只有一个可作答轮。新轮准备失败、取消或提交冲突时旧轮答案及可继续状态保持不变。
4. 五题型使用固定题面与判分依据；创建后修改/删除原题、删除或移动资料、执行实际来源清理，再验证既有练习读答交评与历史、来源失效标注、无原资料跳转，以及新轮拒用失效来源。课程删除和恢复沿既有可见性验证。
5. 部分简答失败但整轮已结束时，结果仍显示准确的已答/已评分/分母。只重试未评分题，验证成功结果不变、零已评分不伪造分数、部分分数保留、重复重试和恢复不重复写学习事件。
6. 当前生效且目标进行中的已完成项可继续/重练，首次完成时间、计划完成数及估时不重复累计；历史版本、完结目标、跳过项及直接调用旧作答入口不能绕过执行约束。完成和阅读启动零新增掌握度证据。
7. 新增页面/API/Tool 在揭示时机前均不暴露参考答案；查询和异步回执只包含相应阶段允许的结果。取消、授权降档和对象版本变化在实际提交及独立记账事务中拒绝越界写入。
8. 旧版数据库正常升级，普通习题首次作答及普通模拟测试的建卷/少题策略/评分/列表保持兼容；本次新增固定内容与关联经备份/恢复后可正确继续，不靠固定迁移尾号断言。
9. 页面验证合并确认、读取中/匹配中/缺题/评分失败、明确重练影响、返回与焦点恢复、最近轮/历史切换、缓存同步及其他入口访问不冒认本次结果；不把模拟网络测试当成真实模型或原生桌面验收。

### 分层人工与真实验证

- 真实 API/SQLite/Worker：准备包含两个课程、共享引用、同题副本、至少 15 道相关题及不相关题的隔离目录。分别执行首次 15 题练习、6/15 中断重启、重练失败保留旧轮、来源删除清理、部分评分重试；记录对象、要求修订、轮次、请求/任务、题目来源及数据库结果。
- 真实模型：使用人工标注的计划标题与真实已采纳题样本，分别检查相关性、无关题排除、重复与复用提示、题量准确、来源边界和失败降级；题干/答案保持原题。匹配与评分分开记录供应商、用量、失败及结果，不以模型替身或纯数量检查替代质量证据。
- 真实 Tauri/WebView2：在现有明暗主题、窄窗、键盘与字体缩放下走完整闭环，覆盖本地站内跳转、返回、等待离开与恢复；另验 Windows 125%/150% 系统缩放。记录 CSS 视口、DPR、系统缩放和主题，不用浏览器 DPR 模拟代勾。
- 所有验收记录标明通过、失败、未执行及未触发，并记录清理/恢复方法；真实模型与用户本地数据操作使用隔离目录，保留原数据。此规格本身没有运行上述验收。

## Out of Scope

- 依据掌握度、逾期或学习进展自动重排计划，以及遗忘预测、FSRS 或新掌握度算法。
- 复习概念、自由任务的学习闭环；它们保留现有编辑、完成与跳过能力。
- 原始资料题目提取、临时生成新题、自动联网补题、跨课程或共享引用资料取题。
- 新建人工选题界面、题目编辑器、计划模板、打卡、提醒、番茄钟或学习计时统计。
- 新增精确页码/段落/播放位置恢复、阅读百分比、强制阅读产出或模型判断“已读懂”。
- 将其他入口的历史学习自动回填到计划项，或以计划完成替代验证性学习证据。
- 以本次固定内容能力为由，全面改造普通模拟测试、历史外键与全库清理，或猜测补齐既有历史题面/概念。
- 通用插件、权限、队列、编排或可配置题目匹配平台；业务开发、实施工单创建及上线操作不由本次 to-spec 自动执行。

## Further Notes

- Q1～Q23 为已批准产品边界，ADR-0029 固化需要长期保留的历史与评分依据取舍；两个新增术语已登记。本规格使用 ready-for-agent 表示规格可进入实施拆票，不代表功能已交付。
- 技术复用的关键差异：普通习题仅保留首次作答；普通模拟测试有独立答案但当前实时读取原题、只支持 5/10/20 随机取题、允许少题，以及部分失败未必可重评。计划练习必须补齐上述契约差异，不能只把旧接口包装成新按钮。
- 主要风险为真实题库覆盖、主题相关性与近似重复、固定内容与来源清理兼容、部分评分恢复及学习事实幂等。实施应先通过一个 15 题的真实 API/SQLite 闭环验证复用，再扩大已批准边界的组合验收，不把未验证项写成已通过。
- 若后续拆票，按业务闭环组织，每票覆盖必要前后端、Agent 和验收；遵循同窗口的 grill → spec → tickets 顺序，不按技术层拆成不可独立验收的工单。
