# 05: 完整闭环、兼容与分层交付验收

Status: ready-for-agent
批准日期：2026-10-17

依据：[定稿规格](../spec.md)、[Grill 决策](../grill.md)、[批准的拆分与共用约束](../tickets-proposal.md)。
每票负责本业务闭环所需的领域、HTTP、页面、Agent 与定向验收；先阅读规格及共用约束，保留既有业务行为。

**What to build:** 在隔离数据中验证资料学习与计划练习全部路径可交付，确认普通习题/模拟测试兼容、数据可升级恢复，分别取得真实模型和原生桌面的证据；明确通过、失败及待用户验证范围。

**Blocked by:** [01：资料学习与返回计划闭环](./01-record-study-loop.md)；[04：评分失败恢复、安全重练与多轮结果](./04-grading-recovery-and-practice-rounds.md)。

**规格覆盖：** 用户故事 49～50，以及前四票的跨能力组合和全部已批准验收场景。

- [ ] 先汇总每票真实生产入口、固定数据、模型/网络替身边界和证据，核对规格全部 50 条故事及 Q1～Q23 均有实现和验收归属，不以勾选代替运行事实。
- [ ] 经真实 API/SQLite/Worker 完整执行：旧项关联、15 题准备、缺题确认补源、6/15 中断重启、部分评分重试、重练失败保留旧轮、旧轮晚到评分、人工完成及 Agent 同结果查询/执行。
- [ ] 运行实际升级、来源删除/移动与清理、备份/恢复，验证固定题面和判分依据、失效链接、课程生命周期及本地目录可搬移；不将静态外键推导当作实际清理已通过。
- [ ] 定向运行本次触及的计划、普通习题、普通模拟测试、学习事件/掌握度、JobRunner、Agent 授权/回执与页面既有测试，以及必要新增行为测试和项目要求检查；只读分析不构成回归通过，历史失败按既有基点规则记录，不借机扩大测试体系。
- [ ] 用人工标注的真实标题和已采纳题样本验证真实模型的主题相关性、重复、精确数量、来源边界和失败降级，匹配与评分分别记录供应商、实际用量、请求/任务、结果和失败；不得用假模型或仅数量检查替代质量验收。
- [ ] 真实 Tauri/WebView2 走前四票的复验路径，覆盖明暗主题、窄窗、键盘焦点/返回、字体缩放，以及 Windows 125%/150%；记录 CSS 视口、DPR、系统缩放及主题，不代勾用户真机验收。
- [ ] 确认页面与 Agent 未提前暴露参考答案，取消、授权降档、版本变化及来源扩充在实际提交处校验；每项最多一轮可作答，重试和恢复不重复学习事实或首次完成统计。
- [ ] 文档、契约、双语和错误码与实际实现一致；同步项目进度时区分已实现/部分实现/未验收，并遵守现有行数限制。涉及权威文档的新增内容仍按批准范围或另列具体提案，不以本票自动获权。
- [ ] 交付记录分别标明自动化、模型/网络替身、真实 API/SQLite/Worker、真实模型、真实原生桌面及未触发项；缺密钥、预算、硬件或用户操作的项目保留未验证，不用模拟替代真实要求，不以实现完成宣布完整验收。

**桌面复验路径：** 使用独立数据目录，保留原目录及备份；记录应用/侧车版本和对象身份，依次执行前四票场景并截取关键状态，保存必要数据库核对结果。完成后退出隔离实例，恢复原目录/设置；清理只针对明确的隔离产物，用户数据不删除。所需供应商调用与用户真机操作按实际授权执行，尚未执行的检查保持未勾选。
