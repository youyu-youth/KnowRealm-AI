# 02: 练习要求确认、精确取题与缺题补源

Status: ready-for-human
批准日期：2026-10-17

依据：[定稿规格](../spec.md)、[Grill 决策](../grill.md)、[批准的拆分与共用约束](../tickets-proposal.md)。
每票负责本业务闭环所需的领域、HTTP、页面、Agent 与定向验收；先阅读规格及共用约束，保留既有业务行为。

**What to build:** 用户一次确认主题、精确题量、题型与资料范围，得到可持久查询的题集准备结果；缺题时推荐本课程其他归属资料，经确认扩源后重新准备。恰好 N 道相关真实题才成功，匹配失败和题量不足明确反馈。03 再接入实际作答。

**Blocked by:** None (can start immediately)。

**规格覆盖：** 用户故事 7～18，以及匹配/补源阶段的 38、45～48。

### 要求确认与题集准备

- [x] 旧练习项可首次配置并保存要求；题量缺失/冲突先消歧，题量为明确正整数，首次合并确认主题、数量、题型及资料对象集合，保存修订与原计划内容基线，不静默改计划正文。
- [x] 只查询已确认范围内、本课程归属且有效的已采纳习题，支持五题型及指定题型；跨课程、共享引用、未采纳、已删除题均不能成为候选。
- [x] 主题理解和相关性匹配使用现有供应商及必要模型能力；模型只选择真实候选，不生成/改写题目，不取得用户答案或无关课程内容，遵守外发同意、用量及预算。
- [x] 准备结果恰好 N 道相关且不同的题；验证候选身份、规范化重复副本、题型与范围，明确区分“库存不足”“匹配未完成”“模型或预算失败”。部分检索不能被报告为全课程不足。
- [x] 准备结果只暴露本阶段允许的状态、数量、来源与匹配说明，不提前揭示参考答案；保留要求修订、选题依据及原题版本校验信息，供 03 在建卷提交时重验。
- [x] 匹配通过现有持久任务能力区分受理、执行和完成，页面可查询、离开、取消和重试，重启有对账；请求重放不重复受理或计量。模型不可用时已有要求不丢失，不以随机题兜底。
- [x] 页面与 Agent 均可确认要求、发起准备、查询状态/缺口；业务确认事实与执行授权分别校验，过期要求、取消或降权在实际提交处阻止写入。
- [x] 通过真实 HTTP/SQLite/Worker、可控外部模型验证准备结果与调度事实，包括 15 题、重复/伪造题目身份、题型过滤、旧要求及失败重试；模型替身仅替换推理，不替代服务/数据库/Worker。真实相关性质量留待 05。

### 缺题与来源扩充

- [x] 缺题反馈明确目标 N、当前已确认范围中的合格题数量与实际检索范围，不以模型失败冒称题库不足；新增来源建议只来自本课程其他归属资料。
- [x] 建议展示真实资料对象、相关性依据及可确认范围；用户明确批准后保存新的要求修订，再重新准备题集，供 03 建卷时使用，仍保证恰好 N 道合格且不同的题。
- [x] 未确认来源不参与取题，三档授权均不能用执行权限代替缺失的业务来源确认；不同课程、共享引用、网络、未采纳或已删题不能补入。
- [x] 来源建议/确认期间资料变化、要求更新、取消或降权会阻止过期提交，并给出可恢复反馈；不得因为扩源准备而先放弃已有轮次或清空已保存要求。
- [x] 页面与 Agent 均可查看缺口、推荐及确认扩源、查询足量题集准备结果；失败、等待、取消及重启恢复沿本票的持久任务能力，不新建旁路调度。
- [x] 真实 API/SQLite/Worker 验证“已选资料 8 题、另有 7 题”的确认补齐路径，以及整个课程不足、部分检索、拒绝确认、来源失效和模型失败；不生成新题或静默降低数量。

**桌面复验路径：** 准备相关题与无关题混合的课程，确认“Redis 基础 15 题”要求，观察准备三阶段及可查询结果；修改要求、模拟不足与失败、离开并恢复。记录请求/任务、要求修订、候选来源、数量及实际检索范围，不展示答案。 补源场景使用来源一 8 道、来源二 7 道相关题，另置跨课程和共享题作为干扰；先拒绝再批准新增来源，验证题集恰好 15 题且无越界，取消或失败保留已有要求与练习。
