# 03：双子任务并行、部分成功与聚合

Type: task
Status: ready-for-human
Blocked by: 02
规格：[spec.md](../spec.md) §5、7～11；Q2/Q4 及 Q7～Q9 已确认。

## 用户结果

一个 general 根任务可以委派最多两个只读 knowledge 子任务，共用原全局两槽与根六次工具额度。多个根同时等待仍能推进；部分失败有真实缺口提示和可追溯来源，不重复请求已成功分支。

## 改动边界

以下实现及勾选的证据层级为真实 API/迁移 SQLite/Worker/Graph＋外部模型替身；界面为组件回归和独立浏览器＋IPC 替身。详见 [03 实施记录](../03-implementation.md)，不代表真实模型或原生验收。

- [x] 同轮两次 delegate_knowledge(task) ToolCall 各委派一个任务，经框架逐调用 Send 并行，不改为批量入参或新增聚合 Job/等待表；根累计最多两子任务，跨调用/重放均确定性限额。
- [x] 子任务按稳定任务身份独立领取、结果和 namespace；所有执行共用原两槽，父等待释放槽。
- [x] 两个 ToolCall 分别绑定原 Job/wait/interrupt ID，父整体停驻并释放槽；全部可靠结果就绪后按原 ID 恢复映射且条件唤醒一次，顺序不改变对应关系，重放不重建已登记分支；结果不明按 Q7 等待选择。
- [x] 所有报告在持久化和进入父模型前校验契约及来源；汇总输入保留有效结果和缺口，工具指引要求区分已支持结论与缺失证据，真实模型表达待下方独立验收。
- [x] 明确部分/全部失败按 Q2 汇总结束；一成功一不明或均不明时，待安全兄弟收口进入 WAITING_USER，选择仅重试选中分支或接受已有结果；重试原子失效对应旧 wait 缓存，保留成功结果/原消费，旧决定不作用于后续等待，不制造无来源结论。
- [x] 共享六次工具额度、字符消费及原请求准入；两次委派计两次，其余父子工具合计剩四次，最后额度竞争不超发，不按子任务重新给额度。
- [x] 父停止时两子任务都受持久取消约束；一个迟到/旧 claim 不影响其他合法分支事实。
- [x] 并行子状态经独立 claim/attempt 校验写原根事件流/seq，根 WAITING_JOB 期间可见；终态与事件同事务，根/子 attempt 不混用，子 token/done 不写父正文；刷新/切会话/压缩/重启从原事件/快照恢复。两个子线程与输入独立，重试和清理不影响成功兄弟或父图。
- [x] 新增/修改文案双语，契约类型与六种当前主题/窄窗/大字号同步（浏览器视口/字号模拟）。

## 验证路径

两个不同对话分别公开提交 general 根轮次 → 每根同轮两次 ToolCall 分别注册子任务/Job/wait/interrupt 后整体停驻 → 两个原槽推进子执行 → 原子根预算/请求记录 → 四个分支分别落结果 → 持久对账/不确定请求的用户决定 → 父汇总/快照/前端。

采用真实 API/迁移 SQLite/Worker/Graph，模型替身仅控制外部模型输出与阻塞点；不得通过解除并发限制或直接写完成状态来获得通过。

- [x] 两根同时等待时无槽死锁，总活动执行始终 ≤2；同会话忙碌拒绝行为保留（生产链＋模型替身）。
- [x] 双 ToolCall 产生独立 interrupt ID 并准确恢复；逆序完成、一成功一明确失败、两个明确失败正确汇总；一成功一结果不明分别验证等待选择、仅重试中断分支和接受部分结果，成功分支不重跑、旧缓存不误唤醒（生产链＋模型替身）。
- [x] 第 6/7 次工具准入并发竞争只有最后合法调用成功；预算恢复后不归零，重复调用不重复扣准入（生产链＋模型替身）。
- [x] 第三子任务跨多次委派调用也被拒绝；knowledge 发起嵌套委派不具备能力（生产链＋模型替身）。
- [x] 取消与最后结果/事件提交竞态、单槽故障、重启时一成功一在途、父未唤醒重放；并发/过期用户决定拒绝，子线程/输入互不覆盖，取消或重试一个子执行不清父/兄弟图（本票 16 项及原恢复/预算回归；模型替身）。
- [x] 有效引用来自正确子任务和原 scope；失效引用不进入父模型投影（真实来源读取/删除＋模型替身；最终真实模型表达另验）。
- [x] 父等待期间子进度可见，快照压缩/重启后根 seq 与两子状态一致，父正文无子 token/done；前端子状态、选择性重试、刷新恢复与查询一致（生产 API/Worker、组件与独立浏览器；模型/IPC 替身）。
- [ ] 真实模型实际发出同轮两个独立 ToolCall、检索引用与真实最终缺口表述；未触发记 NOT_TRIGGERED，不以替身或框架内存实验代勾。
- [ ] 真实 Tauri/WebView2 切会话/等待/停止/部分失败/恢复与 Windows 125%/150%/200% 系统缩放独立验收。

证据：`../03-implementation.md`，附根/子/Job/请求身份与时间线、并发峰值、原预算查询和实际请求数。桌面重复步骤沿 02，改为两个子任务并刻意制造一失败；清理隔离数据和自建进程，临时资源不 add/commit。

## 完成定义

通过两根同时等待与共享最后额度的生产链验证后，才能称“有界并行协作已实现”；“两个请求同时发出”本身不足以证明恢复与限额。按批准范围更新进度。
