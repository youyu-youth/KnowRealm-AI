## 1. 新增 ADR-0030：有界专业 Agent 与持久委派

已登记 ADR-0030；Q9 细化直接补入该 ADR，不另增编号。后续新增 ADR 时重新核实最大编号。

已批准并登记的决定：

1. general 与 knowledge 独立入口，静态身份固定在聊天会话；scope/mode 不是 Agent 身份。
2. 复用现有 DeepAgents Harness；knowledge 同一专业实现服务独立调用和委派。首期本地只读，不拥有写工具、联网或继续委派权限。
3. general 仅按需通过受控 Tool 委派，LangGraph interrupt/原 checkpoint 负责图内等待与恢复，不建设全局 Orchestrator 或新 Agent 服务。
4. 子执行有稳定业务身份、独立 claim 和冻结输入；SQLite 保存结果/消费，checkpoint 不是权限或事实源。
5. 父子共用两个原执行槽及每根六次工具额度；每根最多两个子任务，父等待释放槽。模型请求实际用量沿原表保留，未知不填零。
6. 原 CHAT_TURN Job 输入增加根/子执行的显式区分；两个原 WorkerSpec 分派，保留现有 JobRunner，不新增循环。JOB 等待须以持久父子关系证明资格，不伪造 Operation。
7. 三档授权、Memory/内容采纳/外发确认保持。父取消后拒绝新增调用和迟到结果；部分成功披露缺口；未知请求不自动重发，显式重试保留原消费。
8. 明确这是 ADR-0018/0028 内置委派隔离及 ADR-0026/设计-4 暂不做运行时 Multi-Agent 的阶段性演进。仅放行本期受控 knowledge 专业图，不开放默认通用子代理、文件、Shell、自由通信、嵌套委派或平台能力。

旧 ADR 保留历史决策，仅在相关“当前阶段关联”位置链接新 ADR；不改写历史验收和当时结论。不通过删除 task 黑名单来放开整个默认子代理能力。

## 2. 更新 GLOSSARY.md

新增三个精确定义，连接新 ADR：

- **业务 Agent（Business Agent）**：一套稳定职责、领域工具白名单与可组合图的专业能力；可由会话直接进入或被受控委派。首期 general/knowledge；不同于 ChatMode 和 ChatScope。
- **委派执行（Delegation Execution）**：根 ChatTurn 派生的独立只读专业执行，具有稳定执行 ID、领取身份、冻结任务、持久结果和根预算归属；不等同于 Agent Run、Operation 或独立聊天会话。
- **根预算归属（Root Budget Owner）**：父子工具消费和模型用量的共同根轮次；它不是实际执行 claim，也不是授权凭证。

不重新定义已有 Record、Concept、ChatTurn、Run 或 Operation。
