## 已由原方案确定

- 分层混合架构；general 与 knowledge 可独立直达，主 Agent 按需一级委派。
- 不增加所有请求必经的 LLM 分类器或全局 Orchestrator。
- 会话固定 Agent，agent_id、scope、mode 分开；旧调用默认 general。
- 共享 DeepAgents Harness 与领域 Service；保留受控写入口、授权、外发与内容审核。
- 复用 ChatTurn/Run/Operation/JobRunner；持久执行身份、共享预算、父等待释放额度、取消、重放与重启对账必须一起设计。
- 首期不做 Canvas/Learning/Document Agent、嵌套委派、自由通信、动态 Handoffs、Skills/MCP 平台或管理后台。

## Q1：Knowledge 能力

用户选择：**采用本地只读边界**。

仅读取当前会话有效资料范围，返回结论、真实引用及缺口。不联网，不生成记忆/入库提案，不拥有任何业务写工具。FREE 不自动扩大到 ALL；需要本地资料时提示用户在指定资料范围新建对话。用户明确授予的原有外发同意仍适用于模型请求，“不联网”仅指不使用外部检索源，不代表本地运行模型。

## Q2：部分失败

用户选择：**允许部分成功，明确披露缺口**。

主 Agent 可以使用成功且有来源的子结果汇总，必须说明失败与不足。全部子任务失败时返回可理解的失败和后续选择，不伪造本地知识结论。

## Q3：请求结果不明

用户选择：**不自动重发结果不明的模型调用**。

重启后复用已完成子结果与已记消费；可靠证明尚未发出的步骤继续。已开始请求但没有可靠结果时标记中断，要求显式重试，提示可能重复计费；未知 usage 保留未知。图已提交的结果应先对账，不能因业务投影未完成而重新调用模型。

## Q4：首期规模

用户选择：**采用保守规模，先验证闭环**。

- 父子合计工具准入最多 6 次，委派 Tool 本身也计入；重放相同逻辑调用不重复扣准入次数。
- 一个根任务最多创建 2 个 Knowledge 子任务，子任务不允许继续委派。
- 根与子执行共用现有全局 2 个活动执行槽，等待不占活动槽。
- 每个实际模型请求记录用量；供应商缺 usage 时显示未知，不当作零。
- 不新增可调并发、金额预算或自动扩容；保留现有每请求输入/输出额度与摘要请求配额。
