# 03 第一层：共享六次额度的停止与说明修复

日期：2026-10-22。实施基点：`abecb843fa4d1d57b1baca758f53c9c11a214cae`。

## 事实与范围

用户实际根轮次 `af8c1cb8-f458-4322-ab57-92e329024837` 已创建两个知识任务。持久准入为两次委派、四次检索，共六次；后续检索被拒没有超扣。但旧拒绝信封返回正常空数组，没有 `ok:false`、错误码和“未执行”标识；模型也没有及时获得共享余额，继续生成补查请求，并把不能核实描述为未找到原文。

保留03的六次共享硬上限、最多两子任务、原子准入、取消与幂等恢复，不新增每子任务独立额度、调度平台、API、数据库字段或依赖。第二层预算分配决策另行讨论。

## 实施计划

1. 复用预算中间件，每次调用模型前从持久消费读取共享余额，并让模型知道这是并发快照而非保留额度；归零后从本次模型请求撤下受预算控制的工具，要求用已有证据结束报告。
2. 在统一准入拒绝处返回明确失败码、不可同轮重试与共享余额。检索拒绝明确本次未执行，不能当作检索无命中。成功检索返回共享余额，继续使用原字符裁剪和记账。
3. 报告与父汇总区分“实际检索无命中”与“额度耗尽未能核实”；保留已有证据、来源和未核实缺口。不靠扩大额度掩盖停止问题。
4. 同步提示/图版本和项目进度。涉及恢复的旧图按现有不兼容路径处理，不重跑用户旧任务。

## 验证路径

- 公开API提交 → 真实迁移SQLite、双槽Worker与Graph → 两子任务争抢最后额度 → 工具拒绝 → 下一次实际模型输入与工具集合 → 两份报告汇总。只替换外部模型以精确控制竞态，断言准入仍为六次。
- 复用现有工具预算、重启恢复、上下文预算与提示版本回归；只新增本次改变而现有测试未覆盖的断言。
- 在独立合成资料目录使用已配置、已同意供应商验证真实模型行为；不改用户资料或历史轮次，不把API验收当作原生桌面验收。
- 按改动范围执行Ruff、格式、Pyright及差异检查。临时脚本、数据库和原始日志不add/commit。

## 执行与证据

实现复用 `ToolBudgetMiddleware.awrap_model_call` 和 `ModelRequest.override`：预算策略版本仍为1、上限仍为6，每次模型调用先恢复持久消费，余额为零时仅撤下已登记的预算工具。正余额不预留名额，执行时仍由原 `admit` 事务裁决并发。新额度说明位于最终输入预算中间件之前，进入真实完整输入计量。

检索成功结果携带 `tool_budget(limit/used/remaining)` 并参与原字符裁剪；统一拒绝处携带 `ok:false/error:TOOL_CALL_LIMIT/retryable:false` 和余额，检索拒绝明确本次未执行。委派拒绝的二次校验同步识别新增额度字段，不再把合法拒绝改报为来源失效，报告内容及引用的既有校验保留。

成功检索无命中的提示明确“已执行、当前查询未找到”，去除不考虑余额的换词重试建议。零余额指引要求保留已有证据及合规引用，整理、引用已有原文无需继续检索；只针对用户问题中证据不足的部分解释未核实原因。

动态额度与工具集合会改变实际输入指纹，因此子图恢复时，已完成请求的防重发改用同一执行的原冻结消息链匹配。仍记录实际完整输入指纹和工具成本，不改变未决请求的恢复规则。图版本为v15，普通/研究提示版本为v37/v38；没有增加额度或绕过检查点保护。
