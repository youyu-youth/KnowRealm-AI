# 03 — 安全删除 Record 并完成功能出口

**What to build:** 用户在 Record 工作区能够经过明确确认后软删除当前 Record；取消不会产生请求，失败不会丢失当前页面，成功后返回所属课程的 Records 列表，并且被删除的 Record 在重启后仍不可见。

**Blocked by:** 02 — 可直达的 Record 详情

**Status:** ready-for-agent

- [ ] `DELETE /api/records/{record_id}` 受启动令牌保护；可见 Record 成功软删除返回 204，不存在、已软删除或父课程已软删除的 Record 返回 404。
- [ ] 删除在单个事务中同时写入 `deleted_at` 和 `updated_at`；本切片不物理删除 Record，也不声称清理尚不存在的子资产、文件、向量、聊天或证据。
- [ ] 详情页提供删除入口和含不可恢复警告的确认对话框；取消或关闭对话框不发送删除请求。
- [ ] 删除请求进行中时避免重复提交；失败时保留当前详情与可重试操作，并展示可理解的错误，不执行成功导航。
- [ ] 删除成功后移除或失效相关列表与详情缓存，并导航到所属课程的 Records 页签；本切片不为无课程 Record 提供 UI 删除入口。
- [ ] 删除后，课程列表不再返回该 Record，详情请求返回 404；重启 sidecar 后结果保持一致。
- [ ] 已有课程删除仍会在同一事务中软删除其 Record，且 Course 既有生命周期测试不回归。
- [ ] API 测试覆盖 204、各类 404、时间戳写入、重复删除和事务行为；前端测试覆盖确认、取消、重复提交保护、失败保留、成功缓存更新与导航。
- [ ] 用真实 sidecar 和桌面 Network 验证删除请求、随后列表/详情响应及重启持久性；临时 SQLite 种子仍只作为测试前置，不得被表述为生产 Record 创建能力。
- [ ] 在 1440×900、1280×800、1099×720 以及明暗主题下检查删除入口、确认对话框、错误状态、焦点恢复和无水平溢出。
- [ ] 以功能开始前的固定基线完成 Standards 与 Spec 两轴审查；最终报告明确区分静态检查、自动化测试、真实 HTTP、桌面 Network、渲染与重启持久性证据。
- [ ] 功能出口明确记录：录音、文档导入、后台任务、状态推进、失败来源/恢复、子资产同步软删除以及 30 天文件/向量清理由后续切片实现，本功能不宣称这些链路完成。
