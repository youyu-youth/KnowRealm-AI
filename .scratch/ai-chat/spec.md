# AI 对话（自由 + @记录）Spec

Status: ready-for-agent

> 来源：plan 12（`.scratch/function-plans-introduction/12-ai-chat.md`，2026-08-28 grill 定案回写）；术语遵循 `CONTEXT.md`（聊天会话 / 自由聊天 / 挂载 / 知识点解释）。验收出口线以 plan 12 文件的 9 条为准，本 spec 是实现契约。

## Problem Statement

学习者在工作台里已经有了学习记录（转写、总结、知识点），但产生疑问时没有任何对话入口——只能离开产品去通用 AI 工具提问：那些工具不知道记录内容、回答不可溯源；想直接问通用问题或闲聊也没有入口。同时，角色个性化（档案层的角色与自我介绍）在对话域没有任何承载，AI 回答无法体现"我是谁、我在学什么水平"。

## Solution

左栏新增一级"AI 对话"入口，ChatGPT 式体验：对话列表 + 流式对话区（UI 文案一律称"对话"）。新建对话时一次选定模式：

- **自由聊天**：不挂载任何记录；系统提示注入用户角色与自我介绍（档案未建时中性默认）；
- **挂载对话（@记录）**：选择一条存在转写的学习记录（含收件箱未归类），转写全文常驻上下文，多轮追问细节，答案带 `[1][2]` 角标引用——点击跳转到该记录的转写页并高亮定位原文。

回答以 SSE 流式逐字输出，请求受理即有状态反馈；保留近 10 轮记忆，超过字符预算自动裁剪早期轮次，超长转写降级为"摘要 + 知识点 + 近 3 轮引用摘录段"。挂载记录被删除后对话保留可读并显示"原记录已删除"失效标记、不可再发送。从知识点列表点击可进入聚焦该知识点的对话（预填建议问题）。附带最小档案切片（角色四选一 + 自我介绍 ≤200 字，设置页"档案"区块），让角色注入真实可感、可验证。

## User Stories

1. 作为学习者，我想在左栏一键进入 AI 对话，这样不必离开工作台就能提问。
2. 作为学习者，我想新建对话时选择"自由聊天"或"挂载一条学习记录"，这样按需选择有没有上下文。
3. 作为学习者，我想看到按最近更新排序的历史对话列表，这样能快速回到上次聊到一半的话题。
4. 作为学习者，我想重命名对话，这样列表标题反映内容而不是截断的第一句提问。
5. 作为学习者，我想删除不再需要的对话，且删除前弹窗明示"不可恢复"，这样不会误删。
6. 作为学习者，打开还没有任何对话的 AI 对话页时，我想看到引导卡告诉我能做什么，而不是一片空白。
7. 作为学习者，我想看到回答逐字流式输出，这样长回答不用干等。
8. 作为学习者，发送提问后我想立即看到"已受理/生成中"的状态反馈，这样知道系统在工作而不是卡死。
9. 作为学习者，我想让我的角色（学生/程序员/职场人/其他）与自我介绍影响自由聊天的语气，这样回答贴合我的水平。
10. 作为学习者，没填档案时我希望自由聊天用中性默认语气正常工作，而不是逼我先去设置。
11. 作为学习者，修改角色与自我介绍后，我希望新对话用新语气、旧对话保持原样，这样历史不被追溯改写。
12. 作为学习者，挂载一条已处理的记录后，我想追问"后面讲的那个公式"这类细节并得到基于转写的准确回答。
13. 作为学习者，我想点击回答里的 [1] 引用角标跳到该记录的转写页并高亮定位原文，这样能核实 AI 说的对不对。
14. 作为学习者，转写被我编辑过后点引用，我想得到"原文已变动"的提示，而不是定位失败或死链。
15. 作为学习者，我希望模型编造的引用根本不会展示给我（后端校验摘录真实存在）。
16. 作为学习者，连续追问时我希望 AI 记得最近 10 轮内容，不用重复背景。
17. 作为学习者，对话很长时我希望早期轮次被自动裁剪但回答仍然连贯，不用手动开新对话。
18. 作为学习者，挂载 3 万字以上长转写的记录时对话仍可用（降级为摘要 + 知识点 + 引用段上下文）。
19. 作为学习者，流式中断后我想一键重试，历史里不出现重复提问、也没有半截回答。
20. 作为学习者，一条回答生成中我不能连发第二条（输入禁用、后端也拒绝），避免回答串线。
21. 作为学习者，删除已挂载的记录后，我想看到对话仍在、标着"原记录已删除"，明白数据没丢而不是凭空消失。
22. 作为学习者，挂载失效的对话只能浏览不能再发送，且界面明确告诉我原因。
23. 作为学习者，我想在知识点列表点击某个知识点直接进入"给我讲讲它"的对话，这样不用自己组织提问。
24. 作为学习者，挂载选择器里我想看到只有存在转写的记录可选，不可选的有原因说明，这样不困惑。
25. 作为学习者，收件箱里未归类的记录（有转写）也能挂载对话，这样刚导入的内容立刻能问。
26. 作为自备密钥的用户，还没配置 AI 服务时进入对话页，我想看到明确的"未配置"空态并能就地完成配置，配完即用。
27. 作为用户，我希望对话全文不出现在任何日志里，只有脱敏元数据（模型、token 数、耗时）。
28. 作为键盘用户，我想用键盘完成发送/停止/在列表与对话间导航，且屏幕阅读器能读出流式状态与引用。

## Implementation Decisions

### 数据与迁移

- 新增迁移 0014，一次建三表：`chat_sessions`（软删）、`chat_messages`（追加型，无软删）、`profile`（按数据模型 v2.2 全列建齐，含昵称/头像，本 plan 只消费角色两字段）；同步把测试中的 `PRAGMA user_version` 断言推进到新版本号。
- `chat_sessions` 遵数据模型 §4.4：`course_id` 可空（挂载记录时随记录填其课程，收件箱记录为空）；`record_id` / `concept_id` 可空；`mode` 本 plan 只用 `ASK`（自由聊天 = 无挂载的 ASK，挂载对话 = 带 record 的 ASK，不新增枚举值）；`title` 默认取首条用户消息截断、重命名覆盖；**挂载失效态运行时推导（JOIN 记录软删标记），不落列**。
- `chat_messages`：role 含 USER / ASSISTANT / SYSTEM / TOOL；`citations_json` 存引用；（session_id, created_at）索引；会话删除 = 会话行软删，消息行不动、经会话过滤；30 天物理清理沿用既有清理批次语义（#41）。

### API 契约（全部挂启动令牌；OpenAPI 变更同步 api-types 生成物）

- 对话资源：创建（带模式与可选 record_id）、列表（按 updated_at 倒序，含挂载记录标题与失效态推导结果）、重命名、删除（软删）。
- 发消息：`POST /chat-sessions/{id}/messages`，请求体为用户消息文本；响应为 SSE 流（六类事件：token / status / citation / interrupt / done / error）。受理即发首条 `status` 事件（结构保证首事件 ≤3s）；`interrupt` 类型保留在协议、本 plan 不产生。
- 档案资源：读取与更新 `profile`，仅暴露 `primary_role`（四选一枚举）与 `about_me`（≤200 字）。

### AI 编排与上下文

- LLM 接入在 agents 工厂层新增**流式纯文本生成路径**（与既有结构化输出路径并列）：供应商卡配置、`trust_env=False`、超时与流式逐 token；`llm_call_logs` 埋点仍在工厂层统一落（graph_name 取 "chat"），只记元数据不记正文。
- 对话用 LangGraph `create_agent`（Wave A 工具集为空，"检索第一工具"为 P2 坑位），复用 lifespan 已建的 AsyncSqliteSaver（langgraph.db），`thread_id = chat-{session_id}`；**每轮从 `chat_messages` 重建消息列表显式喂入**，checkpoint 只承载当轮运行态、不做跨轮记忆——上下文裁剪必须显式可控，业务事实唯一在 `chat_messages`。
- 上下文组装（#39）：字符预算 **60000 为代码常量**（当前后端不读 .env、无 pydantic-settings；注释标明部署级语义，配置体系统一后迁移）。两级裁剪：① 超预算从最旧对话轮开始丢（转写仍常驻）；② 转写超 3 万字不再常驻全文，替换为已确认摘要 + 知识点全文 + 近 3 轮被引用的转写摘录段。**1 轮 = 一条成功完成的 user→assistant 往返**，中断轮不计入 10 轮窗口。挂载上下文每轮取记录**当前最新转写版本**（不钉死 source_version）。
- 角色注入：自由聊天会话创建时把角色 + 自我介绍**快照为一条 SYSTEM 消息落库**（"新会话生效不追溯"由此天然成立）；档案未建用中性默认；挂载会话不叠加角色注入。
- 知识点解释：从知识点入口创建 ASK 会话 + 挂载该知识点所属记录 + 系统提示注入该知识点快照（名称/详情/重要度）；不新增列与模式；前端输入框预填建议问题，用户直接发送或改写。

### 引用（MVP 文本定位）

- 挂载对话的提示词约定：正文用 `[1][2]` 角标 + 文末固定格式引用块（每条为转写原文摘录，≤80 字）。
- 流结束后后端解析引用块：写入 `citations_json`、从展示正文剥离、以 `citation` 事件下发。
- **子串校验**：摘录必须在记录当前转写中真实存在（子串匹配），不存在的条目整条丢弃（防幻觉引用）。前端点击引用跳记录转写页做文本搜索定位 + 高亮；找不到时提示"原文已变动"。自由聊天不产出引用。

### 中断与并发

- 客户端断连（请求断开）→ 取消生成，半截 assistant 内容**不落库**。
- 会话末尾存在"无回复的 user 消息"时，下一次发送视为**补答**：复用该 user 行重新生成，不重复落库。
- 同一会话同时只允许一条在途生成：第二条返回 409；前端流式期间禁用发送。
- 流内异常转 `error` 事件，不无声断流。

### 失效态与降级

- 挂载记录软删 → 会话只读：发送被拒（语义化错误），UI 禁用输入并显示"原记录已删除"。
- 无可用 LLM 供应商：左栏入口保持可见可进，进入后"未配置 AI 服务"空态 + 就地配置（复用既有供应商配置组件模式与既有供应商状态查询接口）；发送前再校验。

### 前端

- 路由 `/chat`（列表 + 空态引导卡）与 `/chat/$sessionId`（内容区左列对话列表 + 右侧对话区）；模式新建时一次选定，会话内不可换、不可中途挂载。
- 数据获取走 TanStack Query（本 feature 的 queryKey 工厂）；SSE 消费复用既有 fetch 流 + eventsource-parser 模式（POST 流、令牌头、AbortController 清理）。
- i18n 全量 key（UI 文案用"对话"）；纯图标按钮 aria-label；流式状态与引用可被读屏读取。
- 供应商状态与档案走既有 settings / 新 profile API；api-types 生成物随 OpenAPI 变更重新生成。

## Testing Decisions

- **好测试只测外部行为**：HTTP 状态与错误语义、SSE 事件序列与顺序、数据库落库结果（行、版本号、citations_json）、前端以可访问角色查询到的渲染内容与禁用态；不测内部调用次序或私有函数结构。
- **后端（主缝隙，全部复用既有模式）**：每测试文件自带 fixture——真实 app + 完整迁移链重放 + ASGITransport + 固定令牌头；LLM 在 agents 工厂缝隙以 monkeypatch 替换为**流式 stub**（先例：总结测试的 StubChatOpenAI），stub 同时**捕获收到的消息列表**——上下文组装、SYSTEM 快照、知识点注入、引用指令、裁剪阶梯全部在 API 边界经由"stub 收到了什么"断言；SSE 用 httpx 流式读取逐事件断言；关键落库用 aiosqlite 直查。
- **前端（既有缝隙）**：MSW v2 handlers 扩展对话与档案路由；SSE 消费按既有 fetch stub 回放编码事件流的测试模式断言渲染。
- **纯函数最小单测**：上下文裁剪（预算边界、两级阶梯、轮计数）与引用解析 + 子串校验（角标配对、超长摘录、伪造摘录丢弃）各一组。
- **人工验收（由人执行，不自动化）**：语气变化与"存量对话不变"的体感、回答连贯性、首事件 ≤3s 体感、引用点击跳转高亮的交互体验、空态引导文案、无 Provider 就地配置的端到端走通、删除确认弹窗文案——按 plan 12 验收线逐条人工操作软件验证。

## Out of Scope

- @课程挂载（P3）、@全部资料全局 RAG（P2）、联网搜索工具（P2，SearchProvider/Tavily）；
- 对话转学习资产（P2）、Tutor / Teach-back 模式（P5）、`interrupt` 事件的实际产生；
- Segment 持久化与 Source Anchor 完整溯源（P2；引用仅为转写文本定位）；
- 昵称/头像编辑、多供应商卡管理、档案完整页（留档案与数据目录 plan）；
- 聊天域写 learning_events / Learning Evidence（红线 #5：闲聊不产生证据）；
- 多语言界面（V1 仅中文）、英文内容支持（P2）。

## Further Notes

- 隐私红线：任何日志不落对话全文与 prompt 正文；`llm_call_logs` 只记元数据（先例字段）。
- 后端目录说明文档中"当前最新迁移 0007"与"无 .env"相关表述随本 plan 落地需同步复核更新（文档不留过期信息）。
- `CHAT_CONTEXT_CHAR_BUDGET` 常量默认 60000 字符；若后续引入部署配置体系，随 SHORT_ANSWER_REVIEW_THRESHOLD 一类部署级常量统一迁移。
- 实现票拆分按 tracer-bullet 纵切（桌面端→API→DB），工程基础随首个消费者进入，不单独开工阶段。
